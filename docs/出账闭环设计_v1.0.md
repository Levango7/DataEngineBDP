# 出账闭环设计 v1.0

> 数据引擎大数据平台（DataEngineBDP）· FinOps 出账闭环设计文档
>
> 版本：v1.0　|　日期：2026-09-12　|　状态：出账+结算就绪，分账待 v2.3

## 1. 概述

出账闭环是 FinOps 成本运营的核心业务流程，将平台资源用量转化为可结算的账单，
并完成结算与分账，形成 **出账 → 结算 → 分账** 完整数据闭环。

### 1.1 三环节定义

| 环节 | 组件 | 职责 | 状态 |
|------|------|------|------|
| 出账 | `platform/finops/billing/` | 从 Prometheus 采集租户级成本，生成租户级成本账单 JSON | ✅ 就绪 |
| 结算 | `platform/asset-exchange/` | 拉取 finops 账单，按分成比例执行结算（提供方/平台） | ✅ 就绪 |
| 分账 | `platform/open-api-catalog/` | 将 AK/SK 计量数据（API 调用量）汇入 finops，纳入出账 | ✅ 就绪（计量汇入） |

> **当前进度**：出账与结算 2/3 环节已就绪；分账环节的计量汇入接口已就绪，
> 完整分账到提供方账户的能力待 v2.3 迭代（当前结算已含提供方/平台分成，
> 分账到具体银行账户/钱包的划款能力待 v2.3）。

### 1.2 设计目标

- **闭环完整**：资源用量 → 账单 → 结算 → 分账，全链路可追溯
- **租户隔离**：全程基于 JWT claim 的 tenantId 隔离，不信任请求参数
- **幂等出账**：同租户同账期重复生成返回已存在账单（支持 overwrite 覆盖）
- **降级可用**：Prometheus 不可用时以 0 用量降级生成账单，不阻断闭环
- **接口契约统一**：三组件间通过 REST API 契约对接，松耦合

## 2. 数据流

### 2.1 出账 → 结算 → 分账 数据流

```
┌─────────────────────────────────────────────────────────────────────┐
│                        出账闭环数据流                                │
└─────────────────────────────────────────────────────────────────────┘

  ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
  │  Prometheus   │     │ finops-billing│     │asset-exchange│
  │  (指标存储)   │     │  (出账)      │     │  (结算)      │
  └──────┬───────┘     └──────┬───────┘     └──────┬───────┘
         │                    │                    │
         │  ①采集五维度用量    │                    │
         │ ──────────────────>│                    │
         │                    │                    │
         │                    │  ②生成租户账单JSON  │
         │                    │  (持久化到DB)      │
         │                    │                    │
         │                    │  ③拉取账单         │
         │                    │ <──────────────────│
         │                    │  (GET /billing/{id})│
         │                    │                    │
         │                    │                    │ ④执行结算
         │                    │                    │ (分成比例计算)
         │                    │                    │
         │                    │                    │ ⑤记录结算状态
         │                    │                    │ (SETTLED/FAILED)
         └                    └                    └
                                                     │
  ┌──────────────┐                               ┌───┴──────────┐
  │open-api-catalog│                              │  结算记录     │
  │  (分账/计量汇入)│                              │  (DB)        │
  └──────┬───────┘                               └──────────────┘
         │
         │  ⑥聚合API调用量计量
         │  (按租户×时间范围)
         │
         │  ⑦导出到finops        ┌──────────────┐
         │ ──────────────────>  │ finops-billing│
         │   (POST /generate)    │  (触发账单)   │
         │                       └──────────────┘
         │
         │  ⑧返回导出结果
         │  (含finops账单ID)
         v
```

### 2.2 数据流步骤说明

| 步骤 | 方向 | 说明 |
|------|------|------|
| ① | Prometheus → finops-billing | 账单生成器从 Prometheus 采集 CPU/内存/存储/GPU/网络五维度用量 |
| ② | finops-billing 内部 | 按单价计算各项金额，汇总成账单 JSON，持久化到数据库 |
| ③ | asset-exchange → finops-billing | 结算方调用 finops API 拉取账单详情（含总金额与账期） |
| ④ | asset-exchange 内部 | 按分成比例（默认提供方 80% / 平台 20%）计算结算金额 |
| ⑤ | asset-exchange 内部 | 创建结算记录，状态置为 SETTLED，持久化 |
| ⑥ | open-api-catalog 内部 | 聚合指定时间范围内当前租户全部 API 的调用计量 |
| ⑦ | open-api-catalog → finops-billing | 将 API 调用量导出到 finops，触发账单生成 |
| ⑧ | open-api-catalog → 调用方 | 返回导出结果，含 finops 账单 ID 供后续追溯 |

## 3. 三组件接口契约

### 3.1 finops-billing（出账）

**服务地址**：`http://localhost:8085`（端口 8085）
**路由前缀**：`/api/finops/v1/billing`

| 端点 | 方法 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| `/generate` | POST | 触发账单生成 | `BillingGenerateRequest` | `BillingGenerateResponse` (201) |
| `/{id}` | GET | 查询账单详情 | - | `BillingGenerateResponse` (200) |
| `` | GET | 查询当前租户全部账单 | - | `{tenant, count, bills[]}` (200) |

**BillingGenerateRequest**：
```json
{
  "billingPeriod": "2026-08",
  "start": "2026-08-01T00:00:00Z",
  "end": "2026-09-01T00:00:00Z",
  "namespace": "ns-1",
  "pricingConfigName": "default",
  "overwrite": false
}
```

**BillingGenerateResponse**：
```json
{
  "id": "uuid",
  "tenantId": "tenant-a",
  "billingPeriod": "2026-08",
  "items": [
    {
      "resourceType": "CPU",
      "namespace": "ns-1",
      "usage": 10.0,
      "unitPrice": 2.0,
      "amount": 20.0000,
      "gpuModel": null
    }
  ],
  "totalAmount": 35.5000,
  "status": "GENERATED",
  "generatedAt": "2026-09-12T10:00:00Z",
  "periodStart": "2026-08-01T00:00:00Z",
  "periodEnd": "2026-09-01T00:00:00Z",
  "note": "出账闭环账单：共 5 个明细项..."
}
```

**五维度默认单价**：

| 维度 | 单位 | 单价（元） |
|------|------|-----------|
| CPU | 核时 | 2.0 |
| 内存 | GB·时 | 0.5 |
| 存储 | GB·时 | 0.3 |
| GPU | 卡时 | 8.0（default）/ 12.0（A100）/ 6.0（V100）/ 3.0（T4） |
| 网络 | GB | 0.2 |

### 3.2 asset-exchange（结算）

**服务地址**：`http://localhost:8087`（端口 8087）
**路由前缀**：`/api/v1`

| 端点 | 方法 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| `/settlements` | POST | 基于账单 ID 触发结算 | `BillingSettlementRequest` | `BillingSettlementResponse` (201) |
| `/settlements` | GET | 查询结算列表 | query params | `{tenant, count, settlements[]}` (200) |
| `/settlements/{id}` | GET | 查询结算详情 | - | 结算详情 dict (200) |

**BillingSettlementRequest**：
```json
{
  "billingId": "finops-billing-uuid",
  "assetId": "asset-001",
  "providerShare": 0.8,
  "platformShare": 0.2
}
```

**BillingSettlementResponse**：
```json
{
  "settlementId": "uuid",
  "billingId": "finops-billing-uuid",
  "tenantId": "tenant-a",
  "billingPeriod": "2026-08",
  "billingAmount": 35.50,
  "totalAmount": 35.50,
  "providerRevenue": 28.40,
  "platformRevenue": 7.10,
  "status": "settled",
  "settledAt": "2026-09-12T10:05:00Z",
  "errorMessage": null
}
```

**结算流程**：
1. 调用 finops-billing `GET /api/finops/v1/billing/{billingId}` 获取账单
2. 校验账单租户与当前租户一致（admin 可跨租户）
3. 按分成比例计算提供方收益与平台抽成
4. 创建结算记录，状态 SETTLED，持久化

### 3.3 open-api-catalog（分账/计量汇入）

**服务地址**：`http://localhost:8090`（端口 8090）
**路由前缀**：`/api/v1`

| 端点 | 方法 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| `/billing/export-usage` | POST | 导出 API 调用量到 finops | `ExportUsageRequest` | `ExportUsageResponse` (200) |

**ExportUsageRequest**：
```json
{
  "period": "2026-08",
  "range": "30d"
}
```

**ExportUsageResponse**：
```json
{
  "tenantId": "tenant-a",
  "period": "2026-08",
  "exportedAt": "2026-09-12T10:10:00Z",
  "totalApis": 3,
  "totalCalls": 1500,
  "totalCost": 45.75,
  "items": [
    {
      "apiId": "api-001",
      "apiName": "数据查询API",
      "callCount": 1000,
      "totalCost": 30.0,
      "totalTrafficBytes": 104857600
    }
  ],
  "finopsBillingId": "finops-billing-uuid",
  "finopsTotalAmount": 35.50,
  "status": "SUCCESS"
}
```

**计量汇入流程**：
1. 列出当前租户的全部 API
2. 对每个 API 聚合指定时间范围内的调用计量（次数/费用/流量）
3. 汇总租户级 API 调用成本
4. 调用 finops-billing `POST /api/finops/v1/billing/generate` 触发账单生成
5. 返回导出结果（含 finops 账单 ID 供追溯）

## 4. 技术栈

| 组件 | 技术栈 | 端口 | 持久化 |
|------|--------|------|--------|
| finops-billing | Java 17 / Spring Boot 3.2.x / JPA | 8085 | H2（开发）/ PostgreSQL（生产） |
| asset-exchange | Python 3.10+ / FastAPI / httpx | 8087 | SQLite / Mock |
| open-api-catalog | Python 3.10+ / FastAPI / httpx | 8090 | SQLite / Mock |

## 5. 安全与租户隔离

- **JWT 认证**：三组件均通过 `common-security` Starter（Java）/ `jwt_auth.py`（Python）校验 JWT
- **租户隔离**：租户 ID 一律从 JWT claim `tenantId` 获取，不信任请求参数
  - finops-billing：`TenantContext.getTenantId()`
  - asset-exchange：`AuthContext.tenantId`
  - open-api-catalog：`AuthContext.tenantId`
- **跨租户校验**：结算时校验账单租户与当前租户一致（admin 角色可跨租户）
- **JWT 透传**：asset-exchange / open-api-catalog 调用 finops 时透传 JWT，保持租户链路

## 6. 降级策略

| 故障场景 | 降级行为 | 影响范围 |
|----------|----------|----------|
| Prometheus 不可用 | finops-billing 以 0 用量生成账单 | 账单金额为 0，闭环不中断 |
| finops-billing 不可用 | asset-exchange 结算返回错误 | 结算失败，可重试 |
| finops-billing 不可用 | open-api-catalog 导出标记 FAILED | 计量聚合结果仍返回，导出待重试 |
