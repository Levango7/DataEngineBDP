# 资产交付实现状态

> 面向：产品口径核对、交付验收、后续补实现。
> 结论：**三种交付方式中只有 API 交付具备真实实现**；文件交付与数据库直连交付
> 此前返回假产物（假 URL、假 checksum、假只读账号）并标记成功，现已改为**如实失败**，
> 本文记录其解锁条件。
>
> 变更时间：2026-09-26（v2.1.0-RC 生产化加固批次）

## 1. 为什么要改

`asset-exchange` 的交付服务原本是这样"完成"交付的：

| 方式 | 原产物 | 问题 |
| --- | --- | --- |
| API | `apiKey = "ak-" + "x"*32` | 假的 Access Key。真正的 key 由 open-api-catalog 在审批时发放、并写入 APISIX key-auth（`services/subscription.py:72`、`services/apisix_config.py:95`），假 key 过不了网关 |
| 文件 | `https://storage.example.com/...` + `checksum: sha256:0000...` | 域名不存在、校验和恒为全 0，消费方无法校验也无法下载 |
| 数据库直连 | `username: ro_user` + `password: "***"` | 凭据是占位符，且把"密码"这类字段写进交付产物本身就不安全 |
| 全部 | `dataRows = sampleRows`、`dataBytes = rows * 256` | 编造的用量统计，会被当成真实交付规模 |

三种情况都会把状态置为 `SUCCEEDED`。消费方据此集成，问题要到真实调用才暴露——
这比"明确告诉他还不能做"更糟。

## 2. 现在的行为

| 方式 | 状态 | 说明 |
| --- | --- | --- |
| API | **真实** | 向开放 API 目录取该订阅方对该 API 的订阅；已发放 AK → `SUCCEEDED`，产物含 `credentialSource=open-api-catalog`、`accessKeyMasked`、`catalogSubscriptionId`、`grantedQuota`；未审批 → 交付留在 `PENDING` 并写明"等待提供方审批发放 Access Key"，不谎报成功 |
| 文件 | **如实失败** | `FAILED`，`errorMessage` 指明缺什么、指向本文 |
| 数据库直连 | **如实失败** | 同上 |

安全约束：交付记录里**只存掩码 AK**（`ak-r****7890` 形式）与凭证引用，不存明文凭据；
完整 AK 的唯一权威来源仍是开放 API 目录的订阅详情接口。`secretKey` 本就在目录侧脱敏，
不经交付产物回传。

用量口径：`dataRows` / `dataBytes` 不再估算，保持 0，并在 `artifactMeta.usageMeasuredBy`
标注真实用量来源（open-api-catalog 计量服务）。

## 3. 待补条件（记载在案）

### 文件交付（FILE）

需要三项能力，缺一则只能保持失败态：

1. **数据集物化**：把资产的查询结果落成文件（当前平台无"资产 → 数据文件"的产出链路，
   治理侧只有元数据，不含数据本体）。
2. **对象存储写入 + 预签名**：`platform/storage-io`（Java，AWS S3 SDK）已具备 put/presign，
   但 asset-exchange 是 Python 服务，需要一个 S3/MinIO 客户端依赖或改由 storage-io 提供
   一个签名 HTTP 接口。
3. **真实校验和**：对落盘文件计算 sha256（而非占位串），并在交付产物里带上大小与过期时间。

最小可行路径建议：交付时调用 Trino/Doris 把数据集导出到 MinIO 的
`sq-delivery/<tenant>/<deliveryId>/`，计算 sha256 后生成 15 分钟预签名 URL 回传。

### 数据库直连交付（DATABASE_DIRECT）

1. **凭据托管**：需要为消费方创建**短期只读账号**，凭据应进密钥系统
   （本仓已有 `docs/SECRETS-MANAGEMENT-GUIDE.md` 与 external-secrets chart），
   绝不能再写进交付 JSON。
2. **源库权限编排**：需要按租户/数据集做行级或视图级隔离，否则会越权读全库。
3. **到期回收**：账号回收（`expireAt`）目前无任何执行方。

## 4. 对产品口径的影响

设计文档与 README 里"支持三种交付方式 / 数据资产流通全流程落地"的表述**目前不成立**，
应改为："API 交付已落地（凭证由开放 API 目录发放）；文件交付与数据库直连交付为规划能力，
当前明确返回不可用"。相关口径订正已列入 P1 文档订正清单。

## 5. 测试覆盖
