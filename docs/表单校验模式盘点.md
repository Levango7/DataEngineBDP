## 三、统一建议

### 主流模式

**computed FormRules** 是绝对主流（81.5%），已形成事实标准。建议以此为基础统一封装 `useFormValidation` composable。

### useFormValidation composable 设计（建议）

```ts
// frontend/src/composables/useFormValidation.ts
import { ref, computed, type Ref } from 'vue'
import type { FormInstance, FormRules } from 'element-plus'

export function useFormValidation<T extends Record<string, any>>(
  formRef: Ref<FormInstance | undefined>,
  rulesFactory: (form: T) => FormRules,
  formData: Ref<T>
) {
  const rules = computed<FormRules>(() => rulesFactory(formData.value))

  async function validate(): Promise<boolean> {
    if (!formRef.value) return false
    try {
      await formRef.value.validate()
      return true
    } catch {
      return false
    }
  }

  async function submit(onValid: () => Promise<void> | void): Promise<void> {
    const valid = await validate()
    if (!valid) return
    await onValid()
  }

  return { rules, validate, submit }
}
```

### 迁移优先级

1. **高优先级**：模式 (3) plain object rules → 迁移到 computed FormRules（补类型标注）
2. **中优先级**：模式 (2) static FormRules → 如规则依赖表单数据则迁移到 computed
3. **低优先级**：模式 (1) computed FormRules → 逐步改用 `useFormValidation` composable

## 四、结论

项目表单校验已高度统一（81.5% 使用 computed FormRules），建议：
1. 将 2 个 plain object rules 文件补上 `FormRules` 类型标注
2. 创建 `useFormValidation` composable 统一封装，新表单优先使用
3. 现有表单可渐进式迁移，无需一次性重构
