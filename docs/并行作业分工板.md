## 三、并行作业的六条硬规矩（本仓实测踩过的坑）

1. **只按路径 stage**，禁止 `git add -A` / `git add .`——工作树里长期存在对方的未提交文件。
   提交前跑一次 `git status --porcelain`，确认 staged 列表只含自己的路径。
2. **不许 `checkout` / `reset` / `stash` 别人的分支或工作树**。需要切分支做实验时，
   用**仓库外**的临时 worktree：`git worktree add --detach ../<唯一名> <ref>`，用完 `git worktree remove`。
   （放进仓库内会被门禁脚本的 `rglob` 重复扫到，计数翻倍。）
3. **不复用对方的活动环境**：别人起的容器/集群/服务不要用；自己起时端口先 `netstat -ano` 反查归属，
   用完 `docker rm -f <精确名>`；kind/k3d 集群名带自己的标识，且用独立 `KUBECONFIG`，
   不要改共享的 `~/.kube/config` 当前上下文。
4. **CI 的 `concurrency: cancel-in-progress`**：任何一次 push 都会杀掉同 ref 正在跑的 run。
   推送前先确认上一轮已终判；连续推送只会让验证互相作废。
5. **不要直推 `main`**：本仓 protected main 会"带警告放行"，绕过 8 条 required 检查。
   走分支 + PR，让门禁真的跑过再谈合并（合并权在人）。
6. **结论自己重跑**：对方（含本板）写的数字/状态都只当线索，引用前自己复测一遍。
