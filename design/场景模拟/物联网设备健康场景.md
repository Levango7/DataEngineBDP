## 第1章 场景背景

### 1.1 业务概况

某工业物联网运营商（管理设备 50 万台、覆盖工厂 120 家、日均上报数据点 12 亿条）启动设备健康度监测平台建设，目标是从"故障后维修"升级为"预测性维护 + 实时告警 + 健康度评分"全链路设备管理体系，覆盖以下场景：

1. **设备健康度实时评分**：基于温度、振动、电流、运行时长等多维指标实时计算设备健康度（0-100 分），秒级刷新。
2. **异常检测与告警**：基于规则 + ML 模型识别设备异常模式（温度骤升、振动超标、电流异常），秒级触发告警并推送至运维人员。
3. **预测性维护**：基于历史时序数据训练设备剩余使用寿命（RUL）模型，提前 7-14 天预警设备可能故障，减少非计划停机。
4. **设备画像与分组管理**：按设备类型/工厂/产线/工况维度构建设备画像，支持分组聚合查看与健康度对比。
5. **运维看板**：设备健康度大盘、告警统计、故障趋势、RUL 预测排行、维保工单关联。

### 1.2 物联网挑战与平台能力

表：物联网挑战与平台能力对照表

| 挑战 | 平台能力 |
| --- | --- |
| 50 万设备 × 20 指标 × 1s 采样 = 1000 万点/秒写入 | IoTDB 时序引擎集群 + 批量写入 + 降采样压缩 |
| 设备健康度需秒级计算，依赖实时时序聚合 | Flink 实时流 + IoTDB UDF 滑动窗口聚合 |
| 异常模式多样，单一规则无法覆盖 | 规则引擎 + ML 异常检测（Isolation Forest + LSTM）组合 |
| RUL 预测需长周期历史数据训练 | IoTDB 历史数据导出 + Spark 特征工程 + MLflow 模型管理 |
| 设备分布广，网络不稳定，需断点续传 | MQTT 协议 + 边缘端缓存 + 断点续传 + 数据补偿 |
| 时序数据量大，需分级存储与降采样 | IoTDB 热温冷分级 + 自动降采样（1s→1min→1h→1d） |

### 1.3 平台技术选型

表：物联网设备健康场景技术选型对照表

| 层次 | 组件 | 选型 | 用途 |
| --- | --- | --- | --- |
| 设备接入 | 协议 | MQTT 5.0 + CoAP | 设备遥测数据上报与指令下发 |
| 数据缓冲 | 消息 | Kafka 3.x | 设备遥测数据流 |
| 时序存储 | 引擎 | IoTDB 1.3 | 时序数据存储 + 降采样 + UDF |
| 实时计算 | 引擎 | Flink 1.18 + CEP | 实时健康度计算 + 异常检测 |
| 离线计算 | 引擎 | Spark 3.5 | RUL 模型训练 + 特征工程 |
| 湖仓存储 | 表格式 | Iceberg V2 | 设备画像/维表/告警记录 |
| ML 平台 | 引擎 | MLflow + Isolation Forest + LSTM | 异常检测 + RUL 预测模型 |
| 数据服务 | 网关 | 统一 SQL 网关 + APISIX | 设备看板 + 告警 API |
| 权限 | 身份 | Keycloak + RBAC | 运维/设备管理员/查看者角色隔离 |

## 第2章 部署步骤

### 2.1 前置条件

- 平台已部署 IoTDB 集群（3 节点，SSD 存储）
- 平台已部署 Flink 集群（TaskManager ≥ 4）
- 租户已开通物联网行业模板授权
- 设备端已配置 MQTT 上报地址与认证凭据

### 2.2 一键部署流程

| 步骤 | 操作 | 预期输出 |
| --- | --- | --- |
| 1 | 在行业模板市场选择"物联网设备健康度"模板，点击"部署" | 弹出参数配置表单 |
| 2 | 填写参数：租户 ID、IoTDB 存储组名、设备数量、采样频率 | 参数校验通过 |
| 3 | 点击"确认部署"，等待 Helm Chart 安装 | 状态：部署中 → 部署成功 |
| 4 | 验证 DDL 已创建（IoTDB 时序序列 + Iceberg 设备画像表） | `SHOW TIMESERIES` 返回预期序列 |
| 5 | 验证 DAG 作业已注册（健康度计算 + 异常检测 + RUL 训算流） | 调度中心显示 3 个作业流 |
| 6 | 验证 Dashboard 看板已生成 | 运维看板可访问 |
| 7 | 配置 MQTT 设备接入地址，启动设备模拟器上报数据 | IoTDB 收到时序数据 |

## 第4章 预期结果

### 4.1 功能预期

- 设备健康度评分覆盖 100% 在线设备，评分准确率 ≥ 92%
- 异常检测告警延迟 < 5 秒，误报率 < 5%
- RUL 预测提前预警天数 ≥ 7 天，预测误差 < 15%
- 时序数据写入吞吐 ≥ 1000 万点/秒，查询延迟 < 100ms（单设备）

### 4.2 运营预期

- 非计划停机减少 ≥ 30%
- 运维人员巡检效率提升 ≥ 50%（看板驱动）
- 设备数据存储成本降低 ≥ 40%（降采样 + 分级存储）
- 故障平均修复时间（MTTR）缩短 ≥ 20%

### 4.3 兼容性预期

- V1.0 已安装 `iot-device-health` 模板的租户可通过 Helm upgrade 平滑升级到 V2.0 增强版
- V1.0 时序数据与 V2.0 共享同一 IoTDB 集群，按租户 Namespace 隔离
- 与能源行业模板共享 IoTDB 时序底座，无资源冲突
