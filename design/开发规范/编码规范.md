# 编码规范

> 归属：多平台多租户大数据平台 · 开发规范文档
> 版本：v1.0 ｜ 日期：2026-08-18 ｜ 状态：已完成

## 1. 总则

### 1.1 目标

为多平台多租户大数据平台建立统一的编码风格基线，确保：

- **可读性**：任意工程师可在 5 分钟内读懂任意文件结构。
- **可维护性**：相同问题只有一种写法，重构无歧义。
- **可审计性**：等保三级要求代码可追溯、可审查，命名/注释/日志满足审计需要。
- **多语言一致**：Java/Python/TS/Scala/SQL 跨语言共享同一命名哲学与文件组织规则。

### 1.2 适用范围

| 语言 | 主要场景 | 强制等级 |
| --- | --- | --- |
| Java 17 | 后端服务、Spring Boot 3.x | 强制 |
| Python 3.10+ | 数据处理、AI、运维脚本 | 强制 |
| TypeScript 5.x | 前端 Vue 3、Node 工具链 | 强制 |
| Scala 2.12+ | Spark 引擎层 | 强制 |
| SQL / Hive SQL | 数据建模、ETL | 强制 |
| Shell / Bash | 部署脚本、CI/CD | 推荐 |

### 1.3 例外豁免

- 引入第三方开源模块时遵循上游风格，但接口边界须遵循本规范。
- 生成代码（protobuf、OpenAPI codegen）不强制本规范，但禁止手工修改生成文件。

## 2. 通用规则

### 2.1 文件组织

1. 单文件行数上限 **800 行**，超过须拆分模块。
2. 单函数行数上限 **80 行**，超过须抽取私有方法。
3. 单行字符上限 **120**，长字符串换行用语言原生拼接。
4. 文件必须以单一主类型为单位（一个 Java 文件一个 public class，一个 Python 文件一个主模块）。
5. 文件末尾保留一个空行，禁止连续空行超过 2 行。

### 2.2 命名规范

| 类型 | Java | Python | TypeScript | Scala | 示例 |
| --- | --- | --- | --- | --- | --- |
| 包/模块 | `com.nexus.xxx` | `nexus_xxx` | `@nexus/xxx` | `nexus.xxx` | `com.nexus.datagate` |
| 类 | PascalCase | PascalCase | PascalCase | PascalCase | `DataGateService` |
| 接口 | PascalCase + I 前缀禁用 | 同左 | 同左 | 同左 | `Repository` |
| 方法 | camelCase | snake_case | camelCase | camelCase | `getUserById` / `get_user_by_id` |
| 变量 | camelCase | snake_case | camelCase | camelCase | `userId` / `user_id` |
| 常量 | UPPER_SNAKE | UPPER_SNAKE | UPPER_SNAKE | UPPER_SNAKE | `MAX_RETRY` |
| 枚举 | PascalCase + UPPER_SNAKE 成员 | 同左 | 同左 | 同左 | `Status.RUNNING` |
| 文件 | PascalCase.java | snake_case.py | PascalCase.vue / kebab-case.ts | PascalCase.scala | `UserRepo.java` |

### 2.3 注释规范

- **类注释**：必填，使用 Javadoc / docstring / TSDoc，说明职责、线程安全性、作者。
- **方法注释**：公有方法必填，包含参数、返回值、异常、示例。
- **行内注释**：仅注释"为什么"，不注释"是什么"。禁止 `i++; // i 加 1`。
- **TODO/FIXME**：必须带署名与日期：`// TODO(zhang.san, 2026-09-01): 优化查询计划`。
- **文档语言**：中文注释为主，对外 API 注释中英双语。

### 2.4 异常处理

1. 禁止捕获 `Exception` / `Throwable` 后空处理，必须至少记录日志或重新抛出。
2. 业务异常使用领域自定义异常（如 `TenantNotFoundException`），禁止用 `RuntimeException` 透传业务语义。
3. 异常信息禁止拼接用户输入，防止日志注入。
4. 资源操作必须使用 try-with-resources / with / using，禁止手动 close。

### 2.5 日志规范

| 级别 | 使用场景 |
| --- | --- |
| ERROR | 影响业务正确性，需人工介入 |
| WARN | 可降级异常、限流触发、重试成功 |
| INFO | 关键业务节点、状态变更 |
| DEBUG | 排查问题辅助信息，生产默认关闭 |
| TRACE | 极细粒度调用链，仅本地调试 |

- 禁止使用 `System.out.println` / `print()` 输出业务日志。
- 日志必须带 traceId / tenantId 上下文。
- 敏感字段（密码、token、身份证）必须脱敏后输出。

## 3. Java 编码规范

### 3.1 工程结构

```text
module-xxx/
├── src/main/java/com/nexus/xxx/
│   ├── api/           # 对外 REST/RPC 接口
│   ├── domain/        # 领域模型（Entity、VO、Aggregation）
│   ├── service/       # 应用服务
│   ├── repository/    # 持久化
│   ├── infra/         # 基础设施适配器
│   └── common/        # 通用工具、常量、枚举
└── src/test/java/     # 镜像目录结构
```

### 3.2 关键规则

1. **依赖方向**：api → service → domain ← repository，domain 不依赖任何外层。
2. **Lombok 使用**：仅允许 `@Getter/@Setter/@Builder/@Slf4j`，禁止 `@Data`（避免 toString 泄露）。
3. **Optional 使用**：返回值可用 `Optional<T>`，字段、参数禁止用 Optional。
4. **Stream 使用**：单次遍历用 Stream，多步调试用 for；禁止在 Stream 中调用有副作用的方法。
5. **注解顺序**：类注解顺序 `@Documented > @Retention > @Target > @Deprecated > 业务注解`。
6. **空集合返回**：返回集合禁止返回 null，使用 `Collections.emptyList()`。
7. **字符串判空**：使用 `StringUtils.isBlank()`，禁止 `str == null || str.isEmpty()`。

### 3.3 Spring Boot 约定

- Controller 不写业务逻辑，仅做参数绑定与结果封装。
- Service 事务边界在 Service 层，Controller 禁止 `@Transactional`。
- 配置注入使用 `@ConfigurationProperties`，禁止 `@Value` 散落。
- Bean 命名：Service 用 `xxxService`，Repository 用 `xxxRepository`，Controller 用 `xxxController`。

## 4. Python 编码规范

### 4.1 工程结构

```text
nexus_xxx/
├── __init__.py
├── api/              # FastAPI 路由
├── domain/           # 领域模型（pydantic）
├── service/          # 业务服务
├── repository/       # 持久化
├── infra/            # 基础设施
└── common/           # 通用工具
```

### 4.2 关键规则

1. **类型注解**：所有函数签名必须带类型注解，启用 `mypy --strict`。
2. **格式化**：使用 `black --line-length 120` + `isort` + `flake8`。
3. **异步优先**：IO 密集场景使用 async/await，禁止在 async 函数中调用同步阻塞 API。
4. **数据类**：领域模型使用 `pydantic.BaseModel`，禁止用 dict 透传业务数据。
5. **异常**：业务异常继承 `NexusError` 基类，带 code + message + trace_id。
6. **导入**：标准库 → 第三方 → 本项目，分组用空行分隔。

## 5. TypeScript / Vue 编码规范

### 5.1 工程结构

```text
src/
├── api/             # 接口封装
├── components/      # 通用组件
├── composables/     # 组合式函数
├── stores/          # Pinia store
├── views/           # 页面
├── router/          # 路由
├── utils/           # 工具
└── types/           # 类型定义
```

### 5.2 关键规则

1. **Vue 3 Composition API**：禁止使用 Options API，统一 `<script setup lang="ts">`。
2. **Pinia store**：统一 `defineStore('xxx', () => { ... })` 工厂写法。
3. **Props/Emits**：使用 `defineProps<T>()` 泛型写法，禁止运行时声明。
4. **命名**：组件 PascalCase，组合式函数 `useXxx`，store `useXxxStore`。
5. **样式**：使用 `scoped` + 设计系统 CSS 变量，禁止硬编码颜色。
6. **异步**：统一 `await` 写法，禁止 `.then()` 链式调用业务代码。
7. **TS 严格模式**：`strict: true`，禁止 `any`，禁止 `@ts-ignore`（用 `@ts-expect-error` 带原因）。

## 6. SQL / Hive SQL 编码规范

### 6.1 关键规则

1. **关键字大写**：`SELECT / FROM / WHERE / JOIN / GROUP BY` 全大写。
2. **表名小写下划线**：`ods_user_event`，禁止驼峰。
3. **字段别名**：使用 `AS` 显式声明，禁止隐式别名。
4. **JOIN 类型**：必须显式写 `INNER JOIN` / `LEFT OUTER JOIN`，禁止裸 `JOIN`。
5. **分区分区**：Hive 查询必须带分区谓词 `dt = 'xxx'`，禁止全表扫描。
6. **禁止 SELECT \***：明确列出字段，避免下游字段变更破坏。
7. **注释**：单行 `--`，多行 `/* */`，每个 CTE 须有注释说明用途。

### 6.2 命名约定

| 层 | 前缀 | 示例 |
| --- | --- | --- |
| ODS | `ods_` | `ods_user_log` |
| DWD | `dwd_` | `dwd_user_event_di` |
| DWS | `dws_` | `dws_user_active_1d` |
| ADS | `ads_` | `ads_user_retention_report` |
| DIM | `dim_` | `dim_user` |

## 7. 安全编码要求

### 7.1 输入校验

- 所有外部输入（HTTP/RPC/消息）必须经过 schema 校验后才进入业务层。
- SQL 必须使用预编译参数绑定，禁止字符串拼接 SQL。
- 文件上传必须校验 MIME + 大小 + 内容头魔数。

### 7.2 敏感数据

- 密码使用 BCrypt（cost ≥ 12）或 SM3 + 随机盐，禁止 MD5/SHA1。
- 身份证、手机号日志输出脱敏（保留首 3 末 4）。
- 配置中的密钥使用 Vault 或 Sealed Secrets，禁止明文入库。

### 7.3 依赖安全

- 引入新依赖必须经过安全扫描（Trivy / Snyk），CVE 高危禁止引入。
- 锁文件 `package-lock.json` / `poetry.lock` / `gradle.lockfile` 必须提交。

## 8. 工具链与 CI 校验

### 8.1 强制工具

| 语言 | 格式化 | Lint | 安全扫描 | 覆盖率 |
| --- | --- | --- | --- | --- |
| Java | spotless | checkstyle | spotbugs + trivy | jacoco ≥ 80% |
| Python | black + isort | flake8 + mypy | bandit + trivy | pytest-cov ≥ 80% |
| TS | prettier | eslint + vue-tsc | eslint-plugin-security | cypress + vitest ≥ 80% |
| Scala | scalafmt | scalafix | trivy | scoverage ≥ 80% |

### 8.2 CI 强制门禁

1. PR 必过：format check + lint + unit test + 安全扫描。
2. 主分支必过：integration test + E2E + 性能基准。
3. 覆盖率不达标禁止合并，禁止降低覆盖率阈值。
4. 任意 warning 视为 error，禁止 `//noinspection` 抑制。
