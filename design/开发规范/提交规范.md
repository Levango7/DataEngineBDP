# Git 提交规范

> 归属：多平台多租户大数据平台 · 开发规范文档
> 版本：v1.0 ｜ 日期：2026-08-18 ｜ 状态：已完成

> 适用范围：全平台代码仓库的 Git 提交记录

---

## 1. 总则

### 1.1 目标

建立统一的 Git 提交信息规范，确保：

- **可追溯**：每个提交可追溯到具体变更类型与范围。
- **可生成**：提交信息可自动生成 CHANGELOG。
- **可审计**：等保三级要求变更可审查，规范提交即审计证据。
- **可定位**：通过提交信息可快速定位 `git log --grep` 查找相关变更。

### 1.2 强制范围

- 任意合并到 `main` / `release/*` 的 commit 必须符合本规范。
- PR squash merge 后的 commit message 必须符合本规范。
- 禁止 `git commit -m "fix"` / `git commit -m "update"` 等无意义提交。

## 2. 提交信息格式

### 2.1 Conventional Commits 1.0

采用 [Conventional Commits 1.0](https://www.conventionalcommits.org/) 规范：

```text
<type>(<scope>): <subject>

<body>

<footer>
```

### 2.2 字段定义

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `type` | 是 | 变更类型，见 §2.3 |
| `scope` | 否 | 变更范围（模块名），小写中划线 |
| `subject` | 是 | 简短描述，祈使句，句末不加句号，≤ 50 字符 |
| `body` | 否 | 详细说明，每行 ≤ 72 字符，解释"为什么"而非"是什么" |
| `footer` | 否 | 跟踪信息：`Closes #123`、`BREAKING CHANGE: xxx`、`Reviewed-by: xxx` |

### 2.3 Type 取值

| Type | 含义 | 是否触发 CHANGELOG | 示例 |
| --- | --- | --- | --- |
| `feat` | 新功能 | 是（minor） | `feat(tenant): 新增租户配额管理` |
| `fix` | Bug 修复 | 是（patch） | `fix(auth): 修复 token 过期未刷新` |
| `docs` | 文档变更 | 是（docs 段） | `docs(api): 更新错误码说明` |
| `style` | 格式变更（不影响代码逻辑） | 否 | `style(java): spotless 格式化` |
| `refactor` | 重构（无新功能无 bug 修复） | 否 | `refactor(repo): 抽取公共分页逻辑` |
| `perf` | 性能优化 | 是（perf 段） | `perf(query): 优化 N+1 查询` |
| `test` | 测试变更 | 否 | `test(user): 补充边界用例` |
| `build` | 构建/依赖变更 | 是（build 段） | `build(gradle): 升级 spring-boot 3.2` |
| `ci` | CI 配置变更 | 否 | `ci(github): 新增安全扫描 job` |
| `chore` | 杂项（不触发 CHANGELOG） | 否 | `chore: 更新 .gitignore` |
| `revert` | 回滚 | 是 | `revert: 回滚 feat(tenant) 配额管理` |

### 2.4 Scope 取值

`scope` 使用模块名小写中划线，常见取值：

| Scope | 对应模块 |
| --- | --- |
| `tenant` | 多租户 |
| `auth` | 认证授权 |
| `sql-gateway` | SQL 网关 |
| `lakehouse` | 湖仓引擎 |
| `governance` | 数据治理 |
| `schedule` | 调度编排 |
| `frontend` | 前端 |
| `deploy` | 部署 |
| `docs` | 文档 |
| `api` | API 规范 |
| `security` | 安全 |
| `test` | 测试 |

## 3. 完整示例

### 3.1 简单提交

```text
fix(auth): 修复 token 过期未自动刷新
```

### 3.2 带 body 的提交

```text
feat(tenant): 新增租户配额管理 API

- 新增 POST /api/v1/tenant/{id}/quota 接口
- 新增 GET /api/v1/tenant/{id}/quota 接口
- 配额项：CPU、内存、存储、API 调用次数
- 超额触发 429 状态码 + Retry-After 头

Closes #422
```

### 3.3 破坏性变更

```text
feat(api)!: 统一错误响应格式为 {code, message, traceId, data}

BREAKING CHANGE: 错误响应字段由 {errno, errmsg} 变更为 {code, message, traceId, data}，
所有客户端须同步升级到 v2.0 SDK。

Closes #500
```

### 3.4 多目的提交（不推荐，应拆分）

```text
feat(tenant): 新增租户配额 + 修复 token 刷新

建议拆分为两个 commit：
1. feat(tenant): 新增租户配额
2. fix(auth): 修复 token 刷新
```

## 4. 提交粒度

### 4.1 原则

1. **单一职责**：一个 commit 只做一件事，禁止"顺便改一下"。
2. **可独立构建**：任意 commit 都可 checkout 后成功构建。
3. **可独立回滚**：revert 任意 commit 不会破坏后续 commit（避免依赖倒置）。
4. **小步提交**：单 commit 行数建议 < 300，禁止 > 1000 行的巨型提交。

### 4.2 拆分技巧

```bash
# 使用 git add -p 交互式暂存，分批提交
git add -p src/auth/
git commit -m "fix(auth): 修复 token 过期"

git add -p src/tenant/
git commit -m "feat(tenant): 新增配额校验"
```

## 5. PR 合并方式

### 5.1 合并方式选择

| 方式 | 使用场景 | 主分支 commit 历史 |
| --- | --- | --- |
| Squash merge | 默认，单 commit PR | 线性，一个 PR 一个 commit |
| Rebase merge | 多 commit PR 且每个 commit 有意义 | 线性，保留多个 commit |
| Create merge commit | 仅用于 release 分支合并回 main | 保留 merge commit 信息 |

### 5.2 Squash merge 后的 commit message

PR squash merge 时，自动生成的 commit message 须符合本规范：

- 单 commit PR：使用原 commit message。
- 多 commit PR：使用 PR 标题（须符合规范）+ PR 描述作为 body。

## 6. 自动化校验

### 6.1 commitlint

使用 [commitlint](https://commitlint.js.org/) + [husky](https://typicode.github.io/husky/) 在 commit-msg 钩子中校验：

```js
// commitlint.config.js
module.exports = {
  extends: ['@commitlint/config-conventional'],
  rules: {
    'type-enum': [2, 'always', [
      'feat', 'fix', 'docs', 'style', 'refactor',
      'perf', 'test', 'build', 'ci', 'chore', 'revert'
    ]],
    'subject-max-length': [2, 'always', 50],
    'body-line-length': [2, 'always', 72],
    'header-full-stop': [0],
  }
};
```

### 6.2 CHANGELOG 自动生成

使用 [standard-version](https://github.com/conventional-changelog/standard-version) 或 [release-please](https://github.com/googleapis/release-please) 自动生成 CHANGELOG：

```bash
# 自动生成 CHANGELOG + 打 tag
npx standard-version
```

### 6.3 CI 校验

PR 流水线中增加 commitlint job：

```yaml
jobs:
  commitlint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - run: npx commitlint --from ${{ github.event.pull_request.base.sha }} --to ${{ github.event.pull_request.head.sha }}
```

## 7. 反模式

### 7.1 禁止的提交信息

| 反模式 | 问题 | 正确写法 |
| --- | --- | --- |
| `fix` | 无 type 无描述 | `fix(auth): 修复 token 过期` |
| `update file` | 无 type，描述模糊 | `docs(api): 更新错误码说明` |
| `WIP` | 工作中提交 | 应 stash 或本地分支，禁止推送 |
| `fix bug` | 描述无信息 | `fix(auth): 修复 token 过期未刷新` |
| `优化性能` | 无 type 无 scope | `perf(query): 优化 N+1 查询` |
| `修复张三的bug` | 主语错位 | `fix(tenant): 修复配额校验越界` |
| `feat: a, b, c` | 多目的混在一起 | 拆分为多个 commit |

### 7.2 禁止的提交行为

- ❌ `git commit --no-verify` 跳过钩子（除非紧急 hotfix 并事后补验证）。
- ❌ `git push --force` 到共享分支（特性分支个人可 force，共享分支禁止）。
- ❌ 提交大于 100MB 的文件（用 LFS 或外部存储）。
- ❌ 提交密钥、token、密码（即使后续删除，git 历史仍保留）。
- ❌ 提交生成文件（dist/、target/、node_modules/）。
