## 第1章 声明总述

V2.0 AI能力增强采用**"增强已有L4.5骨架 + 新增独立模块"混合策略**，并非全部新建，也非全部复用V1.0：

- **增强已有L4.5骨架组件**：3个V2.0模块，涉及4个V1.0 L4.5组件（vector-engine / knowledge-engine / llm-gateway / llmops）
- **新建独立模块**：3个V2.0模块（Agent编排引擎 / 模型评测平台 / AI数据分析助手），V1.0无对应骨架代码

表：T000c-01 V2.0 AI能力增强六大模块策略分类

| 策略 | V2.0模块数 | 模块列表 | 涉及V1.0 L4.5组件数 |
|------|-----------|----------|---------------------|
| 增强已有骨架 | 3 | 多模态RAG增强、大模型多模态网关、模型微调平台 | 4（vector-engine/knowledge-engine/llm-gateway/llmops） |
| 新建独立模块 | 3 | Agent编排引擎、模型评测平台、AI数据分析助手 | 0（复用V1.0基础设施但不复用L4.5骨架） |

**声明核心结论**：V2.0 AI能力增强并非"全部新建"，而是"增强3个已有L4.5骨架 + 新增3个独立模块"。增强策略保证向后兼容，不破坏V1.0 API契约；新建模块填补V1.0空白（Agent编排、模型评测、NL2SQL）。V1.0 L4.5骨架的Mock清零是V2.0增强的前置条件。

## 第7章 结论

### 7.1 声明结论

1. **V2.0 AI模块并非全部新建**，而是"增强3个已有L4.5骨架 + 新增3个独立模块"的混合策略
2. **增强策略保证向后兼容**，不破坏V1.0 API契约（V1.0 /api/v1/*保留，V2.0新增/api/v2/*）
3. **新建模块填补V1.0空白**（Agent编排、模型评测、NL2SQL），不复用V1.0 L4.5骨架代码但复用V1.0基础设施
4. **V1.0 L4.5骨架的Mock清零是V2.0增强的前置条件**（关联T000a核查结果：4个增强组件均为"❓部分清零"）

### 7.2 增强模块清单（3个）

- 多模态RAG增强（基于L4.5.3 vector-engine + L4.5.4 knowledge-engine）
- 大模型多模态网关（演进L4.5.6 llm-gateway）
- 模型微调平台（增强L4.5.5 llmops）

### 7.3 新建模块清单（3个）

- Agent编排引擎（V1.0无对应组件，复用L4.5.6网关+L4.2 DS做基础设施）
- 模型评测平台（V1.0无对应组件，复用L4.5.5 MLflow+L4.4 Superset做基础设施）
- AI数据分析助手（V1.0无对应组件，复用L2.7 SQL网关+L3.5资产目录做基础设施）

### 7.4 前置条件清单（关联T000a）

V2.0 AI能力增强的前置条件是V1.0 L4.5骨架Mock清零，具体清单：

- **P0高优先级**：vector-engine启用milvus_enabled build tag（多模态RAG依赖）、llm-gateway切换真实Provider（多模态网关+Agent+评测+助手均依赖）、llmops切换mlflow配置（微调+评测依赖）
- **P1中优先级**：knowledge-engine切换nebula+llm配置（多模态RAG依赖）、ml-platform实现真实后端（微调间接依赖）
- **P2低优先级**：tag-engine切换doris配置（非AI六大模块，行业模板增强前置）

### 7.5 对V2.0实施计划的建议

基于本声明，建议V2.0实施计划调整：

1. **增强模块实施**：在V1.0组件代码基础上扩展，保留Mock实现作为开发/测试/CI零依赖模式，补齐真实实现
2. **新建模块实施**：新建独立模块，复用V1.0基础设施（K8s部署/Helm Chart/可观测/鉴权/计量），不复用V1.0 L4.5骨架代码
3. **前置条件落实**：V2.0 Phase 1启动前，优先完成4个增强组件的Mock清零（关联T000a第一/第二优先级）
4. **API兼容性验证**：V2.0每个增强模块需验证V1.0 API向后兼容（V1.0客户端零改动可继续工作）
