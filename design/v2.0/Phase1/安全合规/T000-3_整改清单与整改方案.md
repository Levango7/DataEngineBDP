## 第1章 概述

### 1.1 整改目标

本整改方案基于 T000-2 差距分析报告识别的 12 项部分满足控制项，制定覆盖全部部分满足项的整改清单与整改实施方案，目标是将 12 项部分满足控制项全部转为已满足，使等保三级满足率从当前 67.6%（25/37）提升至 100%（37/37，排除 5 项不适用），为数擎大数据平台 V2.0 通过等保三级测评提供可执行的实施基准。

整改目标量化指标：

- 控制项满足率：67.6% → 100%（12 项部分满足全部转为已满足）
- 高风险项清零：2 项高风险（应用-2、数据-2）全部清零
- 中风险项清零：8 项中风险全部清零
- 低风险项清零：2 项低风险全部清零
- Mock 清零覆盖：rule-engine、open-api-catalog、encaps-layer、infra-provider-xinchang、infra-provider-baremetal 共 5 个组件安全相关 Mock 全部清零
- 信创国密适配：L0.1 国密卡适配落地，TLCP + SM2 证书登录 + SM4 列级加密信创链路贯通

### 1.2 整改范围

整改范围覆盖等保三级 6 类控制项中全部 12 项部分满足项，按根因聚类为 4 类整改主题：

1. **rule-engine Mock 清零主题**：影响应用-2（访问控制）、数据-2（数据保密性）、管理-5（安全运维管理）共 3 项控制项，含 2 项高风险，为最高优先级整改主题。
2. **信创国密卡适配主题**：影响主机-1（身份鉴别）、应用-1（身份鉴别）、应用-5（通信完整性）、应用-6（通信保密性）共 4 项控制项，均为中风险，为信创环境合规整改主题。
3. **APISIX 配置下发与封装层联动主题**：影响网络-2（网络访问控制）、网络-3（网络入侵防范）、网络-4（恶意代码防范）共 3 项控制项，均为中风险，为动态安全策略下发整改主题。
4. **环境方对接与管理流程完善主题**：影响物理-7（温湿度控制）、物理-8（电力供应）、管理-1（安全管理制度）、管理-5（安全运维管理）共 4 项控制项，含 2 项低风险，为环境对接与管理整改主题。

整改范围不包含 25 项已满足控制项（无需整改）与 5 项不适用控制项（由部署环境方负责，等保测评时提交环境方证明材料）。

### 1.4 整改原则

1. **高风险优先**：2 项高风险（应用-2、数据-2）为 P0 级，必须最先整改完成，消除数据泄露风险。
2. **根因聚类整改**：按根因聚类（rule-engine Mock / 信创国密卡 / APISIX 配置下发 / 环境对接），同一根因的多个控制项集中整改，避免重复开发。
3. **Mock 清零优先**：5 个组件安全相关 Mock（rule-engine、open-api-catalog、encaps-layer、infra-provider-xinchang、infra-provider-baremetal）全部清零，从 SIMULATED 占位返回切换为真实实现。
4. **信创非信创双栈**：信创环境国密（SM2/SM3/SM4/TLCP）与非信创环境国际算法（RSA/SHA/AES/TLS1.3）双栈实现，经 Profile 切换，不破坏非信创环境已满足项。
5. **技术整改与管理整改并行**：技术整改（16 项 48d）由开发团队执行，管理整改（2 项 4d）由安全合规工程师执行，两者无依赖可并行。
6. **与 Phase 1 排期对齐**：整改排期与 Phase 1 批次 2（T020，2026-10-01 ~ 2026-11-09）+ 批次 3（T021，2026-11-10 ~ 2026-11-21）对齐，不超出 Phase 1 时间窗口。

## 第3章 技术整改方案（16 项，48 人天）

### 3.1 R01 rule-engine Mock 清零 + L3.7 脱敏规则真实执行 + 行级权限联动

#### 3.1.1 整改目标

将 rule-engine 组件规则执行器从返回 SIMULATED 占位结果改为真实执行脱敏规则，L3.7 数据安全模块脱敏规则经 GitOps 版本化配置，运行时由 rule-engine 引擎执行，X1 ABAC 层根据脱敏结果做行级权限联动判定，消除应用-2（访问控制）高风险差距。

#### 3.1.2 差距根因

rule-engine 组件 `platform/rule-engine/internal/executor/executor.go` 中规则执行器返回 SIMULATED 占位结果，L3.7 数据安全模块脱敏规则依赖 rule-engine 执行，导致脱敏规则无法真实生效，敏感数据（如身份证号、手机号）可能以明文展示给无权用户。

#### 3.1.3 整改措施

1. **rule-engine Mock 清零**：将 `Executor.Execute()` 方法从返回 SIMULATED 改为真实执行脱敏规则，支持正则脱敏、哈希脱敏、掩码脱敏三种规则类型。
2. **L3.7 脱敏规则真实执行**：脱敏规则经 GitOps 版本化配置（`desensitize-rules.yaml`），运行时由 rule-engine 引擎加载并执行，脱敏结果写入 ABAC 上下文。
3. **行级权限联动**：X1 ABAC 层在运行时根据 Token claim + 资源安全标记 + 脱敏规则做访问判定，敏感列无权访问时返回脱敏值或拒绝。
4. **端到端测试**：验证敏感数据（身份证号、手机号）展示时被正确脱敏，无权用户看到脱敏值，有权用户看到明文。
