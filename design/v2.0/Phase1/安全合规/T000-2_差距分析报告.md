## 第1章 报告概述

### 1.1 报告目的

本报告基于 T000-1 产出的等保三级标准解读与现状盘点，对 GB/T 22239-2019 第三级 6 类 42 条控制项逐条进行差距分析，识别每条控制项的满足状态（已满足 / 部分满足 / 未满足 / 不适用），评定风险等级（高 / 中 / 低），给出整改建议与预估工时，并按风险等级排序形成整改优先级清单，为后续整改实施与等保测评提供输入基准。

### 1.2 评估范围

- **对标标准**：GB/T 22239-2019《信息安全等级保护基本要求》第三级，6 类控制项（物理安全 / 网络安全 / 主机安全 / 应用安全 / 数据安全 / 管理安全），共 42 条控制项。
- **评估对象**：数据引擎大数据平台 V2.0（L0-L5 五层 + X 横切层架构），覆盖 22 自研组件 + 49 模块。
- **评估维度**：设计态（架构设计是否覆盖控制项要求）+ 实现态（当前代码与配置的实际落地情况，含 Mock 清零状态、配置切换状态、能力实现状态）。
- **四环境交付形态**：信创环境 / 本地数据中心 / 公有云 / 私有云，差距分析按环境差异分别标注。

### 1.3 评估方法

1. **逐条比对**：以 T000-1 第 1 章控制项解读为基准，逐条对照 T000-1 第 2 章组件 / 模块现状盘点，识别设计态与实现态的差距。
2. **三态评定**：
   - **已满足**：控制项核心要求已由对应模块落地，代码与配置已实现，有证据支撑。
   - **部分满足**：控制项核心要求部分落地，存在 Mock 未清零、配置未切换、能力未实现、依赖外部环境方等差距，需整改。
   - **未满足**：控制项核心要求未落地，或落地能力存在重大缺陷无法满足等保要求。
   - **不适用**：控制项由部署环境方（机房 / 云厂商）负责，平台不直接落地，说明理由。
3. **风险等级评定**：
   - **高**：控制项核心要求未实现或存在重大缺陷，可能导致数据泄露、系统被入侵、权限失控等严重安全后果，直接影响等保测评通过。
   - **中**：控制项部分要求未实现，存在一定安全风险，可能被利用但影响范围有限，或仅在特定环境（如信创）存在差距。
   - **低**：控制项增强要求未实现，风险较小，或依赖外部环境方配合，平台侧已提供辅助支撑能力。
4. **整改建议**：对每个"未满足"和"部分满足"项，给出具体整改措施、责任模块、预估工时、依赖关系。
5. **优先级排序**：按风险等级（高 > 中 > 低）+ 整改依赖关系排序，形成整改路线图。

### 1.4 评估基准

- **设计态基准**：T000-1 第 3 章控制项与模块映射矩阵（42 控制项逐条映射，33 满足 / 5 部分满足 / 5 不适用）。
- **实现态基准**：T000-1 第 2 章组件盘点（22 组件 Mock 清零状态：6 已清零 / 7 未清零 / 9 部分清零）+ 模块盘点（49 模块安全配置现状）。
- **Mock 清零基准**：`design/v2.0/Phase0/T000a_Mock清零状态核查报告.md`。

### 1.5 术语定义

| 术语 | 定义 |
| --- | --- |
| 设计态 | 平台架构设计文档中描述的安全能力，是否覆盖控制项要求 |
| 实现态 | 平台当前代码与配置的实际落地情况，含 Mock 状态、配置切换状态 |
| Mock 未清零 | 组件代码中 Mock 实现未替换为真实实现，返回 SIMULATED 或占位结果 |
| 满足率 | 已满足控制项数 / 适用控制项总数（排除"不适用"项） |
| 整改工时 | 完成单项整改所需的人天工作量估算，含开发 + 测试 + 验证 |
