# L0.8 容器存储（CSI + JuiceFS）· 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L0 云原生底座层
> 套餐：基础版（三档全含）
> 对标：Kubernetes CSI 规范 / JuiceFS（POSIX·HDFS 兼容）/ OpenEBS Local PV
> 关联：L2.1 统一存储（对象存储底座由本层提供 CSI 接口）；L0.6 SKE 控制面（NVMe + IO_uring 加速）；L0.11 封装层（PVC 由封装层翻译）

## 1. 定位与价值

容器存储是云原生底座的**存储供给层**：以 CSI 标准对接四环境后端（信创国产/本地 Ceph/云 S3/私有云厂商），以 JuiceFS 提供 POSIX/HDFS 兼容语义，以 SKE NVMe + IO_uring 加速本地热路径，向上为 L2.1 统一存储、L0.11 封装层供给 PV/PVC。

客户价值：
- "湖仓集一体"上层零感知——换存储后端只换 StorageClass，作业与 SQL 不改。
- "国产/云可迁移"——同一套 CSI 抽象，信创与公有云同构部署。
- "热数据快"——etcd/缓存/元数据走 NVMe 直通，IO_uring 降低系统调用开销。

平台价值：
- CSI 驱动屏蔽后端差异，四环境交付同一份 Helm Chart。
- JuiceFS 元数据引擎可换（Redis/TiKV/对象存储），按规模分级选型。
- 多租户按 StorageClass + 配额 + 加密密钥隔离，安全收敛到本层。

## 2. 总体架构

```text
┌──────── 上层消费（经封装层 L0.11 翻译 PVC） ────────┐
│  L2.1 统一存储(对象)   Flink/Spark(POSIX)   etcd/缓存(块)  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── CSI 接口层（K8s CSI 规范） ────────┐
│  ControllerPublish / NodePublish / Expand / Snapshot    │
└──────────────────────┬──────────────────────────┘
        ┌──────────────┼──────────────┬──────────────┐
        ▼              ▼              ▼              ▼
   JuiceFS CSI      块存储 CSI      Local PV CSI    对象 CSI(S3Proxy)
   (POSIX/HDFS)     (RBD/Ceph/国产)  (NVMe 直通)     (对接 L2.1)
        │              │              │
        ▼              ▼              ▼
   元数据引擎        国产/本地块      SKE NVMe+IO_uring
   Redis/TiKV/Obj    存储 LUN         (etcd 专属盘/缓存盘)
```

## 3. CSI 驱动抽象

统一 CSI 接口（K8s 标准，客户不直接操作）：
```
interface CSIDriver {
  CreateVolume(name, capacity, params); DeleteVolume(id);
  ControllerPublish(vol, node); NodePublish(vol, target, mode);
  NodeExpand(id, capacity); CreateSnapshot(src);
}
```
四环境 StorageClass 驱动对照表：

| 环境 | 块存储驱动 | 文件/POSIX 驱动 | 对象驱动 | 说明 |
| --- | --- | --- | --- | --- |
| 信创 | 国产 CSI（如华为/海光存储） | JuiceFS + 国产元数据 | 国产对象 CSI | 国产 OS + 国产存储优先 |
| 本地数据中心 | Ceph RBD CSI | JuiceFS + Redis/TiKV | Ceph RGW CSI | 裸金属/虚机自建 |
| 公有云 VM | 云厂商块 CSI（客户提供） | JuiceFS + 云 KV | S3/OBS/OSS CSI | **客户提供密钥，不绑托管服务** |
| 私有云 | 厂商块 CSI / Ceph | JuiceFS + 厂商 KV | 厂商对象 CSI | 客户私有云 VM |

> 关键约束：云环境只用"裸 CSI 后端"，绝不启用云托管文件/块服务——保持可迁移、不锁云。

## 4. JuiceFS 集成

JuiceFS 提供 POSIX 与 HDFS 兼容语义，承载 Flink/Spark 的文件路径访问（与 L2.1 对象存储互补）。

- **挂载模式**：以 CSI Driver 形式部署，每个 PV 对应一个 JuiceFS 子路径（`/jfs/{tenant}/{workspace}`）。
- **元数据引擎选型**：

| 规模 | 引擎 | 说明 |
| --- | --- | --- |
| 单租户/小规模 | Redis（主从） | 低延迟，单点风险可控 |
| 多租户/中规模 | TiKV | 分布式 KV，强一致 |
| 大规模/简化运维 | 对象存储元数据 | JuiceFS 1.0+，省独立组件 |

- **缓存层**：本地 NVMe 作数据缓存（readback/writeback 可配），命中率优先热数据；元数据全内存缓存。
- **HDFS 兼容**：`hadoop fs` 与 Spark/Flink 直接挂 `jfs://`，无需改作业代码。
- **POSIX 语义**：支持随机读写、硬链接、权限位，满足 Doris BE/训练 checkpoint 落盘需求。
- **配额与回收**：JuiceFS `--quota` 按 PV 设容量上限；PVC 删除触发 `jfs gc` 回收孤儿数据。

## 5. Local PV + SKE 加速

SKE 发行版在节点侧提供 NVMe 直通与 IO_uring 加速，专用于热路径：

- **etcd 专属盘**：Local PV 绑定节点 NVMe，IO_uring 队列深度提升 etcd fsync 吞吐。
- **缓存盘**：JuiceFS/Doris BE/Spark shuffle 的本地缓存走 NVMe Local PV，避免与数据盘争抢。
- **调度约束**：Local PV 绑定节点，由 SKE 节点池（NodePool）标签 `ske.io/nvme=true` 调度，封装层透明选择。
- **故障域**：单节点 NVMe 故障只影响该节点缓存/etcd 副本，由 Raft/缓存重建恢复。
- **观测**：SKE 节点 exporter 暴露 NVMe 智能监控（温度/磨损/延迟），异常提前换盘。

## 6. 多租户存储隔离

按租户三重隔离，安全收敛到本层：

- **StorageClass 隔离**：每租户独立 StorageClass（`sc-{tenant}-jfs` / `sc-{tenant}-block`），后端桶/卷前缀按租户划分。
- **配额**：按租户 PVC 总量 + JuiceFS 容量上限，受封装层 ResourceQuota 约束；超限拒绝新 PVC。
- **加密密钥**：每租户独立 KMS 密钥（信创用国产 SM4，云用云 KMS，本地用 Vault），CSI 加密在 NodePublish 阶段注入。
- **NetworkPolicy**：CSI 挂载路径与元数据引擎访问按租户命名空间隔离，跨租户不可见。
- **快照隔离**：CSI Snapshot 按租户命名空间归属，跨租户不可恢复；快照导出走租户专属桶。

## 7. 接口契约（经封装层）

客户不直接见 CSI/PV/PVC，封装层 L0.11 翻译为"存储用量/挂载点"：
```
POST /api/storage/v1/volumes          { tenant, workspace, kind, size } → 创建卷
GET  /api/storage/v1/volumes/{id}/usage → { used, quota, iops }        // 用量
POST /api/storage/v1/volumes/{id}/expand { newSize }                   // 扩容
POST /api/storage/v1/snapshots        { volumeId } → 快照
```
> CSI/PV/PVC 是平台内部对象，客户视角只见"挂载到工作空间的数据盘 + 用量配额"。

## 8. 多环境适配

- **信创**：国产存储 CSI 优先，JuiceFS 元数据走国产 Redis/TiKV，加密用 SM4，能力探测缺失项降级告警。
- **本地数据中心**：Ceph RBD + RGW + JuiceFS(Redis)，自建裸金属/虚机，全开源栈。
- **公有云 VM**：云厂商块/对象 CSI（客户提供密钥），JuiceFS 元数据走云 KV，**不绑云托管 K8s/服务**。
- **私有云**：厂商存储 CSI 或 Ceph，JuiceFS 元数据走厂商 KV，按客户私有云环境定制 Helm values。
- **一致性保证**：同一套 CSI 接口 + JuiceFS 语义，Profile 切换即换后端，上层作业与 SQL 不改。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| JuiceFS 元数据引擎单点 | 文件系统不可用 | Redis 主从/TiKV 三副本；元数据引擎独立故障域 |
| Local PV 绑节点致迁移难 | 节点故障缓存丢失 | 仅作缓存/etcd，数据持久层在对象/块存储；故障重建 |
| 国产 CSI 兼容性 | 功能缺失/性能差 | 驱动层能力探测(preflight)，缺失能力降级或告警 |
| 多租户密钥泄漏 | 跨租户读数据 | 每租户独立 KMS 密钥，NodePublish 内存注入，不落盘 |
| 云环境误用托管服务 | 锁云、不可迁移 | 架构红线：只用裸 CSI 后端，CI 校验 Helm 不含托管 CR |

## 10. 与 UI 的对应

控制台 v0.3「工作空间」存储用量卡片、数据开发挂载点选择、运维「存储池」健康视图均基于本层 CSI/JuiceFS 状态聚合。客户视角只见"存储用量 486 TB · 挂载点 /data"，不暴露 PV/CSI/StorageClass 细节。
