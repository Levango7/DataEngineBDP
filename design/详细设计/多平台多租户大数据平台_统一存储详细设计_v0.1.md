# L2.1 统一存储（湖仓集一体存储底座）· 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L2 大数据引擎层
> 适用套餐：基础版、标准版、旗舰版（全档含，对齐 §11.5.1 套餐矩阵）
> 对标：Apache Iceberg（开放表格式）/ 星环 ArgoDB 湖仓集一体 / Delta Lake
> 关联：L0.11 封装层（配额/隔离）；L2.7 统一 SQL 网关（经 catalog 读写）；L3.5 资产目录（表即资产）

## 1. 定位与价值

统一存储是湖仓集一体的**唯一存储底座**：以"对象存储 + Iceberg 表格式"承载湖（原始）、仓（主题）、集（实时在线）三级数据，计算引擎插拔、流批一体、数据不冗余拷贝。

客户价值：
- "一份数据，多引擎共用"——Spark 写、Trino 查、Doris 在线服务，无需搬运。
- "实时可用"——流数据经 Flink CDC 实时入湖，Doris 物化提供在线查询。
- "多环境同构"——换存储后端不影响上层 SQL 与作业。

平台价值：
- 存储后端经 **StorageDriver 抽象**，四环境（信创/本地/云VM/私有云）零改动切换。
- 存储配额/隔离收敛到封装层，客户只见"存储用量"与"湖仓集一体"。

## 2. 总体架构

```text
┌──────── 计算引擎（读写，均经 catalog） ────────┐
│  Spark(批)   Flink(流/CDC)   Trino(交互)   Doris(在线/物化)  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── 表格式层（Apache Iceberg） ────────┐
│  ACID · Schema/Partition Evolution · Time Travel · 隐藏分区  │
│  湖(原始 Iceberg) → 仓(主题 Iceberg/Doris物化) → 集(在线表)  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── 存储抽象层（StorageDriver，屏蔽后端差异） ────────┐
│  put / get / list / multipart / presigned   统一对象接口    │
└──────────────────────┬──────────────────────────┘
        ┌──────────────┼──────────────┬──────────────┐
        ▼              ▼              ▼              ▼
  信创对象存储      Ceph RGW      客户云对象存储      私有云对象存储
  (国产/MinIO)      /MinIO        (S3/OBS/OSS,        (厂商/MinIO)
                    (本地)         客户提供密钥)
```

## 3. 存储抽象层（StorageDriver）

统一对象接口（内部，客户不直接用）：
```
interface StorageDriver {
  putObject(bucket, key, stream); getObject(bucket, key);
  listObjects(bucket, prefix); multipartUpload(...); presignedUrl(...);
  createBucket(bucket, quota); setQuota(bucket, bytes);
}
```
四环境驱动实现（运行时按 Profile 加载）：

| 环境 | 存储后端 | 驱动 | 说明 |
| --- | --- | --- | --- |
| 信创 | 国产对象存储 / 信创 MinIO | XCObjectDriver | 国产 OS + 国产存储优先 |
| 本地数据中心 | Ceph RGW / MinIO | CephDriver | 裸金属/虚机自建 |
| 公有云 VM | 客户自购云对象存储（S3/OBS/OSS） | S3Driver | **客户提供密钥，不绑云托管 K8s/服务** |
| 私有云 | 厂商对象存储 / MinIO | PrivateDriver | 客户私有云 VM |

> 关键约束：云环境只当"裸对象存储"，绝不启用云原生数据库/消息等托管服务——保持可迁移、不锁云。

## 4. 湖仓集三级

- **湖（原始层）**：Iceberg on 对象存储，ODS 原始贴源，Schema/分区演进友好。
- **仓（主题层）**：DWD/DWS 主题表，Iceberg 或 Doris 物化；重查询走 Doris 物化视图加速。
- **集（实时在线层）**：Doris 在线表，Flink CDC 实时入湖/入仓，支撑毫秒级在线查询与服务。

## 5. 接口契约（内部 / 经网关）

```
POST /api/lake/v1/warehouses              { name, storageProfile } → 建湖仓
POST /api/lake/v1/databases               { warehouse, db }
POST /api/lake/v1/tables                  { db, table, schema, format:iceberg }
GET  /api/lake/v1/tables/{t}/snapshots    → [{id, timestamp, ops}]   // 时间旅行
POST /api/lake/v1/tables/{t}/compact      → 触发小文件合并(compaction)
```
> 数据读写本身经 L2.7 统一 SQL（SELECT/INSERT）或 Flink 作业，不直接暴露对象接口给客户。

## 6. 关键流程

1. **建库表**：封装层按 workspace/project 创建桶前缀 + Iceberg 库表。
2. **批写**：Spark 作业写 Iceberg（封装层翻译为 SparkApplication CR）。
3. **流写**：Flink CDC 实时捕获 → 写 Iceberg（湖）→ 物化到 Doris（集）。
4. **查询**：统一 SQL 网关路由 Trino/Doris 读 Iceberg，客户只见结果。
5. ** compaction**：定时合并小文件，保证读取性能与对象存储成本。

## 7. 与封装层（L0.11）的关系

- 存储配额 = 对象存储桶配额 / PVC 上限，受工作空间 ResourceQuota 约束。
- 桶前缀按 `workspace/project` 隔离，跨租户不可见；NetworkPolicy 加固。
- 客户视角只显示"存储用量 / 湖仓集一体"，不暴露 bucket/key/对象接口。

## 8. 多环境一致性

- Iceberg 表格式、catalog、SQL 四环境完全一致；差异只在 StorageDriver 后端。
- 同一套建表/读写/compaction 流程，Profile 切换即换存储，作业与查询不改。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 小文件膨胀 | 读取慢、对象存储成本高 | 定时 compaction + Spark 写合并参数调优 |
| 对象存储最终一致性 | 读旧数据 | Iceberg manifest 提供快照一致性；读走 catalog 元数据 |
| 跨环境数据迁移 | 交付复杂 | StorageDriver 提供桶间复制工具；按 workspace 粒度迁移 |
| 信创对象存储兼容性 | 功能缺失 | 驱动层做能力探测(preflight)，缺失能力降级或告警 |

## 10. 与 UI 的对应

控制台 v0.3「数据集成」页（MySQL→Iceberg、Kafka→Doris 同步任务）、工作台"存储用量 486 TB · 湖仓集一体"、数据开发（写 Iceberg / 物化 Doris）均基于此底座。本文件是其存储侧契约依据。
