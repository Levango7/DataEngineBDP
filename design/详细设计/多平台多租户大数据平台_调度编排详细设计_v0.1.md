﻿# L4.2 调度编排（DolphinScheduler）· 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L4 数据开发与分析层
> 套餐：标准版起含（§11.5.1），基础版不含
> 对标：Apache DolphinScheduler（国产开源，Java，信创适配好）/ Airflow / Azkaban
> 关联：L2.2 Spark（调度 Spark 作业）；L2.3 Flink（调度 Flink 作业）；L4.1 数据集成（调度同步任务）；L4.3 数据开发 IDE（IDE 提交作业到调度）；L0.11 封装层（租户/配额/隔离）；L3.3 数据质量（DAG 中"SQL 质量校验"节点调 `/api/dq/v1/rules/{id}/run`）；L3.5 资产目录（SLA 违约记录回写）

## 1. 定位与价值

调度编排是数据开发的**时间中枢**：以可视化 DAG 描述任务依赖与触发策略，由 Master 调度、Worker 执行，统一编排 Spark/Flink/同步/SQL/Shell 等异构作业，失败重试、超时告警、补数回溯一站式闭环。

客户价值：
- "拖拽画 DAG"——业务人员无需写代码即可编排数仓 ETL 全流程。
- "一次定义，多环境跑"——同一工作流在信创/本地/云/私有云零改动调度。
- "看得见的运维"——任务状态、运行历史、SLA 达成率可视化，失败即告警。

平台价值：
- 选型 DolphinScheduler，Java 栈与 Spark/Flink 同 JVM 生态，信创 JDK/麒麟/统信适配好。
- on K8s 部署，Master/Worker/Alert/API 分离，资源按租户队列隔离，与封装层配额打通。
- 经封装层 REST 暴露统一 API，IDE/控制台/外部系统统一接入，客户不直连 DS 原生接口。

## 2. 总体架构

```text
┌──────── 接入面（经封装层 REST） ────────┐
│  L4.3 数据开发 IDE   控制台 v0.3   外部 CI/CD  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── DolphinScheduler on K8s ────────┐
│  API-Server ──→ Master(调度) ──→ Worker-Group(执行)  │
│       │              │                  │            │
│   项目/工作流     DAG 解析/触发      任务执行器       │
│   /调度/补数      失败重试/依赖      (SQL/Shell/Py   │
│                  等待/补数           /Spark/Flink    │
│                                     /HTTP/Dependent) │
│       │              │                  │            │
│   PostgreSQL     ZooKeeper         结果回写+告警     │
│   (元数据)       (分布式锁/选主)   → Alert-Server   │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── 被调度作业 ────────┐
│  L2.2 SparkApplication   L2.3 FlinkApplication   L4.1 同步任务   │
└──────────────────────────────────────────────────┘
```

> K8s 部署：API/Master/Worker/Alert 各自 Deployment/StatefulSet，Worker 按租户分队列（worker-group=tenant-x），Pod 级 ResourceQuota+LimitRange 约束。
> ZooKeeper 由 SKE 内置（`zookeeper.replicas=3`），用于 Master HA 选主与分布式锁，配置见 `dolphinscheduler-values.yaml` 的 `zookeeper` 块。

## 3. DAG 模型与任务类型

工作流 = DAG（有向无环图），节点 = 任务实例，边 = 依赖关系。DAG 示例：

```text
[MySQL→Iceberg 同步] ──→ [Spark 清洗] ──┬──→ [Flink 实时物化] ──→ [Doris 在线表]
                                          └──→ [SQL 质量校验] ──→ [Shell 通知]
```

> DAG 中"SQL 质量校验"节点调用 L3.3 数据质量 API `POST /api/dq/v1/rules/{id}/run`，规则统一在 L3.3 维护，避免各租户自写校验 SQL 导致规则不可复用；校验失败按规则 `onFail` 配置告警或阻断下游。

| 任务类型 | 用途 | 执行方式 | 关联模块 |
| --- | --- | --- | --- |
| SQL | Hive/SparkSQL/Trino 查询与建表 | 经 L2.7 统一 SQL 网关 | L2.7 |
| SQL 质量校验 | 数据质量规则校验 | 调 L3.3 `POST /api/dq/v1/rules/{id}/run` | L3.3 |
| Shell | 通用脚本、运维动作 | Worker Pod 内 bash | — |
| Python | 数据处理、UDF 调用 | Worker Pod 内 python | — |
| Spark | 批 ETL、Iceberg 读写 | 提交 SparkApplication CR | L2.2 |
| Flink | 流/CDC、实时物化 | 提交 FlinkApplication CR | L2.3 |
| HTTP | 调外部 API、触发下游系统 | Worker 内 HTTP 客户端 | — |
| 依赖（Dependent） | 跨工作流依赖、天级等待 | 查 DS 元数据 | — |

> 任务参数统一 JSON 描述，封装层翻译为对应 CR/SQL/脚本，Worker 仅执行不感知环境差异。

## 4. 接口契约（经封装层 REST）

```
POST /api/sched/v1/projects                  { tenant, name } → 建项目
POST /api/sched/v1/workflows                 { project, dagJson } → 建工作流
POST /api/sched/v1/workflows/{id}/schedule   { cron, start, end } → 上线调度
POST /api/sched/v1/workflows/{id}/run        { params } → 手动触发
POST /api/sched/v1/workflows/{id}/backfill   { start, end } → 补数
GET  /api/sched/v1/tasks/{id}/status         → { state, startTime, endTime, log }
GET  /api/sched/v1/workflows/{id}/instances  → [{runId, state, duration}]   // 运行历史
```

> 客户/IDE 经封装层调用，封装层注入租户与权限校验，再转发 DolphinScheduler 原生 API；不直暴露 DS 端口。

## 5. 关键流程

```text
定义工作流(IDE/控制台) ──→ 封装层校验租户/配额 ──→ DS API 持久化 DAG
                                                          │
        ┌─────────────────────────────────────────────────┘
        ▼
[Cron 触发 / 手动 run / 补数] ──→ Master 解析 DAG ──→ 按依赖拓扑排序
        │                                              │
        │                                              ▼
        │                              [就绪任务] → 投递到 worker-group=tenant-x
        │                                              │
        │                                              ▼
        │                              Worker 执行(SQL/Spark/Flink/质量校验/...) ──→ 状态回写 PG
        │                                              │
        │                              ┌───────────────┴───────────────┐
        │                              ▼                               ▼
        │                          成功 → 触发下游               失败 → 重试(≤N次)
        │                                                              │
        │                                              超时/重试耗尽 → Alert-Server → 告警
        ▼
全部完成 → 工作流实例 SUCCESS；SLA 监控记录达成/违约
```

1. **定义**：IDE 拖拽生成 DAG JSON，经封装层落库。
2. **调度触发**：Master 按 Cron/手动/补数生成工作流实例，解析 DAG 拓扑。
3. **Worker 执行**：任务按租户队列投递，Worker 执行并实时回写状态与日志；"SQL 质量校验"节点调 L3.3 API。
4. **状态回写**：成功触发下游，失败按策略重试，超时/重试耗尽触发告警。
5. **告警**：Alert-Server 经封装层通知（邮件/钉钉/企微/飞书/webhook），SLA 监控独立记录。

## 6. 多租户隔离

- **项目隔离**：DS Project 绑定租户，封装层按 tenant 过滤，跨租户不可见。
- **Worker 队列按租户**：每租户独立 worker-group（K8s 按 label 调度），资源不抢占。
- **资源配额**：Worker Pod 受 LimitRange 约束，租户总并发任务数受 ResourceQuota 限制。
- **资源文件隔离**：脚本/JAR/资源按 `tenant/project` 路径存对象存储，权限校验在封装层。
- **数据库隔离**：DS 元数据 PG 按 schema/行级租户标识隔离，封装层注入过滤条件。

## 7. 告警与监控

- **失败重试**：任务级配置 `retryTimes + retryInterval`，指数退避，重试耗尽告警。
- **超时告警**：任务级 `timeout`，超时主动 kill Pod 并告警，避免僵尸任务占资源。
- **SLA 监控**：工作流级 SLA 时长，每日达成率统计，违约即告警并记录资产目录（L3.5）。
- **告警通道**：邮件/钉钉/企微/飞书/webhook，经封装层统一配置，租户级订阅；飞书通道对齐 `dolphinscheduler-values.yaml` 中 `channels` 列表（含 `feishu`）。
- **运行监控**：Prometheus 采集 DS Master/Worker 指标（任务量/延迟/队列深度），Grafana 看板。

## 8. 多环境适配

| 环境 | DS 部署 | JDK/OS | 被调度作业 | 说明 |
| --- | --- | --- | --- | --- |
| 信创 | SKE K8s | 国产 JDK/麒麟/统信 | Spark/Flink on 信创 K8s | 优先信创镜像，验证国产兼容 |
| 本地数据中心 | SKE K8s | OpenJDK/CentOS | Spark/Flink on 同 K8s | 裸金属/虚机自建 |
| 公有云 VM | SKE K8s | OpenJDK/云 VM OS | Spark/Flink on 同 K8s | **客户自购 VM，不绑云托管 K8s/服务** |
| 私有云 | SKE K8s | OpenJDK/客户 OS | Spark/Flink on 同 K8s | 客户私有云 VM |

> 关键约束：DS 与被调度作业同 K8s 集群，跨环境仅镜像/存储 Profile 不同，DAG 定义与调度 API 完全一致——保持可迁移、不锁云。

## 9. 部署配置

部署参数落地于 `design/deploy/values/dolphinscheduler-values.yaml`，由封装层 Helm Operator 渲染。关键配置块：

```yaml
# dolphinscheduler-values.yaml（节选）
dolphinscheduler:
  image: sq-dolphinscheduler:3.2-0.1.0
  version: "3.2.2"
  master:
    replicas: 2           # HA
  worker:
    replicas: 2
  alert:
    channels: ["email", "dingtalk", "webhook", "wechat", "feishu"]   # 含飞书
  zookeeper:              # ZooKeeper 由 SKE 内置，用于 Master HA 选主与分布式锁
    replicas: 3
    host: "zk-headless:2181"
    chroot: "/dolphinscheduler"
  database:
    type: "postgresql"
  tierProfiles:
    base:      { enabled: false }   # 基础版不含 L4.2
    standard:  { enabled: true,  master.replicas: 2, worker.replicas: 2, resources: "medium" }
    flagship:  { enabled: true,  master.replicas: 3, worker.replicas: 4, resources: "large" }
```

> 资源配额说明：`tierProfiles.*.resources` 中 quota 为单组件上限，平台总额度见 §11.5.2，由封装层 ResourceQuota 在租户级聚合约束（非所有组件同时满载，故单组件配额之和可略超平台总额度）。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Master 单点/调度抖动 | 触发延迟、任务堆积 | 多 Master + ZooKeeper 选主；队列背压与水平扩 Worker |
| Worker 资源抢占 | 租户间互相影响 | 按租户 worker-group + K8s ResourceQuota/LimitRange 硬隔离 |
| 信创 JDK 兼容性 | DS/依赖库异常 | 信创镜像预验证；缺失能力降级或告警；保留 OpenJDK 兜底 |
| 大量补数回溯 | 集中触发压垮集群 | 补数并发限流 + 分批投递；优先级队列 |
| DAG 死锁/环依赖 | 工作流无法执行 | DS DAG 校验拒绝环路；封装层提交前预检 |
| 跨工作流依赖复杂 | 运维难定位 | Dependent 任务显式声明；依赖关系图可视化 |
