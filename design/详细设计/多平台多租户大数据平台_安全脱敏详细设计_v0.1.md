﻿# L3.7 安全脱敏 · 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L3 数据治理层
> 套餐：基础版起含（§11.5.1）
> 对标：阿里 DataWorks 数据保护伞（分类分级 / 脱敏 / 访问监控 / 审计）/ 华为 FusionInsight 表·列级加密
> 关联：L3.5 资产目录（资产的 `sensitiveLevel`）；L2.7 统一 SQL 网关（脱敏下推）；L0.11 封装层（RBAC / 引擎授权落地）；L3.2 数据标准（码值/类型）
> 技术栈：Java 实现（与 L3 数据治理层同栈，对齐 §5.5"Java 生态优先、减少语言栈数量"决策）

## 1. 定位与价值

安全脱敏提供**字段级脱敏 + 权限申请审批流 + 审计**，满足密评（商用密码应用安全性评估）与等保合规，是平台"金融级数据安全"卖点的落地层。

客户价值：
- "敏感数据自动识别"——无需人工逐字段定级。
- "查询即脱敏"——授权前自动掩码/哈希，授权后按策略可见，客户不写脱敏代码。
- "权限可追溯"——谁申请、谁批准、谁访问全程留痕。

平台价值：
- 脱敏策略**下推到引擎**（L2.7），应用层无法绕过，强制生效。
- 权限最终收敛到 L0.11 封装层 K8s RBAC / 引擎授权，客户无 K8s 权限。
- 国密 SM2/SM3/SM4 可插拔，按环境 Profile 启用，不污染主流程。

## 2. 总体架构


## 3. 四大能力

### 3.1 分类分级（Classification）
- 自动识别：基于内置敏感模板（手机号/身份证/银行卡/姓名/地址…）+ 自学习模型，扫描资产字段。
- 定级：`none | restricted | PII`，回写 L3.5 资产 `sensitiveLevel` 与 L3.1 业务元数据。
- 自定义：支持客户自定义敏感类型与识别规则。

### 3.2 脱敏策略（Masking）
- 策略 = 字段 + 资产 + 算法 + 作用域（查询时 / 导出时 / 存储时）。
- 算法库：**掩码**（138****8000）、**哈希**（SM3/SHA256）、**仅授权可见**、**假名化**（tokenization）。
- 生效方式：策略下推到引擎，查询经 L2.7 时由网关注入脱敏函数，应用层不可绕过。

### 3.3 权限申请与审批（Access & Approval）
- 资产权限申请 → 审批流（L3.7 审批引擎）→ 通过后封装层授予 RBAC / 引擎授权 → 客户可查。
- 审批支持批准/驳回/委托；与工作流通知联动。

### 3.4 审计（Audit）
- 记录敏感数据访问、导出、脱敏命中、权限变更；多维度关联分析识别异常（如批量导出 PII）。
- 审计日志不可篡改，支撑密评/等保核查。

## 4. 接口契约（REST）

### 4.1 分类分级
```
POST /api/sec/v1/classify              { assetId }            → 自动识别敏感字段
GET  /api/sec/v1/assets/{id}/sensitivity → { fields:[{field,level,rule}] }
POST /api/sec/v1/assets/{id}/sensitivity { field, level }      // 人工定级
```

### 4.2 脱敏策略
```
POST /api/sec/v1/mask-policies         { asset, field, strategy(掩码|哈希|仅授权可见|假名), algorithm(SM3|SHA256|AES), scope, requiresApproval }
GET  /api/sec/v1/mask-policies?asset=  → 策略列表
DELETE /api/sec/v1/mask-policies/{id}
```

### 4.3 权限申请与审批
```
POST /api/sec/v1/permission-requests   { assetId, action(read|write), reason } → 进入审批流
POST /api/sec/v1/permission-requests/{id}/approve
POST /api/sec/v1/permission-requests/{id}/reject { reason }
GET  /api/sec/v1/permission-requests?status=pending                    → 待办
```

### 4.4 审计
```
GET /api/sec/v1/audit-logs?assetId=&user=&from=&to=  → 审计记录
GET  /api/sec/v1/risks                                      → 风险识别结果
```

## 5. 关键流程

1. **敏感识别**：扫描资产 → 自动定级 → 建议脱敏策略。
2. **策略生效**：提交脱敏策略（需审批则走审批流）→ 生效后 L2.7 查询自动下推脱敏函数。
3. **权限申请**：点"申请读权限" → 审批 → 封装层授予 RBAC → 客户可查未脱敏原文（按策略）。
4. **审计**：每次敏感数据访问/导出写审计日志；异常行为（如超阈值导出）告警。

## 6. 与封装层（L0.11）/ 统一 SQL（L2.7）的关系

- 脱敏策略经 L2.7 在查询计划阶段注入脱敏函数（如 `mask(phone)` / `sm3(id_card)`），**强制在引擎侧执行**，应用层无法绕过。
- 权限最终落到 K8s RBAC + 引擎级授权（如 Doris 列权限 / Iceberg 行过滤），由封装层统一授予。
- 国密 SM3 在信创环境按 Profile 启用；非信创环境降级为标准算法（SHA256/AES），主流程不变。

## 7. 多环境一致性

- 分类分级逻辑、脱敏策略模型、审批流四环境完全一致。
- 加密算法按 Profile 选择（国密 / 标准），差异收敛到算法驱动，业务无感。
- 审计留痕与合规口径四环境统一，便于跨环境交付与核查。

## 8. 部署配置

部署参数落地于 `design/deploy/values/security-values.yaml`，由封装层 Helm Operator 渲染。关键配置块：

```yaml
# security-values.yaml
security:
  image: sq-security:0.1.0       # Java 实现
  replicas: 2
  resources:
    requests: { cpu: "0.5", memory: "1Gi" }
    limits:   { cpu: "1",   memory: "2Gi" }
  approval:
    engine: "java"               # 审批流引擎（Java）
    timeout: "24h"
  crypto:
    profile: "default"           # 信创 Profile 启国密
    algorithms: ["SM2", "SM3", "SM4", "SHA256", "AES"]
  audit:
    storage: { type: "postgresql" }
    immutable: true              # 审计日志不可篡改
  tierProfiles:
    base:      { replicas: 1, resources: "small" }
    standard:  { replicas: 2, resources: "medium" }
    flagship:  { replicas: 3, resources: "large" }
```

> 资源配额说明：`resources` 中 quota 为单组件上限，平台总额度见 §11.5.2，由封装层 ResourceQuota 在租户级聚合约束（非所有组件同时满载，故单组件配额之和可略超平台总额度）。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 脱敏被应用层绕过 | 敏感泄露 | 脱敏强制在引擎侧下推，不在应用层做 |
| 权限蔓延 | 越权访问 | 审批流 + 定期回收 + 审计 |
| 国密兼容性 | 信创不达标 | Profile 探测 + 算法驱动降级/告警 |
| 审计遗漏 | 合规事故 | 全量访问/导出留痕 + 异常识别规则 |
