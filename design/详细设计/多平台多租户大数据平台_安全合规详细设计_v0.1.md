# X2 安全合规 · 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · X 横切能力层
> 对标：等保三级（GB/T 22239）/ 密评（GM/T 0054）/ 数据安全法 / 个人信息保护法
> 关联：X1 身份权限（认证审计）；L3.7 数据安全（分级脱敏）；L0.11 封装层（操作审计）；L5.2 运营后台（合规看板）
> 适用版本：基础版✅ / 标准版✅ / 旗舰版✅（全版本开放，对照 §11.5 套餐模块矩阵）

## 1. 定位与价值

安全合规是平台的**合规底座**：以"等保三级 + 密评 + 数据合规"三线并进，统一落地边界防护、访问控制、国密加密、全链路审计留痕，使平台在信创环境一次性通过等保三级测评与商用密码应用安全性评估，在非信创环境按客户要求按需启用。

客户价值：
- "开箱合规"——信创交付即过等保三级 + 密评，客户无需自建安全体系。
- "数据留痕"——操作/数据/系统三类日志全链路审计，180 天可追溯。
- "出境可控"——数据分级分类 + 出境白名单，满足数据安全法与个保法。

平台价值：
- 安全能力经 **SecurityFacade** 统一封装，四环境（信创/本地/云VM/私有云）按 Profile 启用。
- 合规证据自动归档，对接 L5.2 运营后台合规看板，测评材料一键导出。

## 2. 合规框架

```text
┌──────── 三线并进合规框架 ────────┐
│  等保三级(GB/T 22239)  密评(GM/T 0054)  数据合规(数安法/个保法)  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── SecurityFacade 统一封装 ────────┐
│  边界防护 · 访问控制 · 国密加密 · 审计留痕 · 入侵检测 · 恶意代码  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── 证据归档 → L5.2 合规看板 ────────┐
│  测评材料导出 · 密评报告生成 · 合规自检报告  │
```

| 合规线 | 标准 | 落地章节 | 强制环境 |
| --- | --- | --- | --- |
| 等保三级 | GB/T 22239-2019 | §3 | 信创必过，其余按需 |
| 密评 | GM/T 0054-2018 | §4 | 信创必过，其余按需 |
| 数据合规 | 数据安全法 / 个保法 | §5 | 全环境启用 |

## 3. 等保三级落地

| 等保要求 | 实现方式 | 关联模块 |
| --- | --- | --- |
| 边界防护 | K8s NetworkPolicy 租户隔离 + Ingress WAF + 出口白名单 | L0.11 封装层 |
| 访问控制 | RBAC + ABAC 双模型，最小权限，X1 提供 | X1 身份权限 |
| 安全审计 | 统一审计中心，三类日志 180 天，§6 详述 | X2 本模块 |
| 入侵检测 | HIDS Agent（信创国产）/ Falco 容器行为监控 | X2 本模块 |
| 恶意代码 | 镜像扫描（Trivy/国产替代）+ 签名准入 + 病毒墙 | L0.11 封装层 |
| 可信验证 | 镜像签名（cosign/国密替代）+ 准入控制 | L0.11 封装层 |

> 关键约束：所有安全组件经 Operator 部署，信创环境替换为国产等效组件（国产 HIDS、国产 WAF、国密签名），保持接口不变。

## 4. 密评落地（GM/T 0054）

| 密评项 | 实现方式 | 国密算法 |
| --- | --- | --- |
| 密码算法使用 | 数据加密/签名/哈希全用国密 | SM4(对称)/SM2(非对称)/SM3(摘要) |
| 密钥管理 | 统一 KMS，密钥分级分层，信创对接国产 KMS | SM2 主密钥 + SM4 数据密钥 |
| 密码协议 | 传输层 TLS 国密版本，管理通道 GMSSL | TLCP/GMSSL 替代 TLS1.2 |
| 随机数 | 国密硬件随机数发生器（信创）/ 安全 PRNG | 符合 GM/T 0005 |
| 密码产品 | 信创环境使用商用密码产品认证组件 | 模块化可替换 |

```
interface KmsFacade {
  genKey(spec: KeySpec); encrypt(keyId, plaintext); decrypt(keyId, ciphertext);
  sign(keyId, data); verify(keyId, data, sig); rotateKey(keyId);
}
```
> 信创环境 KMS 对接国产密码机（如卫士通/信安世纪），非信创可降级为软件国密实现（GmSSL/SwXia）。

## 5. 数据合规

- **分级分类**：数据按公开/内部/敏感/核心四级标注，L3.7 数据安全联动脱敏。
- **最小授权**：X1 RBAC + ABAC，敏感数据访问需二次审批 + 动态脱敏。
- **全链路留痕**：数据访问/导出/加工全记录，含主体/客体/时间/操作/结果。
- **出境管控**：核心/敏感数据默认禁止出境，白名单按租户配置，出境操作实时告警。
- **个人信息**：识别个人信息字段，加工前强制脱敏，导出需审批 + 留痕。

## 6. 审计日志（统一审计中心）

三类日志统一采集、统一存储、统一查询：

| 日志类型 | 来源 | 内容 | 保留 |
| --- | --- | --- | --- |
| 操作日志 | X1/L0.11 | 登录/配置/作业提交/管理操作 | 180 天 |
| 数据日志 | L3.7/L2 | 数据访问/导出/加工/脱敏 | 180 天 |
| 系统日志 | K8s/组件 | 系统事件/异常/安全告警 | 180 天 |

```text
审计源 → FluentBit(采集) → Kafka(缓冲) → 安全合规专用 ES/国产替代(存储) → 审计查询 API
                                                          ↓
                                                  WORM 一次写入不可改 · 180天保留
```
> 关键约束：审计日志写入 WORM（一次写入不可修改）存储，防篡改；信创环境使用国产日志存储替代 ES。

## 7. 接口契约（内部 / 经网关）

```
GET  /api/compliance/v1/audit/logs?from&to&type&actor  → 审计日志查询
POST /api/compliance/v1/audit/export                    → 导出审计报告(审批)
GET  /api/compliance/v1/report/level-protection         → 等保自检报告
GET  /api/compliance/v1/report/crypto-assessment        → 密评自检报告
POST /api/compliance/v1/data/classify                   → 数据分级标注
GET  /api/compliance/v1/data/classify/{assetId}         → 查询数据分级
POST /api/compliance/v1/data/export-check               → 出境合规校验
```
> 接口均经 X1 鉴权 + 审计留痕；导出类接口需二次审批，结果回写审计中心。

## 8. 多环境适配

| 环境 | 等保 | 密评 | 数据合规 | 安全组件 |
| --- | --- | --- | --- | --- |
| 信创 | 必过三级 | 必过密评 | 全启用 | 国产 HIDS/WAF/KMS/日志 |
| 本地数据中心 | 按客户要求 | 按客户要求 | 全启用 | 开源 HIDS/Falco/软件国密 |
| 公有云 VM | 按客户要求 | 按客户要求 | 全启用 | 复用客户云安全组件可选 |
| 私有云 | 按客户要求 | 按客户要求 | 全启用 | 开源/厂商组件按需 |

> 关键约束：信创环境强制启用全部安全能力且必须使用国产等效组件；非信创环境按客户合规要求按需启用，但数据合规（§5）与审计留痕（§6）全环境强制启用。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 等保测评标准更新 | 落地偏差 | SecurityFacade 抽象 + 合规项可配置，按新版标准更新检查清单 |
| 国密组件性能 | 加密吞吐低于国际算法 | 热点数据用 SM4 硬件加速；非敏感数据不强制加密 |
| 审计日志量巨大 | 存储成本高、查询慢 | Kafka 缓冲 + 分区存储 + 冷热分离，180 天后归档冷存 |
| 信创国产组件兼容性 | 功能缺失或行为差异 | 接口层做能力探测，缺失能力降级 + 告警，保持接口一致 |
| 数据出境判定复杂 | 误判漏判 | 分级标注 + 白名单 + 人工审批兜底，可疑操作实时告警 |
