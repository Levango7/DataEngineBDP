# 多平台多租户大数据平台 · 运营后台详细设计（L5 平台侧）（v0.1）

> 版本：v0.1 ｜ 日期：2026-08-01 ｜ 状态：详细设计稿
> 依赖：封装层 v0.1（租户模型 / 套餐→ResourceQuota 翻译）、安全脱敏 v0.1（审批流）、控制台信息架构 v0.1（运营后台页）、产品原型 v0.4（L5 多租户产品层）
> 定位：平台运营方视角的管理后台（对应控制台 v0.3「运营后台」页），与「客户视角控制台」隔离；是「好卖钱」的商业化闭环核心。
> 适用版本：标准版✅ / 旗舰版✅（基础版❌，对照 §11.5 套餐模块矩阵）

---

## 1. 定位与职责

运营后台服务于**平台方（我方运维 / 运营 / 销售）**，不直接暴露给租户客户。职责：

1. **租户全生命周期**：开户、套餐分配、配额调整、暂停 / 恢复 / 注销。
2. **套餐与 SLA**：档位定义（基础 / 标准 / 旗舰），映射到底层 ResourceQuota 与节点池租约。
3. **资源计量**：按租户 / 工作空间采集 CPU、内存、存储、作业数、查询次数。
4. **账单计费**：按套餐基线 + 计量溢出生成账单，支持对账与回溯。
5. **运营看板**：全局租户数、资源水位、营收、健康度。
6. **工单与审批**：接入 L3.7 权限 / 脱敏审批流，统一处理。

## 2. 与封装层及相邻模块的关系

| 运营动作 | 调用方 | 底层翻译（见封装层 v0.1） |
| --- | --- | --- |
| 开户 | 运营后台 | 建租户记录 → 平台方 Namespace 下挂租户标签 |
| 分配套餐 | 运营后台 | 套餐档位 → Workspace ResourceQuota + 节点池租约 |
| 计量采集 | 封装层 Sidecar / Prometheus | 按 `tenant` / `ws` 标签聚合 |
| 审批 | 运营后台 ← L3.7 | 权限 / 脱敏申请 → 运营审批 → 封装层 RBAC 落地 |
| 注销 | 运营后台 | 删租户下所有 Workspace → 级联回收 K8s 资源 |

**不绑云**：账单完全基于本平台计量，不依赖任何云厂商账单（呼应部署清单 v0.1 铁律）。

## 3. 接口契约

### 3.1 租户 `POST /api/v1/admin/tenants`
```json
{ "name":"acme", "displayName":"Acme 金融", "type":"external",
  "package":"standard", "contact":{"name":"","email":""} }
→ 200 { "tenantId":"t-acme", "status":"active", "quotaRef":"ws-default-quota" }
```

### 3.2 套餐 `GET /api/v1/admin/packages`
```json
[ { "id":"base",   "cpu":"8",  "mem":"32Gi",  "storage":"200Gi", "pricePerMonth":0 },
  { "id":"standard","cpu":"32", "mem":"128Gi", "storage":"1Ti",   "pricePerMonth":9800 },
  { "id":"flagship","cpu":"128","mem":"512Gi", "storage":"5Ti",   "pricePerMonth":39800 } ]
```

> **pricePerMonth 定价口径**：pricePerMonth 为 SaaS 月度订阅价（含套餐内 CPU/内存/存储基线额度，溢出另计），适用于 SaaS 部署模式。与 §11.5.4 私有化交付报价为两种独立定价模型：§11.5.4 私有化报价为「平台许可费（一次性 20 万/50 万/150 万）+ 年度服务费（4 万/10 万/30 万）」，适用于私有云/本地数据中心部署；本节 pricePerMonth 为 SaaS 月订阅价，对应 base/standard/flagship 三档（与 values tierProfiles 对齐，不用 basic）。两种模型按部署模式选择，不叠加。

### 3.3 计量 `GET /api/v1/admin/metering?tenant=t-acme&from=...&to=...`
```json
{ "cpuHours":120.5, "memGBHours":480, "storageGBDays":300, "jobs":42, "queries":310 }
```

### 3.4 账单 `GET /api/v1/admin/bills?tenant=t-acme&month=2026-08`
```json
{ "tenantId":"t-acme", "package":"standard", "base":9800,
  "overflow":{ "cpuHours":120.5, "cost":240 }, "total":10040, "status":"unpaid" }
```

### 3.5 运营看板 `GET /api/v1/admin/dashboard`
```json
{ "tenants":18, "active":16, "paused":2, "mrr":176200,
  "clusterCpuUsage":0.62, "clusterMemUsage":0.55, "health":"green" }
```

## 4. 关键流程

### 4.1 开户 → 套餐 → 计量 → 出账
```
运营后台开户(tenant=acme, package=standard)
  → 封装层: 租户记录 + 默认 Workspace(ws-default) + ResourceQuota(standard 档)
  → 客户在 ws-default 内建项目/提交作业
  → 计量采集器按 tenant=acme 标签聚合资源
  → 月度: base(9800) + overflow(按 cpu/storage 溢出) = 账单
  → 欠费超阈值 → 运营后台置 paused → 封装层回收租约(作业挂起, 数据保留)
```

### 4.2 SLA 档位映射
| 套餐 | ResourceQuota | 节点池租约 | 多租户隔离 |
| --- | --- | --- | --- |
| base | 8C/32G/200G | 共享节点池 | Namespace + deny-all |
| standard | 32C/128G/1T | 共享节点池优先 | 同上 + 配额硬限 |
| flagship | 128C/512G/5T | 独占节点池租约 | 同上 + 节点亲和独占 |

---

## 5. 多环境一致性

- 计量口径：四环境统一按 `tenant` / `ws` 标签采集，公式一致。
- 账单：本平台生成，不读云账单；公有云环境客户 VM 成本由客户自行承担，我方只计量平台内资源。
- 套餐档位与 ResourceQuota 映射四环境相同（差异仅在底层节点供给，由封装层吸收）。

## 6. 风险与对策

| 风险 | 现象 | 对策 |
| --- | --- | --- |
| 计量精度不足 | 账单纠纷 | 统一 Sidecar 埋点 + Prometheus，账单可核对可回溯 |
| 溢出计费争议 | 客户拒付 | 套餐内免费额度告警，溢出前通知 |
| 欠费误杀 | 数据丢失 | paused 仅挂起作业，数据保留；注销需二次确认 + 宽限期 |
| 多租户串扰 | 越权 | 封装层 RBAC + NetworkPolicy deny-all 兜底 |

## 7. 与控制台信息架构的对应

- 客户视角（控制台 v0.3 客户侧）：工作空间 / 项目 / 作业 / 账户配额——**不可见**运营后台。
- 平台视角（控制台 v0.3「运营后台」页）：租户 / 套餐 / 计量 / 账单 / 看板 / 审批——**仅平台方可见**。
- 两者共享封装层租户模型与计量数据，视角隔离由封装层权限层实现（L0.11 + L3.7）。
