﻿# L4.1 数据集成（SeaTunnel）· 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L4 数据开发与分析层
> 套餐：标准版起含（§11.5.1），基础版不含
> 对标：Apache SeaTunnel（原 Waterdrop，国产开源，Java）/ DataX / Flink CDC
> 关联：L2.1 统一存储（同步到 Iceberg）；L2.8 Kafka（流式接入）；L4.2 调度编排（被调度）；L0.11 封装层（凭据/隔离）；L3.1 元数据（消费 `/api/meta/v1/entities` 获取源/目标 schema）；L3.4 血缘（作业执行后回写 `/api/lineage/v1/collect`）；X3 统一运维观测（作业指标回传与告警）

## 1. 定位与价值

数据集成是平台的**统一数据进出通道**：以 Apache SeaTunnel 为引擎，屏蔽多源异构差异，将外部业务库、消息流、文件批量同步至湖仓集一体存储，并支撑库到库、湖到仓的反向回流。

客户价值：
- "配一下就能同步"——可视化 Source/Sink 配置，无需写 Spark/Flink 代码。
- "实时与批量同源"——CDC 实时入湖与离线全量同步共用同一套连接器与监控。
- "国产库都接得上"——信创环境下达梦/人大金仓/OceanBase 开箱即用。

平台价值：
- 引擎以 **SeaTunnel on K8s（Zeta 模式）** 部署，作业即 Pod，资源按租户隔离。
- 同步任务经封装层 REST 提交，由 L4.2 调度编排触发，客户只见"同步任务"。

```text
┌──────── 客户入口（经 L0.11 封装层 REST） ────────┐

```

## 3. Source/Transform/Sink 抽象

SeaTunnel 以"插件化连接器 + Transform 管子"组成 DAG 作业；连接器清单按四环境可用性维护。

| 类别 | 连接器 | 方向 | 信创 | 本地 | 公有云 | 私有云 |
| --- | --- | --- | --- | --- | --- | --- |
| 关系库 | MySQL CDC / JDBC | Source | ✓ | ✓ | ✓ | ✓ |
| 关系库 | Oracle CDC / JDBC | Source | ✓ | ✓ | ✓ | ✓ |
| 国产库 | 达梦 / 人大金仓 / OceanBase | Source/Sink | ✓ | ✓ | ◐ | ✓ |
| 消息 | Kafka / RocketMQ | Source/Sink | ✓ | ✓ | ✓ | ✓ |
| 文件 | HDFS / S3 / OSS / FTP | Source/Sink | ✓ | ✓ | ✓ | ✓ |
| 湖仓 | Iceberg / Doris | Sink | ✓ | ✓ | ✓ | ✓ |
| 缓存 | Redis | Source/Sink | ✓ | ✓ | ✓ | ✓ |
| 搜索 | Elasticsearch | Source/Sink | ✓ | ✓ | ✓ | ✓ |
| 文档库 | MongoDB | Source/Sink | ✓ | ✓ | ✓ | ✓ |

> Transform 算子：Sql（行内 SQL）、FieldMapper（字段映射/重命名）、Filter（过滤）、Replace（脱敏替换）、JsonPath（嵌套展开）。◐ 表示公有云环境由客户提供实例与凭据，平台不托管。
> Redis/ES/MongoDB 连接器对齐 `seatunnel-values.yaml` 中 `connectors.redis/elasticsearch/mongodb` 配置项，作为可选 Source/Sink，用于缓存同步、搜索索引构建与文档库集成场景。

## 4. 接口契约（经封装层 REST）

```
POST /api/integration/v1/jobs                 { name, source, sink, transform, mode } → jobId
GET  /api/integration/v1/jobs/{id}            → { status, metrics, lastRun }
POST /api/integration/v1/jobs/{id}/start      → 触发运行（同步或交 L4.2 调度）
POST /api/integration/v1/jobs/{id}/stop       → 优雅停止
GET  /api/integration/v1/jobs/{id}/metrics    → { rowsIn, rowsOut, throughput, lag }
POST /api/integration/v1/datasources          { type, connProps, credentialRef } → dsId
```

> 凭据经 L0.11 封装层 Vault 注入，作业 Pod 仅持有临时 token，不落明文配置；客户 API 不直接接触 SeaTunnel 原生端口。

## 5. 关键流程

```text
[配置Source/Sink] → [封装层校验+凭据注入] → [提交SeaTunnel Job]
        → [JobMaster调度] → [Source拉取/CDC订阅]
        → [Transform管子链] → [Sink写入Iceberg/Doris]
        → [指标回传] → [监控告警]
```

1. **配置**：控制台选连接器、字段映射、同步模式（全量/增量/CDC 实时）；Source/Sink 的 schema 可调 `GET /api/meta/v1/entities/{id}`（L3.1 元数据）自动填充，避免手工填写易错。
2. **提交**：封装层翻译为 SeaTunnel JobConfig，凭据替换为 token，提交 Zeta RestEndpoint。
3. **执行**：JobMaster 分配 Task，Source 并行拉取，Transform 流式处理，Sink 写湖仓。
4. **监控**：作业指标（吞吐/延迟/脏数据）回传封装层，对接 X3 统一运维观测（告警）；作业成功后调 `POST /api/lineage/v1/collect`（L3.4 血缘）回写字段级血缘。

## 6. 与湖仓集集成

- **CDC 实时入湖**：MySQL/Oracle CDC → SeaTunnel → Iceberg（湖，ODS 贴源），Schema 演进自动同步。
- **批量离线同步**：定时全量/增量拉取业务库 → Iceberg（仓，DWD/DWS），由 L4.2 调度触发。
- **多源联邦**：Kafka 流 + JDBC 库经同一 Job 合并写入 Doris（集，在线服务）。
- **反向回流**：湖仓 Iceberg → 业务库（回写报表/对账），Sink 复用 JDBC 连接器。
- **缓存与搜索同步**：Iceberg/Doris → Redis（缓存预热）/ Elasticsearch（搜索索引构建）/ MongoDB（文档库分发），复用 Sink 连接器，由 L4.2 调度触发。

## 7. 多租户与安全

- **凭据隔离**：每个数据源凭据存于租户专属 Vault 路径，作业 Pod 按 workspace ServiceAccount 拉取，跨租户不可见。
- **行级权限**：Sink 写 Iceberg 时携带租户标签，查询侧经 L2.7 统一 SQL 网关做行级过滤。
- **网络隔离**：作业 Pod 受 NetworkPolicy 约束，仅可访问白名单数据源端点与湖仓服务。
- **资源隔离**：作业 Pod request/limit 按工作空间 ResourceQuota 限额，超额排队或拒绝。

## 8. 多环境适配

| 环境 | 引擎部署 | 数据源特征 | 差异处理 |
| --- | --- | --- | --- |
| 信创 | SeaTunnel on SKE K8s | 国产库/国产消息优先 | 国产连接器优先加载，JDBC 驱动替换为信创版 |
| 本地 | SeaTunnel on SKE K8s | 自建 MySQL/Kafka/Ceph | 连接器全量可用 |
| 公有云 | SeaTunnel on SKE K8s | 客户自购云数据库/消息 | 仅当数据源，**不启用云托管同步服务** |
| 私有云 | SeaTunnel on 客户 K8s | 客户私有云内组件 | 镜像走客户私有镜像仓 |

> 四环境 SeaTunnel JobConfig 完全一致，差异仅连接器端点与驱动 Profile，保持可迁移、不锁云。

## 9. 部署配置

部署参数落地于 `design/deploy/values/seatunnel-values.yaml`，由封装层 Helm Operator 渲染。关键配置块：

```yaml
# seatunnel-values.yaml（节选）
seatunnel:
  image: sq-seatunnel:2.3-0.1.0
  version: "2.3.4"
  master:
    mode: "kubernetes"          # Zeta on K8s
    replicas: 2
  worker:
    replicas: 2
  connectors:
    mysql:         { enabled: true }
    postgres:      { enabled: true }
    kafka:         { enabled: true }
    iceberg:       { enabled: true }
    dameng:        { enabled: true, driver: "dm-jdbc" }       # 国产库（信创）
    kingbase:      { enabled: true, driver: "kingbase-jdbc" }
    oceanbase:     { enabled: true, driver: "oceanbase-jdbc" }
    redis:         { enabled: true }
    elasticsearch: { enabled: true }
    mongodb:       { enabled: true }
  tierProfiles:
    base:      { enabled: false }   # 基础版不含 L4.1
    standard:  { enabled: true,  worker.replicas: 2, resources: "medium" }
    flagship:  { enabled: true,  worker.replicas: 4, resources: "large" }
```

> 资源配额说明：`tierProfiles.*.resources` 中 quota 为单组件上限，平台总额度见 §11.5.2，由封装层 ResourceQuota 在租户级聚合约束（非所有组件同时满载，故单组件配额之和可略超平台总额度）。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| CDC 断点续传失败 | 数据丢失/重复 | SeaTunnel 保存 offset 至 Iceberg，断点恢复；Sink 幂等写 Iceberg 主键去重 |
| 国产库连接器成熟度 | 同步异常/字段类型缺失 | 优先 JDBC 通用连接器兜底；信创环境做预连接 preflight 探测 |
| 高吞吐作业压垮源库 | 源库性能下降 | Source 限速（rps/并发数）+ 避峰调度；CDC 走 binlog 不查源表 |
| Zeta 引擎单点 | 控制面不可用 | JobMaster 多副本 + K8s 自愈；作业 Pod 与控制面解耦，控制面宕机作业继续 |
| 凭据泄露 | 数据源被越权访问 | Vault 临时 token + NetworkPolicy + 审计日志，作业结束 token 即失效 |
