# L2.6 湖仓集一体 · 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L2 大数据引擎层
> 适用套餐：基础版、标准版、旗舰版（全档含，对齐 §11.5.1 套餐矩阵）
> 对标：星环 ArgoDB 湖仓集一体范式（在"湖仓一体"上增加"集"实时在线服务维度）
> 关联：L2.1 统一存储（底座）；L2.2 Spark（仓建模）；L2.3 Flink（实时入湖 CDC）；L2.4 Trino（即席查询）；L2.5 Doris（集层在线+物化）；L2.7 统一 SQL 网关（单一入口）；L0.11 封装层（隔离/配额）

## 1. 定位与价值

L2.6 是**架构层规范模块**，不提供具体引擎，而是定义"湖 → 仓 → 集"三级数据流转与联动的统一契约。把行业"湖仓一体"（湖+仓）升级为"湖仓集一体"（湖+仓+集），新增**实时在线服务维度**，让一份数据既能贴源沉淀、又能主题建模、还能毫秒级服务业务。

客户价值：
- **一份数据，三级复用**——湖原始不丢，仓主题好用，集在线秒回，无需跨系统搬运。
- **实时可用**——CDC 秒级入湖，物化视图秒级同步到集层，业务所见即最新。
- **客户不感知层级**——经 L2.7 统一 SQL 网关统一入口，只关心"查什么"，不关心"在哪一层"。

平台价值：
- 三级流转规范统一，避免各引擎各自为政导致数据冗余、口径分裂。
- 治理（元数据/血缘/质量/权限）跨三级贯通，不因层级断链。
- 与 L2.1 存储底座解耦：本模块只定"怎么流"，L2.1 定"怎么存"。

## 2. 三级架构总览

```text
┌──────────────────────── 湖仓集一体（L2.6 规范） ────────────────────────┐
│                                                                          │
│   湖 Lake（原始贴源）      仓 Warehouse（主题建模）     集 Serving（在线）  │
│   ────────────────       ────────────────         ────────────────     │
│   Iceberg on 对象存储     Iceberg / Doris 物化       Doris 在线表+物化视图  │
│   Flink CDC 实时写入      Spark ETL DWD/DWS          毫秒级在线查询         │
│   Schema 演进友好         Trino 即席查询             直连业务系统/控制台     │
│                                                                          │
│   ODS 原始 ──── ETL ───→ DWD/DWS 主题 ──── 物化 ───→ ADS 在线服务表       │
│                                                                          │
└──────────────────────────────┬───────────────────────────────────────────┘
                               ▼
            统一治理：元数据 / 血缘 / 质量 / 权限（跨三级贯通）
                               ▼
            统一入口：L2.7 统一 SQL 网关（客户不感知层级）
                               ▼
            统一底座：L2.1 统一存储（对象存储 + Iceberg）
```

三级分工原则：**湖忠实沉淀、仓统一口径、集高频服务**，各司其职、不越界、不回写。

## 3. 湖层（Lake）：原始贴源

- **存储形态**：Iceberg 表 on 对象存储，ODS 贴源，保留原始字段与变更历史。
- **写入方式**：Flink CDC 实时捕获上游（MySQL/Oracle/Kafka）→ upsert 入湖，秒级延迟。
- **Schema 演进**：Iceberg 原生支持加列/改列/分区演进，适应上游变更不阻塞写入。
- **职责边界**：湖只做"忠实沉淀"，不做聚合、不做过滤，原始可追溯。
- **典型表**：`ods_order_di`（订单增量）、`ods_user_binlog`（用户变更日志）。
- **延迟目标**：从上游变更到湖可见 ≤ 10 秒。
- **保留策略**：按业务需要设置快照保留期与分区过期，原始层保留期最长。
- **分区策略**：按事件时间隐藏分区，配合 Iceberg manifest 加速按时间范围回溯。

## 4. 仓层（Warehouse）：主题建模

- **存储形态**：DWD/DWS 主题表，Iceberg（重分析）或 Doris 物化（重查询加速）。
- **建模方式**：Spark ETL 从湖层读取，按星型/雪花模型加工成 DWD/DWS。
- **查询方式**：Trino 即席查询走 Iceberg catalog；高频固定查询走 Doris 物化视图。
- **职责边界**：仓做"口径统一 + 主题沉淀"，是分析侧单一事实来源。
- **触发机制**：调度触发（小时/日批）或湖层快照变更触发（近实时）。
- **延迟目标**：从湖到仓 ≤ 分钟级（近实时）或 ≤ 小时级（批）。
- **建模规范**：维度表与事实表分离，统一命名 `dwd_<业务>_<粒度>`、`dws_<业务>_<指标>`。
- **物化选择**：大范围分析留 Iceberg 走 Trino；高频点查/聚合落 Doris 物化视图。

## 5. 集层（Serving）：在线服务

- **存储形态**：Doris 在线表 + 物化视图，ADS 应用数据，宽表/聚合表为主。
- **同步方式**：Flink 从湖/仓实时物化到 Doris，或 Doris 物化视图自动同步。
- **查询性能**：毫秒级在线查询，直连业务系统、控制台、报表、API 服务。
- **职责边界**：集做"高频在线服务"，不承担历史沉淀职责，可按 TTL 滚动清理。
- **典型表**：`ads_user_profile`（用户画像）、`ads_realtime_dashboard`（实时大屏）。
- **延迟目标**：从仓到集 ≤ 10 秒；端到端查询 P99 ≤ 100 毫秒。
- **服务接口**：对外提供 JDBC/REST 查询接口，由 L2.7 网关统一鉴权后下发。
- **高可用**：Doris 集群多副本部署，BE 节点跨 K8s 节点反亲和，单节点故障不影响在线服务。

## 6. 数据流转规范

```text
上游 DB/Kafka ──CDC──→ 湖(Iceberg) ──ETL──→ 仓(DWD/DWS) ──物化──→ 集(Doris ADS)
   │  秒级          │  分钟/小时级         │  秒级同步          │
   │  Flink         │  Spark/Trino        │  Flink/Doris MV    │
   ▼                ▼                     ▼                    ▼
 原始事件       贴源沉淀              主题口径            在线服务
```

流转契约：
- **湖 → 仓**：Spark 批 ETL，按调度或快照触发，产出 DWD/DWS，写入 Iceberg 或 Doris。
- **仓 → 集**：Flink 流式物化 或 Doris 物化视图，秒级同步，产出 ADS 在线表。
- **湖 → 集**（近实时捷径）：Flink CDC 直接物化到 Doris，跳过仓层用于低延迟大屏。
- **回溯**：任一级可经 Iceberg Time Travel 回到历史快照，重算下游。
- **不反向**：数据只向下游流，集层不回写仓、仓不回写湖，避免污染原始。
- **幂等**：每级作业支持按快照重跑，下游可重建，不产生重复数据。
- **可观测**：每级流转记录延迟、吞吐、失败次数，汇聚到统一作业监控。

## 7. 统一治理（跨三级贯通）

- **元数据**：三级共用 Iceberg REST Catalog + Doris Catalog 联邦（Hive Metastore 仅作可选兼容，非主 catalog），表即资产，登记到 L3.5 资产目录。
- **血缘**：从湖源表到仓主题表到集在线表，端到端血缘贯通，影响分析跨级可追。
- **质量**：湖层校验原始完整性，仓层校验口径一致性，集层校验新鲜度（同步延迟告警）。
- **权限**：以库表列粒度统一授权，跨层级同一主体权限一次下发，不因层级分裂。
- **审计**：每级读写作业统一审计日志，可追溯"谁在何时改了哪一级的哪张表"。
- **成本**：三级存储与计算分别计量，按 workspace 归集，支撑租户账单与容量规划。
- **版本**：仓层主题表支持版本标记，集层物化视图随仓版本联动刷新，避免半更新态。

## 8. 接口契约（经 L2.7 统一 SQL 网关）

```
POST /api/lakehouse/v1/pipelines          { name, source, layers:[lake,warehouse,serving] } → 建三级流水
POST /api/lakehouse/v1/pipelines/{p}/run  → 触发一次湖→仓→集流转
GET  /api/lakehouse/v1/lineage/{table}    → [{upstream, downstream, layer}]   // 跨级血缘
GET  /api/lakehouse/v1/freshness/{table}  → { layer, lastSync, lagSeconds }    // 新鲜度
POST /api/lakehouse/v1/materialize        { source, target:doris, view }      // 物化到集层
GET  /api/lakehouse/v1/health             → { lake, warehouse, serving }       // 三级健康度
```
> 客户读写经 L2.7 统一 SQL 网关路由到对应层级引擎，不直接感知"这条查询走了 Trino 还是 Doris"。

## 9. 多环境一致性

- 三级流转逻辑（湖→仓→集、CDC、物化）四环境**零改动**。
- 差异只在 L2.1 StorageDriver 后端：信创国产对象存储 / 本地 Ceph / 公有云客户自购 S3 / 私有云厂商存储。
- 引擎部署形态随 SKE K8s 一致；Doris/Trino/Spark/Flink 的 catalog 均指向同一 Iceberg REST Catalog。
- 客户在任一环境提交的同一套 pipeline 定义，可原样迁移到另一环境运行。
- 信创环境对 Doris/Trino 等引擎的国产化适配由封装层屏蔽，流转规范不变。
- 公有云环境仅用客户自购对象存储作底座，不启用任何云原生托管引擎，保持可迁移。
- 四环境均以同一套 Helm Chart 部署引擎，仅 values.yaml 中 StorageDriver profile 不同。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 湖层小文件膨胀 | CDC 高频写入产生大量小文件，读取慢 | 定时 compaction + Flink 写合并参数调优 |
| 物化视图同步延迟 | 集层口径与仓层短暂不一致 | 新鲜度监控告警 + 业务侧标注"近实时"语义 |
| 跨层级一致性 | 湖仓集口径漂移 | 统一 catalog + 血缘校验 + 仓层作为单一事实源 |
| 三级冗余存储 | 同一数据湖/仓/集三份 | 湖仓共用 Iceberg 不拷贝；集层只放物化结果，按 TTL 滚动 |
| 流转链路长难排查 | 故障定位难 | 端到端血缘 + 每级延迟埋点 + 统一作业日志 |
| 近实时捷径绕过仓 | 口径不受仓约束 | 仅限明确标注的"大屏/探查"场景，正式报表必须经仓 |

## 11. 与 UI 的对应

控制台 v0.3「数据集成」页（CDC 入湖、物化入集任务）、「数据开发」（湖贴源/仓主题/集在线三类作业）、工作台"湖仓集一体"概览（三级数据量、新鲜度、流转拓扑）均基于本规范。本文件是其流转与治理侧契约依据。

## 12. 演进路线

- **v0.1（当前）**：定义三级流转规范与接口契约，湖仓集基础联动跑通。
- **v0.2**：近实时捷径（湖→集）产品化，物化视图同步延迟可观测、可告警。
- **v0.3**：跨级血缘可视化与影响分析，三级成本分摊落到租户账单。
- **v1.0**：智能物化推荐（按查询热度自动建议集层物化视图），三级自治流转。
