# L2.10 多模型选配引擎 · 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L2 大数据引擎层
> 适用套餐：旗舰版（基础版、标准版不含，对齐 §11.5.1 套餐矩阵）
> 对标：NebulaGraph（图）/ Milvus（向量）/ Elasticsearch（搜索）/ Redis（键值）
> 关联：L4.5.3 向量库（Milvus 复用）；L4.5.4 知识工程（NebulaGraph 复用）；L2.7 统一 SQL 网关（多模型 SQL 适配）；L0.11 封装层（选配/计费/隔离）；L3.5 资产目录（ES 集成）

## 1. 定位与价值

多模型选配引擎是 L2 层的**选配层模块**：图、向量、搜索、键值四类非关系引擎按需勾选，**不强制安装**，由封装层按套餐与租户需求驱动启用。

客户价值：
- "按需付费"——基础版零负担起步，业务出现图/向量/搜索诉求时再勾选安装。
- "一引擎多用"——Milvus 同时服务 L2.10 与 L4.5.3 向量库，NebulaGraph 同时服务 L2.10 与 L4.5.4 知识工程，避免重复部署。
- "统一入口"——经 L2.7 统一 SQL 网关，客户用同一 SQL 方言访问多模型，屏蔽 nGQL/DSL 差异。

平台价值：
- 初始交付复杂度降低——不勾选则不部署，K8s 资源占用与运维面收敛。
- 选型已拍板国产开源三件套（NebulaGraph/Milvus/ES），信创友好、可迁移、不锁厂商。
- 多环境同构——四环境部署 Helm values 差异仅在存储后端与镜像 tag，上层 SQL 与作业不改。

## 2. 选配清单

| 模型 | 引擎选型 | 语言/实现 | 适用场景 | 是否必装 |
| --- | --- | --- | --- | --- |
| 图 | NebulaGraph | C++ | 知识图谱、关系推理、血缘图谱 | 否（旗舰版可选） |
| 向量 | Milvus | Go/C++ | 语义检索、RAG 嵌入召回、推荐 | 否（旗舰版可选） |
| 搜索 | Elasticsearch | Java | 全文检索、资产目录、日志检索 | 否（旗舰版可选） |
| 键值 | Redis | C | 缓存、会话、限流计数器 | 否（按需，常与在线服务共部署） |

> 键值默认复用 Doris 在线表或封装层缓存；显式勾选 Redis 仅在高 QPS 缓存场景。

## 3. NebulaGraph 图引擎

K8s 部署（Helm + nebula-operator，三副本 graphd/storaged/metad），存储经 StorageDriver 落对象存储或本地 PV，按租户独立 Space 隔离。

```text
┌──────── NebulaGraph 集群（K8s Namespace: sq-graph） ────────┐
│  graphd(nGQL 入口)  →  storaged(分片, RocksDB)  ←  metad(元) │
│         ▲                                                    │
│         │ nGQL over Thrift                                   │
│  L2.7 统一 SQL 网关（图方言适配）                            │
└──────────────────────────────────────────────────────────────┘
```

- 数据模型：Tag（点属性）/ EdgeType（边属性）/ Space（图空间，按租户隔离）。
- 查询语言：nGQL（`GO ... OVER`、`FETCH PROP`、`MATCH` Cypher 兼容子集）。
- 部署参数：storaged 副本数 ≥3，partition 按 `租户预估点数/10w` 估算，disable_auto_compact=false。
- 与 L4.5.4 复用：知识工程直接复用同一集群的独立 Space，不重复部署；血缘图谱由 L2.7 网关写入独立 Space。

Schema 示例（nGQL）：

```ngql
CREATE SPACE sq_tenant_001(partition_num=10, replica_factor=3);
USE sq_tenant_001;
CREATE TAG entity(name string, type string, ts timestamp);
CREATE EDGE related(kind string, weight double, ts timestamp);
```

## 4. Milvus 向量引擎

K8s 部署（milvus-operator，含 proxy/querynode/indexnode/datanode + etcd/minio 依赖），存储后端复用平台对象存储（minio 兼容 S3），indexnode 独立节点池避免建索引抢占查询。

- 索引类型：FLAT（小规模精确）/ IVF_FLAT / HNSW（高召回默认）/ IVF_PQ（海量压缩）。
- 度量：COSINE（语义默认）/ IP / L2，由 Collection 创建时指定。
- 部署参数：querynode 副本随 QPS 横扩；indexnode 按建索引任务突发弹性；etcd 三副本元数据。
- 与 L4.5.3 复用：向量库模块直连同一 Milvus 集群的 Collection，按 `workspace/collection` 命名隔离；L2.10 仅提供集群，L4.5.3 提供业务语义与嵌入管线（Embedding 模型由 L4.5.3 侧管理）。

Collection 创建示例（Python，pymilvus）：

```python
from pymilvus import Collection, FieldSchema, CollectionSchema, DataType
schema = CollectionSchema([
    FieldSchema("id", DataType.INT64, is_primary=True),
    FieldSchema("embedding", DataType.FLOAT_VECTOR, dim=768),
    FieldSchema("tenant", DataType.VARCHAR, max_length=64),
])
col = Collection("sq_tenant_001_doc", schema)
col.create_index("embedding", {"index_type": "HNSW", "metric_type": "COSINE", "M": 16, "efConstruction": 200})
```

## 5. Elasticsearch 搜索引擎

K8s 部署（ECK Operator，data/master/ingest 三角色），索引分片按租户隔离，存储经 StorageDriver；data 节点独立节点池，避免与计算引擎争抢内存。

- 全文检索：分词（IK 中文）/ 同义词 / 高亮 / 聚合，DSL 经 L2.7 网关适配为 SQL 子集。
- 与 L3.5 资产目录集成：表/字段/标签入 ES 索引 `sq_catalog_v1`，控制台"资产搜索"直查此索引；元数据变更经 CDC 增量同步。
- 日志检索可选：与 L2.6 可观测共享 ES 集群或独立集群，按租户索引前缀 `sq_log_{tenant}_*` 隔离。
- 部署参数：data 节点 heap ≤ 容器内存 50%，shard 数按 `索引数据量/30GB` 估算，replica ≥1。

资产目录索引 mapping 示例（DSL）：

```json
{"mappings": {"properties": {
  "table_name": {"type": "text", "analyzer": "ik_max_word"},
  "columns": {"type": "nested", "properties": {"name": {"type": "keyword"}, "comment": {"type": "text"}}},
  "tags": {"type": "keyword"}, "tenant": {"type": "keyword"}
}}}
```

## 6. 统一 SQL 适配

经 L2.7 统一 SQL 网关统一入口，多模型 SQL 方言映射：

| 客户 SQL 形态 | 目标引擎 | 网关翻译 |
| --- | --- | --- |
| `MATCH (n)-[r]->(m) RETURN ...` | NebulaGraph | 转 nGQL `GO/MATCH` |
| `SELECT * FROM vec_table ORDER BY sim(vec, ?) LIMIT k` | Milvus | 转 search + 向量参数 |
| `SELECT * FROM es_table WHERE MATCH(title, '关键词')` | Elasticsearch | 转 DSL query_string |
| `SELECT k, v FROM kv_table WHERE k = ?` | Redis / Doris | 转 GET 或 Doris 点查 |

适配流程：网关解析 SQL → 识别目标表所属引擎（查 catalog 元数据）→ 命中方言映射表 → 翻译为原生请求 → 执行 → 结果归一化为关系表形态返回。

> 客户只见标准 SQL 形态，方言映射在网关侧完成；未勾选的模型对应 SQL 直接报"未启用"，不静默失败。网关维护方言能力矩阵，覆盖语法白名单明确，超白名单语法提示原生入口。

## 7. 选配与计费

| 套餐 | 图(Nebula) | 向量(Milvus) | 搜索(ES) | 键值(Redis) |
| --- | --- | --- | --- | --- |
| 基础版 | 不含 | 不含 | 不含 | 复用 Doris |
| 标准版 | 不含 | 不含 | 不含 | 复用 Doris |
| 旗舰版 | 全选 | 全选 | 全选 | 可选 |

> 对齐 §11.5.1 套餐矩阵：L2.10 整体仅在旗舰版纳入；基础版/标准版均不含 L2.10 任一子引擎。标准版 L3.5 资产目录搜索改用 Trino LIKE / 全文 UDF 替代 ES，避免引入 L2.10 依赖；旗舰版起 ES 接入，资产目录搜索切换至 ES 索引以获得分词与高阶检索能力。

选配动作由 L0.11 封装层驱动：控制台勾选 → 生成 Helm values → SKE 应用 Operator 部署 → 注册到 L2.7 网关方言表。卸载反向执行，数据按租户 Space/Collection/Index 粒度清理。计费按"启用引擎数 × 资源规格 × 时长"，未勾选不计费、不占资源；旗舰版可选引擎按"启用即计费"。

## 8. 多环境适配

| 环境 | NebulaGraph | Milvus | Elasticsearch | Redis |
| --- | --- | --- | --- | --- |
| 信创 | 国产 OS + 国产 CPU 编译版 | 国产 OS + 国产 CPU 编译版 | OpenJDK 兼容版 | 国产版 |
| 本地数据中心 | K8s + 本地 PV | K8s + 对象存储 | K8s + 本地 PV | K8s |
| 公有云 VM | K8s + 客户对象存储 | K8s + 客户对象存储 | K8s + 客户对象存储 | K8s |
| 私有云 | K8s + 厂商存储 | K8s + 厂商存储 | K8s + 厂商存储 | K8s |

> 关键约束：云环境仅用客户自购对象存储做后端，**绝不启用云托管图/向量/搜索服务**，保持可迁移、不锁云。镜像 tag 按环境切换（信创用国产 CPU 编译版，其余用官方 x86/ARM 多架构镜像）。Helm values 仅存储后端与镜像 tag 不同，部署模板四环境一致。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 多引擎资源争抢 | K8s 节点资源紧张 | 按 Namespace 配 Request/Limit + 调度反亲和 + 独立节点池 |
| 信创编译兼容 | 引擎不可用 | Nebula/Milvus 提供国产 CPU 编译版；ES 用兼容 JDK；preflight 探测 |
| 重复部署浪费 | Milvus/Nebula 多副本 | L4.5.3/L4.5.4 复用同一集群，按 Space/Collection 隔离而非新集群 |
| 网关方言覆盖不全 | 部分 SQL 不可用 | 网关维护方言能力矩阵，未覆盖语法明确报错并提示原生入口 |
| 卸载残留数据 | 存储泄漏 | 卸载按租户粒度清理 Space/Collection/Index，并回收对象存储前缀 |
| 大图/大向量建索引慢 | 业务阻塞 | indexnode 独立节点池 + 异步建索引 + 进度可观测 |

## 10. 与 UI 的对应

控制台「引擎选配」页（基础/标准/旗舰套餐勾选图、向量、搜索、键值）、资产目录搜索框（ES）、知识工程图谱可视化（Nebula）、向量检索调试台（Milvus）均基于此模块。本文件是其选配、部署、计费与 SQL 适配的契约依据。
