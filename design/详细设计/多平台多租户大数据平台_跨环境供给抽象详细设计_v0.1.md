# L0.5 跨环境统一供给抽象 · 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L0 机器供应层
> 套餐：基础版（三档全含）
> 对标：Cluster API（Kubernetes SIG 集群生命周期抽象）/ Terraform Provider 抽象
> 关联：L0.1~L0.4（四环境供应实现）；L0.10 环境适配框架（本模块是其 L0 侧对应）；L0.6 SKE 控制面；L0.11 封装层（业务层经封装层间接消费三原语，不直连）

## 1. 定位与价值

跨环境统一供给抽象是 L0 机器供应层的**唯一抽象入口**：把信创、本地数据中心、公有云 VM、私有云四类机器供应差异收敛为统一的 NodePool / StoragePool / NetworkPool 三原语，上层 SKE 控制面与业务 Helm Chart 只面向三原语，**四环境零改动交付**。

客户价值：
- "一套部署描述，四环境可装"——Helm/Cluster API 模板不因环境改写。
- "环境能力差异可见"——preflight 输出能力矩阵，缺失能力提前告警而非上线才暴露。
- "不锁云"——云环境只取裸 VM/裸对象存储，绝不依赖云托管 K8s/数据库/消息服务。

平台价值：
- L0.1~L0.4 四个供应实现只对接本抽象的统一接口，新增环境只需写一个 Driver + Profile。
- 本模块是 L0.10 环境适配框架在机器侧的对应：L0.5 定义"机器长什么样"，L0.10 定义"K8s 在这机器上怎么跑"。

## 2. 统一原语

三类原语屏蔽四环境供应差异（内部接口，客户不直接调用）：

```text
interface NodePool {
  createPool(name, role, replicas, machineSpec);     // role: master/worker/edge
  scalePool(name, replicas); deletePool(name);
  listNodes(name); drainNode(nodeId);                 // 安全下线
}
interface StoragePool {
  createVolume(name, sizeGi, tier);                   // tier: hot/warm/cold
  attachVolume(volumeId, nodeId); detachVolume(...);
  snapshotVolume(volumeId);                           // 供灾备/迁移
}
interface NetworkPool {
  createVpc(name, cidr); createSubnet(vpc, cidr, zone);
  exposeIngress(pool, port);                          // 入口暴露统一走 L0.10 Ingress
  bindSecurityGroup(pool, rules);                     // 租户/池间隔离
}
```

> 三原语输出均为"已就绪的 K8s 可纳管节点 + 挂载点 + 网络可达"，交 L0.6 SKE 控制面纳管。本模块不安装 K8s（那是 L0.6 职责），只供应机器。

### 2.1 三原语 → REST 端点路径映射契约

三原语为内部接口（伪代码 interface），四环境实现各自暴露为 REST 端点，统一前缀 `/api/l0/v1/`，按环境子路径区分。下表给出原语方法→REST 路径的统一映射，L0.1~L0.4 实现须严格对照本表，驱动命名须出现本表所列 Driver 名：

表：三原语 REST 端点路径映射表

| 原语 | 方法 | REST 路径（统一前缀 `/api/l0/v1/`） | 请求体 | 响应 | 四环境 Driver 命名（L0.5 §3） |
| --- | --- | --- | --- | --- | --- |
| NodePool | createPool | `POST /{env}/nodepools` | `{ name, role, replicas, machineSpec }` | `{ poolId, status }` | XCBaremetalDriver / IPMIDriver / CloudVMDriver / PrivateVMDriver |
| NodePool | scalePool | `POST /{env}/nodepools/{pool}/scale` | `{ targetReplicas }` | `{ status, replicas }` | 同上 |
| NodePool | deletePool | `DELETE /{env}/nodepools/{pool}` | - | `{ status }` | 同上 |
| NodePool | listNodes | `GET /{env}/nodepools/{pool}/nodes` | - | `[{ nodeId, status, labels }]` | 同上 |
| NodePool | drainNode | `DELETE /{env}/nodes/{nodeId}` | - | `{ status }` | 同上 |
| StoragePool | createVolume | `POST /{env}/volumes` | `{ name, sizeGi, tier }` | `{ volumeId }` | XCStorageDriver / CephDriver / CloudDiskDriver / PrivateStorageDriver |
| StoragePool | attachVolume | `POST /{env}/volumes/{id}/attach` | `{ nodeId }` | `{ status }` | 同上 |
| StoragePool | snapshotVolume | `POST /{env}/volumes/{id}/snapshots` | - | `{ snapshotId }` | 同上 |
| NetworkPool | createVpc | `POST /{env}/vpcs` | `{ name, cidr }` | `{ vpcId }` | XCNetworkDriver / VlanDriver / CloudVpcDriver / PrivateNetworkDriver |
| NetworkPool | exposeIngress | `POST /{env}/vpcs/{vpc}/ingress` | `{ pool, port }` | `{ endpoint }` | 同上 |

> `{env}` 取值：`xc`（信创 L0.1）/ `onprem`（本地 L0.2）/ `cloud`（公有云 L0.3）/ `privatecloud`（私有云 L0.4）。preflight 端点统一为 `POST /{env}/preflight`。本表是 L0.1~L0.4 接口实现的对照基准，四环境 REST 路径须与本表一致，驱动命名须与 §3 表格一致，确保双向引用闭环。

## 3. 四环境驱动对照

四环境各自实现 §2 三原语，运行时按 Profile 加载对应 Driver：

| 环境 | NodePool 驱动 | StoragePool 驱动 | NetworkPool 驱动 | 关键约束 |
| --- | --- | --- | --- | --- |
| 信创（L0.1） | XCBaremetalDriver | XCStorageDriver | XCNetworkDriver | 国产 CPU/OS/网卡优先，BIOS/固件基线校验 |
| 本地数据中心（L0.2） | IPMIDriver（IPMI/PXE 置机） | CephDriver / LVMDriver | VlanDriver | 裸金属或虚机，自建网络无 SDN |
| 公有云 VM（L0.3） | CloudVMDriver（ECS/EC2/VM） | CloudDiskDriver | CloudVpcDriver | **客户提供凭证，只取裸 VM，不启云托管服务** |
| 私有云（L0.4） | PrivateVMDriver | PrivateStorageDriver | PrivateNetworkDriver | 客户私有云 VM，按厂商 API 适配 |

> 关键约束：云环境只供应"裸 VM + 裸磁盘 + 裸 VPC"，绝不调用云托管 K8s/数据库/消息——保持可迁移、不锁云。所有云凭证由客户提供并经 L0.10 凭证托管加密注入。

## 4. Profile 机制

每环境一个 Profile YAML，描述该环境的供应参数与能力边界，部署时按 `--profile <env>` 加载：

```yaml
# config：profile-xinchuang.yaml
apiVersion: supply.shuqing.io/v1
kind: SupplyProfile
metadata:
  name: xinchuang-site-a
spec:
  environment: xinchuang              # xinchuang | onprem | publiccloud | privatecloud
  nodePool:
    machineSpec: { cpuArch: kunpeng, os: kylin-v10, kernel: "4.19+" }
    roles: [master, worker, edge]
    maxReplicas: 200
  storagePool:
    tiers: [hot, warm]
    backend: ceph                     # ceph | local-lvm | cloud-disk | private-storage
  networkPool:
    cidr: 10.30.0.0/16
    zones: [zone-a, zone-b]
  capabilities:                       # 由 §5 preflight 探测后回填/校验
    liveMigration: true
    storageSnapshot: true
    multiZone: true
```

> Profile 是"环境契约"：L0.5 Driver 读它供应机器，L0.10 适配框架读它决定 K8s 调度策略，L0.6 SKE 读它判断集群容量。三处共用同一份 Profile，避免多处环境描述漂移。

## 5. 能力探测（preflight）

部署前对目标环境跑 preflight，输出能力矩阵，决定上层启用哪些特性（如热迁移、跨可用区、存储快照）：

```text
命令示例：执行环境供应前能力探测
shuqing-supply preflight --profile xinchuang-site-a
```

```text
能力矩阵示例：
┌──────────────┬──────────┬──────────────┬───────────┬──────────┐
│ 环境         │ 热迁移   │ 存储快照     │ 跨可用区  │ GPU      │
├──────────────┼──────────┼──────────────┼───────────┼──────────┤
│ 信创 site-a  │   ✓      │    ✓         │    ✓      │   ✗      │
│ 本地 dc-1    │   ✗      │    ✓         │    ✗      │   ✓      │
│ 公有云       │   ✓      │    ✓         │    ✓      │   ✓      │
│ 私有云       │   ✓      │    ✗         │    ✗      │   ✗      │
└──────────────┴──────────┴──────────────┴───────────┴──────────┘
```

> 探测结果回填 Profile.capabilities 并写回；上层（L0.10/L2 引擎）按能力矩阵自动降级：缺热迁移则禁用节点重调度，缺快照则灾备走对象存储复制，缺 GPU 则 AI 引擎回退 CPU 模式。**能力缺失不阻塞交付，只降级并告警**。

## 6. 与 L0.10 环境适配框架的关系

本模块与 L0.10 是**机器侧 / K8s 侧**的一对抽象，分工严格不重叠：

| 维度 | L0.5（本模块） | L0.10 环境适配框架 |
| --- | --- | --- |
| 抽象对象 | 物理机/VM、裸磁盘、裸网络 | K8s 在已供应机器上的运行适配 |
| 输出 | 就绪节点 + 挂载点 + 网络可达 | 可调度 K8s 集群（CNI/CSI/Ingress 适配） |
| 关键动作 | createPool / attachVolume / exposeIngress | 装 CNI/CSI、调 kubelet、配 Ingress、注入凭证 |
| 与 L0.6 关系 | 供应机器交 SKE 纳管 | 在 SKE 纳管的机器上调通 K8s |

> 协作流程：L0.5 按 Profile 供应机器 → 交 L0.6 SKE 纳管 → L0.10 在其上调通 K8s 适配 → 上层 Helm Chart 部署。三者串行，任一失败回滚并报告失败原语。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 四环境 Driver 实现漂移 | 行为不一致、上层需打补丁 | 三原语接口契约 + 共用 conformance 测试套件，CI 强制四环境全跑 |
| 云凭证泄露 | 客户云资源被误操作 | 凭证经 L0.10 托管加密注入，Driver 仅运行时取用，不落盘不进日志 |
| 能力探测误判 | 上层依赖缺失能力运行失败 | preflight 实测而非声明，结果写回 Profile 并由 L0.10 二次校验 |
| 信创硬件兼容性 | 供应失败或节点不稳 | Driver 内置 BIOS/固件/驱动基线校验，不达标拒绝纳管并告警 |
| 跨环境数据迁移 | 交付周期长 | StoragePool.snapshot + 桶间复制工具，按 workspace 粒度迁移 |

## 8. 与 UI 的对应

控制台 v0.3「平台运维」页"环境供应"区（Profile 选择、preflight 能力矩阵展示、节点池扩缩容）与本模块对应；客户视角只看到"环境就绪 / 节点池 / 存储用量"，不暴露 Driver/IPMI/云 API 细节。本文件是其供应侧契约依据。
