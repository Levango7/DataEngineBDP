# L5.3 行业应用模板 · 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L5 多租户产品层（SaaS）
> 对标：各行业 ISV 解决方案 / Salesforce AppExchange 模式
> 关联：L4.2 调度编排（DolphinScheduler）；L4.4 BI 可视化（Superset+ECharts）；L3.5 资产目录；X1 统一身份权限；L0.11 封装层

## 1. 定位与价值

行业应用模板是面向外部客户的**预置分析模板**（经营分析、风控、物联网等），让客户"开箱即用"而非从零搭建数据模型、作业流与仪表盘。模板本身环境无关，仅在实例化时绑定客户真实数据源。

客户价值：
- "开箱即用"——选定行业模板后，仅需绑定数据源即可获得完整分析能力，省去 6～12 个月搭建周期。
- "可裁剪可扩展"——模板以 Helm Chart 形式交付，租户在 values.yaml 中裁剪参数，亦可 fork 后二次开发。
- "持续升级"——模板版本独立演进，平台推送新版本时租户可一键升级并保留本地定制。

平台价值：
- 沉淀行业 Know-How 为可复用资产，缩短交付周期、降低 PaaS→SaaS 转化门槛。
- 模板产物自动注册到 L3.5 资产目录并打标 `source=template:{模板ID}`，全链路可追溯。
- 仅旗舰版开放（基础版❌ 标准版❌ 旗舰版✅），形成旗舰版差异化卖点。

## 2. 模板结构

一个模板 = 数据模型 + 作业流 + BI 仪表盘 + 权限模板 + README，统一以 **Helm Chart** 打包，`values.yaml` 承载租户级参数。

```text
templates/{模板ID}/
├── Chart.yaml                 # 模板元信息（name/version/appVersion/description）
├── values.yaml                # 租户级参数（数据源占位、阈值、租户ID）
├── templates/
│   ├── ddl/                   # 数据模型：建表 DDL / Iceberg Schema / 样例数据
│   │   ├── ods_*.sql          # ODS 贴源层
│   │   ├── dwd_*.sql          # DWD 明细层
│   │   └── dws_*.sql          # DWS 汇总层
│   ├── dags/                  # 作业流：DolphinScheduler DAG JSON（对接 L4.2）
│   ├── dashboards/            # BI 仪表盘：Superset dashboard JSON + ECharts option（对接 L4.4）
│   ├── rbac/                  # 权限模板：Keycloak realm/client/role JSON（对接 X1）
│   └── namespace.yaml         # 租户级 Namespace + 资源配额（对接 L0.11）
├── README.md                  # 业务说明 / 适用场景 / 参数表 / 升级注意事项
└── schema.json                # values.yaml 字段校验 schema（用于安装时校验）
```

模板**环境无关**：纯 Helm + SQL + JSON，不含任何 IP/域名/密钥；环境差异仅在实例化时通过数据源连接信息注入。

## 4. 模板生命周期

```text
[开发 dev] → [审核 review] → [上架 catalog] → [安装 install] → [实例化 instantiate]
                                      ↑                              │
                                      │                              ▼
                                  [升级 upgrade] ← [运行 running] ←──┘
                                      │                              │
                                      └──────────────────────────────┘
                                                                   │
                                                                   ▼
                                                             [卸载 uninstall]
```

状态机说明：
- **dev**：模板作者在 dev 环境开发，本地校验 `helm lint` + `schema.json` 通过。
- **review**：平台运营审核（安全审计见第 8 节）+ 业务评审，通过后入 catalog。
- **catalog**：模板进入模板目录，对旗舰版租户可见可装。
- **install**：租户选定模板 + 填写 values → Helm install 到租户 Namespace，**不触数据**。
- **instantiate**：绑定客户真实数据源 → 触发首次作业运行 → 生成 BI 仪表盘快照。
- **running**：作业按 DAG 周期运行，仪表盘实时刷新。
- **upgrade**：平台推送新版本，租户一键升级，保留本地定制（values 合并策略）。
- **uninstall**：Helm uninstall + 清理租户 Namespace 内模板产物，资产目录标记下线（不物理删除数据）。

## 5. 安装与实例化

**安装（install）**——只部署骨架，不触数据：
1. 校验租户为旗舰版且未达模板配额上限。
2. 渲染 values.yaml（注入租户ID、Namespace、数据源占位）。
3. `helm install {release} {chart} -n {tenant-ns} -f values.yaml`，创建租户级 Namespace 与配额（对接 L0.11）。
4. 注入数据源连接信息（来自 L3.5 资产目录或租户填写，存入租户 Secret）。
5. 模板产物（表 Schema、DAG、仪表盘、RBAC）注册到 L3.5 资产目录，打标 `source=template:{模板ID}`。

**实例化（instantiate）**——绑定真实数据，首次出数：
1. 校验数据源连通性 + Schema 与 DDL 兼容性。
2. 触发首次作业运行（ODS→DWD→DWS 全链路），失败可回滚至 install 态。
3. 生成 BI 仪表盘首屏快照（避免空仪表盘体验）。
4. 激活 RBAC（Keycloak realm/client/role 同步至 X1）。
5. 实例化完成进入 running 态，作业按 DAG 周期运行。

## 6. 接口契约

```text
# 列出模板目录（按行业/版本过滤）
listTemplates(filter: {industry?, version?, keyword?}) -> [TemplateMeta]
  TemplateMeta = {id, name, industry, version, description, status, installCount, rating}

# 安装模板到租户（不触数据）
installTemplate(tenantId, templateId, values: Values) -> {releaseName, namespace, status}

# 实例化（绑定数据源 + 首次运行）
instantiate(tenantId, releaseName, datasourceBindings: [{占位, 资产ID}]) -> {jobRunId, dashboardSnapshotUrl, status}

# 升级模板（保留本地 values 定制）
upgradeTemplate(tenantId, releaseName, targetVersion, valuesMergeStrategy: "merge"|"overwrite") -> {fromVersion, toVersion, status}

# 卸载模板（清理产物，数据保留）
uninstallTemplate(tenantId, releaseName, purgeData: bool=false) -> {status, retainedAssets}
```

约束：所有接口需旗舰版租户权限 `template:*`；install/instantiate 异步执行，返回 jobId 供轮询；upgrade 默认 merge 策略保留租户定制。

## 7. 多环境对照

| 维度 | 信创环境 | 本地化部署 | 云 VM 部署 | 私有云部署 |
|---|---|---|---|---|
| 模板本体 | 纯 Helm+SQL+JSON，环境无关 | 同左 | 同左 | 同左 |
| 镜像架构 | **需验证 ARM 镜像可用性**，缺失则构建 ARM 版 | x86 镜像 | x86 镜像 | x86/ARM 按集群 |
| 数据源 | 适配信创数据库（如 GaussDB） | 适配 MySQL/PG | 适配云 RDS | 适配客户既有库 |
| 实例化差异 | 仅数据源连接信息随环境变 | 同左 | 同左 | 同左 |
| 升级渠道 | 内网镜像的 chart repo | 内网 chart repo | 公网/内网均可 | 内网 chart repo |

模板本身**环境无关**，差异仅在实例化时数据源随环境变；信创环境需在审核阶段额外验证 ARM 镜像可用性，缺失则由平台补构建 ARM 版本后方可上架。

## 8. 风险对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 模板含恶意 SQL（删表/越权） | 数据泄露/破坏 | 上架前安全审计：SQL 静态扫描 + 沙箱试运行 + DDL 白名单（禁 DROP/TRUNCATE 跨租户） |
| 模板资源爆炸（全表扫描/死循环） | 拖垮集群 | 模板作业受租户配额约束（CPU/内存/时长，对接 L0.11）；OLAP 查询强制带分区裁剪与 LIMIT |
| 模板版本与平台版本不兼容 | 升级失败 | Chart.yaml 声明 `appVersion` 范围；升级前校验兼容性，不兼容则提示先升级平台 |
| 信创 ARM 镜像缺失 | 信创环境不可装 | 审核阶段验证 ARM 镜像，缺失则平台补构建；上架标注支持架构 |
| 模板间冲突（同 Namespace 资源名冲突） | 安装失败 | 强制命名约定 `{templateId}-{resource}`；安装前预检冲突，冲突则拒绝并提示 |
| 模板作者提交后门 | 安全风险 | 模板签名（GPG）+ 审核人复核 + 关键变更二次评审；运行时禁止模板访问跨租户资源 |

## 9. 演进路线

- v0.1：9 个行业模板上架，覆盖金融/政务/制造/零售/物联网五大行业，支持 install/instantiate/upgrade/uninstall 全生命周期。
- v0.2：模板市场评分与评论、模板组合（多模板协同）、AI 辅助模板生成。
- v0.3：跨平台模板（同一模板适配信创+x86）、模板订阅与自动升级、模板 SLA 监控。
