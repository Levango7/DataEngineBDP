# L4.5.2 机器学习（MLflow + MLlib）· 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L4 数据开发与分析层
> 对标：MLflow（开源 MLOps 标准）/ Spark MLlib（分布式机器学习库）/ Kubeflow 训练编排
> 关联：L2.2 Spark（MLlib 训练底座）；L4.5.5 LLMOps（MLflow 扩展到大模型）；L3.5 资产目录（模型即资产）；L0.11 封装层（配额/隔离/CR 翻译）
> 适用版本：标准版✅ / 旗舰版✅（基础版❌，对照 §11.5 套餐模块矩阵）

## 1. 定位与价值

机器学习模块是平台的**模型全生命周期底座**：以 MLflow 承担"实验追踪 → 模型注册 → 模型部署"三段闭环，以 Spark MLlib 承担分布式训练，全程跑在 K8s 上，模型作为一等资产入 L3.5 资产目录。

客户价值：
- "训练可追溯"——每次运行的参数/指标/产物自动留痕，实验可复现、可对比。
- "模型可治理"——版本化注册、阶段切换（Staging/Production）、一键回滚。
- "部署即点击"——模型从 Registry 一键发布到 K8s Serving，端点自动伸缩。

平台价值：
- MLflow on K8s（Tracking Server + Model Registry + Serving）统一部署，四环境同构。
- 训练作业经封装层翻译为 SparkApplication CR，受工作空间 ResourceQuota 与 GPU/NPU 配额约束。
- LLMOps（L4.5.5）复用 MLflow Tracking/Registry 扩展，传统 ML 与大模型共用一套追踪治理底座。

## 3. 实验追踪（MLflow Tracking）

以 Experiment → Run 组织：一次训练对应一个 Run，自动记录参数、指标、产物（模型/图表/标签）。

- **Experiment**：按工作空间隔离，命名 `ws_{workspaceId}/proj_{projectId}`。
- **Run**：训练启动时创建，结束写入 status；支持嵌套 Run（超参搜索父 Run + 子 Run）。
- **Tracking 后端**：PostgreSQL 存元数据（实验/运行/指标），artifact 存对象存储（经 StorageDriver）。

代码示例：训练追踪（Python）
```python
import mlflow, pyspark
mlflow.set_experiment("ws_12/proj_7")
with mlflow.start_run(run_name="rf_v1") as run:
    mlflow.log_params({"numTrees": 100, "maxDepth": 8})
    model = rf.fit(train_df)            # Spark MLlib 分布式训练
    mlflow.log_metric("auc", eval_auc)
    mlflow.spark.save_model(model, "models/rf_v1")   # artifact 入对象存储
```

> 客户不直接接触 Tracking Server 地址，控制台经封装层 REST 代理访问；SDK 模式下由封装层注入 `MLFLOW_TRACKING_URI`。

## 4. 模型注册与部署（Model Registry + Serving）

- **Registered Model**：一个模型名对应多条 Model Version，版本自增、不可覆盖。
- **Model Version 阶段**：None → Staging → Production → Archived，阶段切换留审计记录。
- **部署到 K8s**：将 Production 版本翻译为 KServe InferenceService CR，自动伸缩、灰度按版本流量比。

代码示例：注册与部署（Python）
```python
mv = mlflow.register_model("models:/rf_v1", "rf_credit_risk")
client.transition_stage_version("rf_credit_risk", mv.version, "Production")
# 封装层翻译为 InferenceService CR，暴露 /v2/models/rf_credit_risk/infer
```

## 5. 训练流程（Spark MLlib → MLflow → Registry → Serving）

```text
[控制台/SDK 提交训练]
        ▼
[封装层翻译为 SparkApplication CR + 注入 mlflow tracking uri]
        ▼
[Spark on K8s 调度到 GPU/NPU 节点池] ── MLlib 分布式训练（fit）
        ▼
[mlflow.log_params/log_metric/log_model] ── Run 落 PostgreSQL + artifact 落对象存储
        ▼
[mlflow.register_model + transition → Production] ── Registry 版本化
        ▼
[封装层翻译为 KServe InferenceService CR] ── 在线推理端点
        ▼
[L3.5 资产目录登记：模型即资产，血缘到训练数据集]
```

## 6. 接口契约（经封装层 REST）

```
POST /api/ml/v1/experiments                 { name } → 创建实验
POST /api/ml/v1/runs                        { experimentId, params } → 启动运行
GET  /api/ml/v1/runs/{id}/metrics           → [{metric, value, step}]
POST /api/ml/v1/models                      { name, sourceRunId } → 注册模型版本
POST /api/ml/v1/models/{m}/versions/{v}/stage  { stage } → 切换阶段
POST /api/ml/v1/deployments                 { model, version, replicas } → 部署到 K8s
GET  /api/ml/v1/deployments/{d}/predict     { payload } → 在线推理
```

> 所有接口经封装层鉴权与配额校验；推理端点对外暴露 KServe 路由，受 NetworkPolicy 与租户隔离约束。

## 7. 与 LLMOps（L4.5.5）的关系

L4.5.5 LLMOps 复用本模块的 Tracking/Registry 扩展，不另起炉灶：
- **追踪复用**：大模型训练/微调的 loss、eval、checkpoint 同样走 `mlflow.log_metric/log_artifact`。
- **注册复用**：大模型权重作为 Model Version 入 Registry，版本与阶段治理同传统 ML。
- **扩展点**：LLMOps 增加大模型专属 artifact 类型（adapter/LoRA 权重、tokenizer）、PEFT 微调作业翻译、vLLM 推理后端；本模块仅提供底座，大模型细节由 L4.5.5 承担。

## 8. 多环境适配

| 环境 | 训练节点 | 加速器 | Serving 后端 | 说明 |
| --- | --- | --- | --- | --- |
| 信创 | 国产 K8s 节点池 | 昇腾 NPU（CANN） | KServe + 国产推理 | MLlib 纯 CPU 训练 + NPU 推理适配 |
| 本地数据中心 | 自建 K8s 节点池 | NVIDIA GPU / 纯 CPU | KServe + Triton | 裸金属/虚机自建 |
| 公有云 VM | 客户自购 GPU 云主机 | 客户提供 GPU | KServe + Triton | **不绑云托管训练服务**，保持可迁移 |
| 私有云 | 私有云 K8s 节点池 | 厂商 GPU/NPU | KServe + Triton | 客户私有云 VM |

> 关键约束：训练作业始终翻译为 SparkApplication CR 跑在客户 K8s，绝不调用云厂商托管训练 API——保持四环境同构、不锁云。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| MLflow Tracking Server 单点 | 实验记录不可用 | 多副本部署 + PostgreSQL HA；artifact 已在对象存储不丢 |
| 大模型 artifact 体积大 | 注册/拉取慢 | 大权重直存对象存储，Registry 仅存指针；LLMOps 侧分块拉取 |
| GPU/NPU 资源争抢 | 训练排队 | 封装层按工作空间配额 + K8s 调度队列优先级 |
| 信创 NPU 与 MLlib 兼容 | 训练失败 | MLlib 训练纯 CPU；推理侧 NPU 适配由 L4.5.5 与封装层驱动探测 |
| 模型血缘断裂 | 治理盲区 | 训练 Run 强制关联数据集资产 ID，注册时回写 L3.5 血缘边 |
