# L0.9 可观测基座 · 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L0 云原生底座层
> 套餐：基础版（三档全含）
> 对标：kube-prometheus-stack / Grafana LGTM Stack / OpenTelemetry
> 关联：X3 统一运维观测（复用本层基础设施，叠加租户视图与 SLA 看板）；L0.6 SKE 控制面（节点级指标采集源）；L0.11 封装层（客户看板只显封装后视图）

## 1. 定位与价值

可观测基座是平台侧的**三位一体采集-存储-查询基础设施**：Prometheus（指标）+ Loki（日志）+ Tempo（链路）+ Grafana（统一查询面），以 kube-prometheus-stack 一体化部署于 SKE K8s 之上，**客户无感知、不可直连**。

平台价值：
- 引擎作业（Spark/Flink/Trino/Doris）的指标、日志、链路三路打通，平台运维一处定位。
- 采集存储与租户视图**解耦**——本层只做基础设施，X3 在其上叠加租户隔离、告警、SLA 看板。
- 四环境（信创/本地/公有云/私有云）同一套 Helm Chart，仅存储后端与节点 exporter 差异化。

客户价值（经 L0.11 封装后透出）：
- 故障可追溯——作业失败时链路-日志-指标一键关联，无需登录节点排查。
- 资源可观测——经 X3 看到租户维度用量与作业健康度，不暴露集群节点细节。

## 2. 总体架构

```text
┌──────── 采集层（DaemonSet / Deployment on K8s） ────────┐
│  node-exporter      kube-state-metrics      引擎 exporter   │
│  Promtail(日志)     OpenTelemetry SDK(链路)                  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── 存储层（平台侧，客户不可见） ────────┐
│  Prometheus(TSDB,指标15d)  Loki(日志30d)  Tempo(链路7d)    │
│  存储: SKE 本地 NVMe 加速查询 + 对象存储冷备               │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── 查询层（Grafana，仅平台运维可访问） ────────┐
│  Grafana DataSource: Prometheus/Loki/Tempo 三路统一面板    │
└──────────────────────┬──────────────────────────┘
                        ▼
                   X3 统一运维观测（叠加租户视图/告警/SLA）
```

## 3. 指标采集

采集源以 kube-prometheus-stack 为基，叠加引擎 exporter：

| 采集源 | 类型 | 关键指标 | 抓取间隔 |
| --- | --- | --- | --- |
| node-exporter | DaemonSet | CPU/MEM/磁盘 IO/网络/FS 使用 | 30s |
| kube-state-metrics | Deployment | Pod/Deployment/Job/PVC/ResourceQuota 状态 | 30s |
| kubelet/cAdvisor | 内置 | 容器 CPU/MEM/重启次数 | 30s |
| Spark Master/Worker Metrics | ServiceMonitor | 作业数/Task 失败/Executor 内存池 | 30s |
| Flink JobManager/TaskManager | ServiceMonitor | Checkpoint/反压/吞吐/算子水位 | 15s |
| Trino Coordinator | ServiceMonitor | 查询数/排队/执行时长/内存池 | 30s |
| Doris FE/BE | ServiceMonitor | QPS/导入速率/Compaction/BE 存活 | 30s |

> ServiceMonitor CR 按 namespace 自动发现，新引擎接入只需暴露 /metrics + 注册 ServiceMonitor。

## 4. 日志采集

Loki + Promtail 结构化日志，按 K8s namespace 物理隔离：

- **采集**：Promtail DaemonSet 挂载节点 /var/log/pods，按 namespace 打标签 `{namespace, pod, container, app}`。
- **结构化**：应用日志输出 JSON（含 trace_id/span_id 字段），Promtail json 解析后入 Loki，与 Tempo 链路 ID 对齐。
- **隔离**：Loki tenant_id = namespace，跨租户查询受 X3 鉴权网关约束；平台运维可全量检索。
- **过滤**：Promtail stages 剔除健康检查/Probe 噪声日志，降低存储与查询成本。

## 5. 链路追踪

Tempo + OpenTelemetry 跨引擎作业链路：

- **注入**：引擎作业提交时由平台注入 OTel SDK，SpanContext 经 Kafka Header / Spark TaskContext / Flink RPC 透传，跨 Spark→Trino→Doris 串联。
- **上报**：OTel Collector（Deployment）接收 OTLP，按采样率（默认 10%，错误 100%）入 Tempo。
- **关联**：Tempo span attributes 携带 `job_id/tenant_id/sql_id`，Grafana 链路面板可下钻到对应 Loki 日志（trace_id）与 Prometheus 指标（exemplars）。

## 6. 存储与保留

| 数据 | 后端 | 保留期 | 加速 |
| --- | --- | --- | --- |
| 指标 | Prometheus TSDB | 15 天（可配置） | SKE NVMe 本地存储 + 远程写 Thanos/对象存储长期 |
| 日志 | Loki chunks | 30 天（可配置） | NVMe 索引 + 对象存储 chunks |
| 链路 | Tempo blocks | 7 天（可配置） | NVMe 热块 + 对象存储冷块 |

> 保留期经 Helm values 配置；超期数据归档到统一存储（L2.1）对象桶，按环境 StorageDriver 切换后端。SKE NVMe 加速近 7 天热查询，冷数据走对象存储。

## 7. 与 X3 分工

| 职责 | 本层 L0.9 | X3 统一运维观测 |
| --- | --- | --- |
| 采集 | ✅ 全量基础设施采集 | ❌ 不重复采集 |
| 存储 | ✅ 三库存储与保留 | ❌ 不存数据 |
| 查询面 | Grafana（平台运维） | 租户看板（经 L0.11 封装，按 tenant 过滤） |
| 告警 | Prometheus Rule 基础告警 | 租户告警策略 + 通知渠道 + SLA 看板 |
| 租户隔离 | namespace 物理隔离 | 逻辑租户视图 + 配额告警 |

> 关键约束：本层 Grafana 仅平台运维可达；客户看板经 X3 + L0.11 封装，只显租户维度聚合视图，不暴露集群/Pod/节点细节。

### 7.1 接口契约（透出给 X3 的查询能力）

本层 Grafana/Prometheus/Loki/Tempo 不对客户直连，但对 X3 统一运维观测暴露**租户维度查询接口**，X3 在其上叠加鉴权、告警、SLA 看板。接口统一前缀 `/api/obs/v1/`，按指标/日志/链路三类划分：

表：L0.9 对 X3 透出的接口契约表

| 能力 | REST 端点（前缀 `/api/obs/v1/`） | 请求参数 | 响应 | 说明 |
| --- | --- | --- | --- | --- |
| 指标查询 | `POST /metrics/query` | `{ tenantId, query(PromQL), start, end, step }` | `{ result: [{ metric, values }] }` | X3 按 tenantId 过滤，仅返回该租户 namespace 指标；支持引擎作业指标（Spark/Flink/Trino/Doris） |
| 指标元数据 | `GET /metrics/metadata` | `{ tenantId }` | `[{ name, type, help }]` | 供 X3 构建看板指标选择器，仅暴露业务指标名（经 L0.11 翻译），不暴露 K8s 原生指标名 |
| 日志查询 | `POST /logs/query` | `{ tenantId, namespace, pod?, container?, start, end, limit }` | `{ entries: [{ ts, line, labels }] }` | Loki tenant_id = namespace 物理隔离；X3 鉴权网关校验 tenantId 范围 |
| 日志上下文 | `GET /logs/{traceId}/context` | - | `{ before, line, after }` | 按 trace_id 关联上下文日志，供故障下钻 |
| 链路查询 | `POST /traces/query` | `{ tenantId, serviceName?, operation?, start, end, limit }` | `{ traces: [{ traceId, spans }] }` | Tempo span attributes 携带 job_id/tenant_id/sql_id，按 tenantId 过滤 |
| 链路详情 | `GET /traces/{traceId}` | - | `{ spans: [{ spanId, parent, name, duration, attrs }] }` | 单链路详情，可下钻到对应 Loki 日志与 Prometheus exemplars |
| 告警规则 | `POST /alerts/rules` | `{ tenantId, rule, expr, severity }` | `{ ruleId }` | X3 代租户下发告警规则，本层 Prometheus Rule 执行 |
| 看板数据源 | `GET /datasources` | `{ tenantId }` | `[{ type, url, db }]` | 供 X3 嵌入 Grafana 面板，数据源按租户隔离 |

> 契约边界：本层只提供"按 tenantId 过滤后的查询能力"，不提供租户鉴权（X3 负责）、不提供看板布局（X3 负责）、不提供告警通知渠道（X3 负责）。本层 Grafana 仅平台运维可达，客户看板经 X3 + L0.11 封装。本节是 L0.9 与 X3 跨模块集成的契约基准。

## 8. 多环境适配

| 环境 | 节点 exporter | 存储后端 | 部署差异 |
| --- | --- | --- | --- |
| 信创 | 国产 OS node-exporter 兼容版 | 信创对象存储冷备 | 国产镜像 + 离线 Helm |
| 本地数据中心 | 标准 node-exporter | Ceph RGW / MinIO 冷备 | 裸金属 SKE |
| 公有云 VM | 标准 node-exporter | 客户云对象存储（S3/OBS/OSS）冷备 | **不启用云托管监控**，保持可迁移 |
| 私有云 | 标准 node-exporter | 厂商对象存储 / MinIO 冷备 | 客户私有云 K8s |

> 同一套 Helm Chart + values 覆盖四环境；云环境**只当冷备对象存储**，绝不启用云原生托管监控服务——避免锁云。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 高基数指标爆炸 | Prometheus 内存 OOM | label_keep 约束高基数 label；远程写 + 长期查走 Thanos |
| 日志量过大 | Loki 存储与查询成本高 | Promtail 过滤噪声 + 采样 + 按 namespace 保留分级 |
| 链路采样丢关键错误 | 故障定位缺链路 | 错误链路 100% 采样 + 日志 trace_id 兜底关联 |
| 跨引擎 SpanContext 透传断裂 | 链路不完整 | 引擎接入规范强制 OTel SDK + Header 透传契约 |
| 信创 node-exporter 兼容性 | 节点指标缺失 | 国产 OS 适配版 + 缺失指标降级告警 |
| 客户误连平台 Grafana | 越权看全集群 | NetworkPolicy + IAM 仅平台运维可达；客户走 X3 封装看板 |
