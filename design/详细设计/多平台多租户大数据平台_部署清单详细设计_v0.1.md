## 1. 铁律（不可破）

| # | 铁律 | 反例（禁止） |
| --- | --- | --- |
| 1 | K8s 一律自建，使用**自研 SKE 发行版（基于 kubeadm 二次封装）** | 启用云托管 K8s（ACK/EKS/TKE/CCE）；原样使用 KubeSphere/RKE2/k3s/kind |
| 2 | 四环境一套主代码 + Profile 驱动，业务代码零改动 | 为某环境写专属分支 |
| 3 | 客户无 K8s 概念，所有操作经封装层（L0.11）翻译 | 给客户暴露 kubeconfig / kubectl |

## 2. 部署拓扑

### 2.1 总体拓扑

```text
                客户（控制台 v0.3 / 运营后台 / 开放 API）
                              │
                              ▼
                  X4 APISIX 网关（南北向流量入口）
                              │
                              ▼
                  L0.11 封装层（业务语义翻译）
                              │
                              ▼
   ┌──────────────── K8s（自研 SKE 发行版，客户不可见）────────────────┐
   │                                                                  │
   │  控制面（3 节点 HA）: kube-apiserver / etcd / scheduler / cm      │
   │  CNI: Cilium（eBPF）  CSI: 国产/JuiceFS  可观测: Prom+Graf+Loki  │
   │                                                                  │
   │  数据面（按 arch/负载分节点池）:                                  │
   │    批池(Spark)  流池(Flink)  OLAP池(Doris)  即席池(Trino)        │
   │    时序池(IoTDB)  消息池(Kafka)  智能池(Milvus/Nebula/LLM)        │
   │                                                                  │
   │  存储层: 对象存储（XCObject/Ceph/S3/MinIO）+ Iceberg 表格式      │
   └──────────────────────────────────────────────────────────────────┘
```

### 2.2 自研 SKE 发行版（基于 kubeadm 二次封装）

| 维度 | 选型 | 说明 |
| --- | --- | --- |
| 上游 | Kubernetes v1.28+ | 保留上游兼容性与生态 |
| 封装 | 自研 SKE（Shuqing Kubernetes Engine） | 基于上游 K8s 二进制 + 深度调优 + 自研 installer，**非 KubeSphere/RKE2/k3s/kind 原样** |
| 交付 | 一组静态 Pod + ske-installer | 升级原子化，对客户不暴露 K8s 控制台 |
| 架构 | amd64 + arm64 多架构 | 信创 arm64（鲲鹏/飞腾）交叉编译 |
| 模式 | dev（kind） / prod（kubeadm 全量调优） | dev 用于本地，prod 用于客户交付 |

### 2.3 控制面 HA

- 3 节点 etcd 独立部署，独占 NVMe + CPU 核
- kube-apiserver 多副本 + keepalived + haproxy 提供 VIP
- 跨可用区反亲和，RTO ≤ 30s

## 3. 自研 SKE Bootstrap

### 3.1 SKE installer（基于 kubeadm 二次封装）

```text
ske-installer
  ├── preflight.sh          # 能力探测：arch/OS/存储/KMS/LB/国密
  ├── bootstrap.sh          # 调用 kubeadm init/join + 注入 SKE 调优
  ├── tuning/
  │   ├── kernel.sh         # 大页 + NUMA 绑核 + CPU 隔离 + sysctl
  │   ├── storage.sh        # NVMe 直通 + IO_uring + LocalPV
  │   └── controlplane.sh   # etcd 独占 + apiserver max-inflight
  ├── manifests/
  │   ├── cilium-values.yaml
  │   ├── scheduler-policy.yaml
  │   └── kubelet-config.yaml
  └── profiles/             # 四环境 Profile
      ├── xinchuang.yaml
      ├── onprem.yaml
      ├── publiccloud.yaml
      └── privatecloud.yaml
```

### 3.2 SKE 七大性能支柱（对应产品原型 §5.1.1）

| 支柱 | 调优内容 | 落地脚本 |
| --- | --- | --- |
| ① 内核调优 | 大页(2MB/1GB) + NUMA 绑核 + CPU 隔离 + 网络栈 sysctl | `tuning/kernel.sh` |
| ② 网络 eBPF | Cilium 取代 kube-proxy，绕过 iptables 慢路径 | `manifests/cilium-values.yaml` |
| ③ 存储 IO | NVMe 直通 + IO_uring + LocalPV；etcd 专属 NVMe | `tuning/storage.sh` |
| ④ 拓扑感知调度 | topologyKey=numa + single-numa-node + 自研数据本地性扩展器 | `manifests/scheduler-policy.yaml` |
| ⑤ 控制面隔离 | etcd 独立部署独占 NVMe+CPU；apiserver max-inflight=3000/2000 | `tuning/controlplane.sh` |
| ⑥ 组件精简 | 移除 cloud-provider、非必要 addon、关闭未用特性门 | `manifests/kubelet-config.yaml` |
| ⑦ 封装收敛 | SKE 不直接暴露给客户；由封装层(L0.11)翻译 | 见 §11 |

### 3.3 HA 方案

| 组件 | 方案 | 副本数 |
| --- | --- | --- |
| kube-apiserver | 多副本 + keepalived VIP | 3 |
| etcd | 独立集群，独占 NVMe | 3 |
| scheduler / controller-manager | 多副本选主 | 3 |
| Ingress (X4 APISIX) | 多副本 + haproxy LB | 3 |

### 3.4 etcd 调优

- `--auto-compaction-retention=1`
- `--quota-backend-bytes=8589934592`（8Gi）
- `heartbeat-interval=250` / `election-timeout=2500`
- 独占 NVMe 盘，IO_uring 启用

### 3.5 安全加固

- kubelet 匿名访问关闭，只允许客户端证书
- RBAC 强制开启，默认 deny
- PodSecurityPolicy → Pod Security Standards admission（restricted）
- 审计日志开启，写入独立 PV，保留 90 天

## 4. 多环境适配（四环境 Profile）

### 4.1 Profile 差异表

| 维度 | xinchuang（信创） | onprem（本地） | publiccloud（公有云） | privatecloud（私有云） |
| --- | --- | --- | --- | --- |
| 算力架构 | 鲲鹏(ARM64)/海光(x86)/飞腾 | x86 为主 | 云实例(多 arch) | 厂商 x86/ARM |
| OS | openEuler/麒麟/统信 | CentOS/RHEL/Ubuntu | 云定制内核 OS | 厂商 OS |
| 镜像变体 | openeuler | rocky | ubuntu | 厂商 OS |
| 存储驱动 | XCObjectDriver | CephDriver | S3Driver（客户提供密钥） | PrivateDriver(MinIO) |
| 网络/LB | Cilium + MetalLB | Cilium + 硬件 LB | 云 CNI + 云 LB | 厂商 CNI + HAProxy |
| KMS/加密 | 国密卡(SM2/3/4)+国产 KMS | Vault/自研 KMS | 自托管 KMS（弱绑定云） | 自托管/厂商 KMS |
| 国密 | SM3 哈希启用 | 标准 | 标准 | SM4 启用 |
| 身份 | Keycloak + LDAP | Keycloak/LDAP | Keycloak（自托管） | Keycloak/厂商 IAM |
| 弹性 | 固定节点池 | 固定+Cluster Autoscaler | 自建节点池（可选调云 API） | 自建节点池（可选调云 API） |
| 可观测 | 自托管 Prometheus | 自托管 | 自托管/云监控 | 自托管 |
| K8s 形态 | **自研 SKE 发行版** | **自研 SKE 发行版** | **自研 SKE 发行版** | **自研 SKE 发行版** |

> 公有云环境铁律：`S3Driver` 仅消费客户在公有云自购 VM 上的对象存储，**不启用任何云托管 K8s / RDS / Kafka**。

### 4.2 Profile 加载机制

```text
部署时: ske-installer --profile xinchuang
  → 加载 profiles/xinchuang.yaml
  → 渲染 Helm values overlay
  → 调用 kubeadm init + 注入 SKE 调优
  → 安装 CNI/CSI/可观测
  → 按 §8 顺序部署业务 Chart
```

### 5.2 资源配额关系

> Helm values 中的 `quota` 是 **Namespace 级平台配额**（该引擎在整个 Namespace 内可用的资源上限），§11.5.2 是**每租户默认配额**。关系：`平台配额 ≥ Σ(租户配额)`。一个集群可承载多租户。

## 6. 多 Arch 镜像构建 CI

### 6.1 构建流水线（build-images.yaml）

```yaml
# .github/workflows/build-images.yaml（节选）
jobs:
  build-multi-arch:
    strategy:
      matrix:
        arch: [amd64, arm64]
        variant: [ubuntu, rocky, openeuler]  # 信创 openeuler 仅 arm64 交叉编译
    steps:
      - uses: docker/setup-qemu-action        # arm64 交叉编译
      - uses: docker/setup-buildx-action
      - run: |
          docker buildx build \
            --platform linux/${{ matrix.arch }} \
            --build-arg BASE_IMAGE=${{ matrix.variant }} \
            -t registry.shuqing.local/spark:3.5.1-${{ matrix.variant }}-${{ matrix.arch }} \
            --push .
      - run: docker manifest create ...        # 合并 multi-arch manifest
```

## 11. X4 与 L2.7 职责边界（P2-E5 修复）

> 原文档未澄清 X4 API 网关与 L2.7 统一 SQL 网关的关系，导致误认为是同一组件。本节明确两者职责边界。

### 11.1 职责对比

| 维度 | X4 APISIX（南北向流量） | L2.7 统一 SQL 网关（东西向查询联邦） |
| --- | --- | --- |
| 流量方向 | 南北向：外部用户 → 平台 API | 东西向：SQL → 多引擎 |
| 入口 | 客户/控制台/运营后台/开放 API | 统一 SQL 查询入口 |
| 出口 | 平台内各服务（控制台/运营/SQL 网关/IDE/BI） | Spark/Flink/Trino/Doris/Iceberg |
| 核心能力 | 鉴权/限流/灰度/计量/路由/SSL 卸载 | SQL 解析/联邦优化/查询路由/结果合并/权限下推 |
| 协议 | HTTP/HTTPS/gRPC | SQL（JDBC/REST） |
| 状态 | 无状态 | 无状态（含查询执行 Pod 池） |
| 选型 | Apache APISIX 3.8 | 自研（Calcite/ANTLR） |

### 11.2 协作流程

```text
客户提交 SQL 查询:
  客户 → X4 APISIX（鉴权/限流/计量）
       → L2.7 统一 SQL 网关（解析/联邦优化/路由）
            → Spark/Trino/Doris/Iceberg（执行）
       ← 合并结果 + 权限脱敏下推
  ← 返回结果给客户
```

### 11.3 路由规则

| API 路径 | X4 路由到 | 说明 |
| --- | --- | --- |
| `/api/v1/sql/submit` | L2.7 统一 SQL 网关 | SQL 查询入口 |
| `/api/v1/workspaces/*` | L0.11 封装层 | 工作空间管理 |
| `/api/v1/console/*` | L5.1 控制台后端 | 控制台 API |
| `/api/v1/ops/*` | L5.2 运营后台 | 运营 API |
| `/api/v1/assets/*` | L3.5 资产目录（L5.1 内） | 资产检索/申请 |
| `/api/v1/ide/*` | L4.3 Theia IDE | 在线开发 |
| `/api/v1/bi/*` | L4.4 Superset | BI 看板 |
| `/api/v1/open/*` | L5.5 开放 API | 对外服务目录 |
