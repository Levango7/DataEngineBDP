# X3 统一运维观测 · 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · X 横切能力层
> 对标：kube-prometheus-stack / Grafana LGTM Stack / Datadog（租户视图）
> 关联：L0.9 可观测基座（复用基础设施）；L0.11 封装层（客户看板过滤）；L5.2 运营后台（全局监控）；L2.* 引擎（指标采集）；X2 安全审计（审计日志接入）
> 适用版本：基础版✅ / 标准版✅ / 旗舰版✅（全版本开放，对照 §11.5 套餐模块矩阵）

## 1. 定位与价值

统一运维观测是平台的**唯一可观测出口**：以 Prometheus + Grafana + Loki + Tempo + Alertmanager 承载指标/日志/链路/告警四维数据，平台方看全局水位、客户方只看业务健康。

客户价值：
- "业务健康一目了然"——封装层过滤底层 Pod/节点噪声，看板只显作业成功率、查询时延、SLA 达成。
- "故障可追溯"——跨引擎作业全链路（Spark→Trino→Doris）一键钻取，日志链路联动。
- "告警不打扰"——分级告警，客户只收业务级，平台级告警进运营后台。

平台价值：
- 一套 kube-prometheus-stack 部署于 K8s，四环境同构，复用 L0.9 可观测基座。
- 指标按租户 label 隔离，Loki 按 tenant 标签分片，多租户观测互不越权。

## 2. 总体架构

```text

│  kube-state-metrics  node-exporter  引擎 Exporter  业务埋点  │

                        ▼
┌──────── 存储层（on K8s） ────────┐
│  Prometheus(TSDB,指标)  Loki(对象存储后端,日志)  Tempo(对象存储后端,链路)  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── 查询/告警层 ────────┐
│  Grafana(统一看板)  Alertmanager(分级路由)  统一查询 API  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── 视图层（双视图） ────────┐
│  平台方：运营后台(L5.2) 全局集群/租户水位                          │
│  客户方：封装层(L0.11) 看板 仅显业务健康/SLA，过滤底层噪声          │
└──────────────────────────────────────────────────┘
```

## 3. 指标体系

**平台指标**（平台方可见，客户不可见）：
- 集群级：节点数、CPU/内存利用率、K8s 调度延迟、PV 容量/IO。
- 节点级：磁盘 IO、网络吞吐、内核负载、Pod 重启次数。
- Pod 级：容器 OOM、CrashLoopBackOff、HPA 弹性伸缩计数。

**业务指标**（按租户 label `tenant_id` 隔离，客户可见）：
- 作业指标：成功率、失败数、运行时长、排队数（Spark/Flink/Doris 作业）。
- 查询指标：QPS、P50/P99 时延、慢查询数（Trino/Doris）。
- 存储指标：湖仓表大小、增量速率、compaction 耗时（接 L2.1）。
- SLA 指标：可用性 SLO、查询时延 SLO、作业成功率 SLO，按租户独立计算。

> 隔离方式：Prometheus 通过 `tenant_id` label 区分；Grafana 数据源加 `{tenant_id="$tenant"}` 变量过滤；封装层注入租户上下文，跨租户查询拒绝。

## 4. 日志体系

- **统一日志**：Loki 收集 K8s Pod 日志 + 引擎日志（Spark/Flink/Trino/Doris），Promtail 采集。
- **租户隔离**：Loki 按 `tenant_id` 标签分片，查询强制带租户标签，跨租户日志不可见。
- **审计日志**：操作审计（建表/删表/授权/作业提交）由 X2 安全审计模块产生，独立 Loki stream，保留期 ≥ 180 天，仅运营后台可查。
- **日志分级**：ERROR/WARN 进 Alertmanager 触发告警；INFO/DEBUG 仅查询用，TTL 30 天。

## 5. 链路追踪

- **Tempo** 存储链路数据，后端复用对象存储（与 L2.1 同 StorageDriver）。
- **跨引擎全链路**：作业提交 → Spark 执行 → Trino 查询 → Doris 在线服务，OpenTelemetry SDK 注入 traceId，Tempo 串联。
- **排障联动**：Grafana 看板异常点 → Tempo 钻取链路 → Loki 关联同 traceId 日志，三联动定位根因。
- **采样策略**：正常链路 1% 采样，错误/慢链路 100% 采样，控制存储成本。

## 6. 告警体系

**分级告警**（Alertmanager 路由）：

| 级别 | 触发源 | 路由目标 | 客户可见 |
| --- | --- | --- | --- |
| P0 紧急 | 集群不可用/数据丢失 | 平台 OnCall + 工单 + IM | 否（仅运营后台） |
| P1 严重 | 节点宕机/作业大面积失败 | 平台运维 + 工单 | 否 |
| P2 业务 | 租户作业失败/SLA 违约 | 客户 IM/邮件 + 工单 | 是（看板"服务异常"） |
| P3 提醒 | 慢查询/存储水位 80% | 客户看板提示 | 是（看板"水位提醒"） |

> 客户看板只显"服务健康/异常/水位提醒"三态，不暴露 Pod/节点细节；P0/P1 平台内部消化，不打扰客户。

## 7. 接口契约

```
GET  /api/obs/v1/dashboards                → [{id, name, scope:platform|tenant}]
GET  /api/obs/v1/dashboards/{id}/render    { timeRange, tenantId } → 看板快照
GET  /api/obs/v1/metrics/query             { promql, tenantId }    → [{ts, value}]
GET  /api/obs/v1/logs/query                { logql, tenantId, limit } → [logLine]
GET  /api/obs/v1/traces/{traceId}          → 跨引擎全链路详情
GET  /api/obs/v1/alerts                    { tenantId, severity }  → [alert]
POST /api/obs/v1/alerts/rules              { tenantId, expr, severity } → 建租户告警规则
```

> 所有查询接口经封装层鉴权，强制注入 `tenantId`，跨租户访问返回 403。

## 8. 多环境适配

| 环境 | 部署方式 | 后端存储 | 说明 |
| --- | --- | --- | --- |
| 信创 | kube-prometheus-stack on SKE | 国产对象存储 + 本地 PV | 国产 Exporter 适配 |
| 本地数据中心 | 同上 | Ceph RGW / MinIO | 裸金属/虚机自建 |
| 公有云 VM | 同上 | 客户云对象存储（S3/OSS） | **客户提供密钥，不绑云托管监控** |
| 私有云 | 同上 | 厂商对象存储 / MinIO | 客户私有云 VM |

> 关键约束：云环境只用"裸对象存储"做 Loki/Tempo 后端，绝不启用云原生监控托管服务——保持可迁移、不锁云。四环境 kube-prometheus-stack 配置同构，差异仅在 StorageDriver Profile。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 指标基数爆炸（多租户高基数） | Prometheus 查询慢/OOM | label 保持低基数，按租户分片 Prometheus，长留存转 VictoriaMetrics |
| Loki 查询跨租户泄露 | 数据越权 | 查询强制带 tenant_id 标签，封装层鉴权注入 |
| 链路存储成本高 | 对象存储膨胀 | 采样策略 + TTL 7 天 + 错误链路独立保留 30 天 |
| 客户看板暴露底层细节 | 体验混乱/越权 | 封装层白名单字段过滤，只显业务语义指标 |
| 信创 Exporter 兼容性 | 指标缺失 | 适配层做能力探测，缺失指标降级或自研 Exporter |

## 10. 与 UI 的对应

控制台 v0.3「运维观测」页（租户看板：作业健康/查询时延/SLA/水位提醒）、运营后台「全局监控」页（集群/节点/全租户水位/P0-P1 告警）、告警中心（分级列表 + 工单联动）均基于此模块。本文件是其观测侧契约依据。
