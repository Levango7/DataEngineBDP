# L2.9 时序引擎（IoTDB 2.0）· 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L2 大数据引擎层
> 适用套餐：旗舰版（基础版、标准版不含，对齐 §11.5.1 套餐矩阵）
> 对标：Apache IoTDB 2.0（国产开源，清华主导）/ InfluxDB / TDengine
> 关联：L2.7 统一 SQL 网关（IoTDB SQL 方言适配）；L2.1 统一存储（冷数据降采样归档 Iceberg 湖）；L4.1 数据集成（IoTDB 作为源/汇）；L0.11 封装层（配额/隔离）

## 1. 定位与价值

时序引擎是面向**工业/物联网场景**的选配模块（旗舰版可选），以 Apache IoTDB 承载高写入吞吐、低延迟查询的时序数据，与湖仓集一体存储形成互补——结构化批/流走 Iceberg/Doris，高频时序点位走 IoTDB。

客户价值：
- "工业数据直采"——设备测点经 MQTT/OPC UA 实时入 IoTDB，毫秒级点位写入。
- "时序 SQL 透明"——经统一 SQL 网关以 IoTDB 方言查询，对工业用户零学习成本。
- "降采样归档"——冷数据自动降采样后归档到 Iceberg 湖，热温冷分层。

平台价值：
- 选型 Apache IoTDB（国产开源、清华主导），**信创适配好**，四环境同构部署。
- IoTDB on K8s（StatefulSet）由 SKE 发行版承载，客户无感知 K8s 复杂度。
- 定位选配模块，非工业场景可不启用，平台核心不依赖。

```text
└──────────────────────┬──────────────────────────┘

└───────────────────────────────────────────────────────────┘
```

## 3. 数据模型

IoTDB 采用**时间序列树**模型：`root.存储组.设备.测点`，每条记录 = `(时间戳, 测点值)`。

```text
root
 └─ factory01            (存储组 sg)
    └─ lineA             (设备)
       ├─ temperature    (测点, FLOAT)
       ├─ pressure       (测点, FLOAT)
       └─ status         (测点, INT32)
```

示例数据（一台设备多测点对齐写入）：

| time | root.factory01.lineA.temperature | root.factory01.lineA.pressure | root.factory01.lineA.status |
| --- | --- | --- | --- |
| 2026-08-03 10:00:00.000 | 75.3 | 1.21 | 1 |
| 2026-08-03 10:00:01.000 | 75.5 | 1.20 | 1 |
| 2026-08-03 10:00:02.000 | 75.4 | 1.22 | 0 |

> 与关系模型区别：以"设备-测点-时间戳"为索引，列存 + 时间局部性，写入顺序追加、查询时间范围扫描，适配高频写入与时间窗口聚合。

## 4. 接口契约（内部 / 经网关）

IoTDB 原生提供 **IoTDB SQL** 与 **Session API** 两类接口，平台统一收敛到 L2.7 网关：

```
-- IoTDB SQL（经统一 SQL 网关，方言=iotdb）
SELECT temperature FROM root.factory01.lineA
  WHERE time >= 2026-08-03T10:00:00 AND time < 2026-08-03T11:00:00;

-- 降采样查询（内置 UDF）
SELECT max_value(temperature) FROM root.factory01.lineA
  GROUP BY ([2026-08-03T00:00:00, 2026-08-04T00:00:00), 1h);
```

```
// Session API（数据集成 L4.1 调用，批量写入）
POST /api/ts/v1/sessions/{sid}/insertRecords
  { deviceId:"root.factory01.lineA",
    measurements:["temperature","pressure"],
    timestamps:[...], values:[...] }
POST /api/ts/v1/ttl                    { sg:"root.factory01", ttl:"90d" }
```

> 客户不直连 IoTDB；写入经 L4.1 采集 Agent，查询经 L2.7 统一 SQL 网关，由封装层做租户隔离与配额校验。

## 5. 关键流程

```text
设备点位 ──MQTT──▶ Edge Agent ──批量──▶ IoTDB Session API
                                              │
                          ┌───────────────────┼───────────────────┐
                          ▼                   ▼                   ▼
                     WAL(持久)          排写缓存(内存)        TsFile(列存)
                          └───────────────────┴───────────────────┘
                                              ▼
                          统一 SQL 网关 ──查询/降采样──▶ 结果 / 归档 Iceberg
                                              ▼
                          TTL 自动清理过期点位（按存储组）
```

1. **写入**：Edge Agent 聚合点位 → Session API 批量 insertRecords → WAL 持久化 + 排写缓存。
2. **存储**：内存表 flush 为 TsFile（列存、时间局部性），DataNode 横向扩容按存储组分片。
3. **查询**：统一 SQL 网关路由 IoTDB SQL，支持时间范围、降采样 UDF、对齐 ALIGN。
4. **降采样归档**：定时任务将分钟/小时粒度聚合结果写入 L2.1 Iceberg 湖，IoTDB 仅留热温数据。
5. **TTL 清理**：按存储组设置存活时间，过期数据自动删除，控制存储增长。

## 6. 资源与调优

| 维度 | 配置 | 说明 |
| --- | --- | --- |
| 写入吞吐 | DataNode 副本数、排写缓存、批量大小 | 单节点百万点位/秒，横向扩 DataNode |
| 存储加速 | SKE NVMe 本地盘承载 TsFile | StatefulSet 绑本地 NVMe，避免对象存储写放大 |
| TTL | 按存储组设存活期（如 90d） | 自动清理过期点位，控制 TsFile 增长 |
| 查询 | 时间范围下推、降采样 UDF、对齐 | 避免全表扫描，结果集对齐到统一时间轴 |
| 资源隔离 | ConfigNode/DataNode 独立 ResourceQuota | 受 L0.11 封装层工作空间配额约束 |

> 关键：IoTDB TsFile 优先落 SKE 本地 NVMe（低延迟、高 IOPS），冷数据经降采样归档 Iceberg 湖（对象存储），热温冷分层不冗余。

## 7. 多环境适配

| 环境 | 部署形态 | 存储后端 | 说明 |
| --- | --- | --- | --- |
| 信创 | IoTDB on SKE K8s（StatefulSet） | 国产本地盘 / 信创存储 | 国产 OS + 国产 CPU，IoTDB 信创认证 |
| 本地数据中心 | IoTDB on SKE K8s | Ceph RBD / 本地 NVMe | 裸金属/虚机自建 |
| 公有云 VM | IoTDB on SKE K8s | 云块存储（客户自购） | **客户提供存储，不绑云托管时序服务** |
| 私有云 | IoTDB on SKE K8s | 厂商块存储 / 本地盘 | 客户私有云 VM |

> 关键约束：四环境 IoTDB 部署形态、SQL、Session API 完全一致；云环境只用"裸块存储"，绝不启用云托管时序数据库——保持可迁移、不锁云。选配模块按需启用，非工业场景不部署。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 写入峰值打满 DataNode | 写入延迟、丢点位 | Edge Agent 端缓冲 + 批量 + 背压；横向扩 DataNode |
| TsFile 膨胀 | 存储占用高、查询变慢 | TTL 自动清理 + 定时 compaction 合并 TsFile |
| 冷数据查询慢 | 长周期分析体验差 | 降采样归档 Iceberg 湖，长周期走 Trino 查 Iceberg |
| 信创硬件性能差异 | 吞吐不达标 | SKE NVMe 加速 + 压测基线 + DataNode 扩容 |
| 选配模块运维负担 | 非工业客户误启用 | 控制台显式开关，默认不部署，仅旗舰版可选 |
