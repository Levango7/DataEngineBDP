# L2.2 批计算（Spark 3.5）· 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L2 大数据引擎层
> 适用套餐：标准版、旗舰版（基础版不含，对齐 §11.5.1 套餐矩阵）
> 对标：Apache Spark 3.5 on Kubernetes / 星环 Inceptor / Databricks Runtime（开源对齐）
> 关联：L2.1 统一存储（读写 Iceberg）；L2.7 统一 SQL 网关（经网关提交重批作业）；L0.11 封装层（翻译为 SparkApplication CR）；L4.2 调度编排（DolphinScheduler 调度 Spark 作业）

## 1. 定位与价值

批计算是平台的**通用重计算底座**：承担批 ETL、离线数仓构建、ML 训算与大规模数据加工；以 Spark 3.5 on K8s 形态运行，读写统一存储 Iceberg，作业经封装层翻译为客户无感的"任务"。

客户价值：
- "提交即跑"——客户在数据开发页提交 SQL/PySpark/Scala 作业，无需感知 K8s/Spark Operator。
- "一份数据加工"——Spark 直接读写 Iceberg，无中间搬运，结果立即可被 Trino/Doris 查询。
- "四环境同代码"——信创 ARM 到公有云 x86，作业代码与 SQL 零改动，仅镜像变体与存储驱动差异。

平台价值：
- Spark 3.5 属 Java 生态，**ARM/x86 原生支持**，信创适配零障碍。
- 作业全经 Spark Operator → SparkApplication CR，统一调度、监控、配额、隔离。
- 与 SKE 拓扑调度联动，executor 优先调度到数据所在节点，感知数据本地性。

## 2. 总体架构

```text
┌──────── 客户入口（不暴露 K8s） ────────┐
│  数据开发(IDE/SQL)   L4.2 调度编排   L2.7 统一SQL网关(重批)  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── L0.11 封装层（工作空间/项目/任务 → Namespace/Quota/SparkApplication CR） ────────┐
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── Spark Operator on K8s（监听 SparkApplication CR） ────────┐
│  Driver Pod（per 作业） → 拉起 Executor Pod（动态分配）            │
│  镜像变体：spark-x86 / spark-arm（信创） / spark-gpu(ML 可选)      │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── Spark 3.5 引擎（SQL / DataFrame / MLlib / Structured Streaming micro-batch） ────────┐
│  Catalog: RestCatalog → L2.1 Iceberg   执行: AQE + DPP + 向量化 Parquet 读  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── L2.1 统一存储（对象存储 + Iceberg，StorageDriver 屏蔽四环境后端） ────────┐
└──────────────────────────────────────────────────────┘
```

## 3. 引擎抽象与 K8s 集成

- **Spark Operator**：部署于平台系统 Namespace，监听各租户 Namespace 下的 `SparkApplication` CR，按 spec 拉起 Driver/Executor Pod，作业结束自动回收。
- **CRD（SparkApplication）核心字段**：

| 字段 | 说明 |
| --- | --- |
| spec.type | Batch / Streaming(micro-batch) |
| spec.mainApplicationFile | 作业 jar/py/sql 在对象存储路径 |
| spec.driver.cores/memory | Driver 资源 |
| spec.executor.cores/memory/instances | Executor 资源与初始数 |
| spec.dynamicAllocation | 启用动态分配（min/max shuffleTracking） |
| spec.nodeSelector/affinity | SKE 拓扑调度注入数据本地性 |
| spec.image | 镜像变体（x86/arm/gpu）按环境 Profile 选 |

- **提交流程**：封装层把客户"任务"翻译为 SparkApplication CR `kubectl apply` 到租户 Namespace；Operator reconcile 拉起 Pod；状态回写 CR `.status` 由封装层映射为"任务运行/成功/失败"。

## 4. 与统一存储集成

- **Catalog 接入**：Spark 配置 `spark.sql.catalog.lake = org.apache.iceberg.spark.SparkCatalog`，`type=rest`，指向 L2.1 RestCatalog 服务；建表/读写均经 catalog，不直连对象存储路径。
- **读写 Iceberg**：`INSERT/OVERWRITE` 写 Iceberg（ACID 快照）；`SELECT` 走 manifest 短路读，Time Travel 支持 `FOR VERSION AS OF` / `FOR TIMESTAMP AS OF`。
- **分区策略**：按 `dt`（日）+ `hour` 隐藏分区，Iceberg Hidden Partitioning 自动注入，客户 SQL 不写分区列；大表 compaction 由 L4.2 定时触发 Spark 作业合并小文件。
- **ML 集成**：MLlib 训练数据读 Iceberg DataFrame，模型写出回对象存储（按 workspace 隔离前缀）。
- **流批一体**：Structured Streaming micro-batch 模式复用同一 SparkApplication CR（`type=Streaming`），checkpoint 写对象存储，与 Flink（L2.3）分工——Spark 管微批回填/ML，Flink 管实时 CDC。

## 5. 接口契约（经封装层 / 统一 SQL 网关）

```
POST /api/batch/v1/jobs                  { workspace, project, type, mainFile, args, resources } → jobId
GET  /api/batch/v1/jobs/{id}             → { status, driverLog, executorStats, duration }
POST /api/batch/v1/jobs/{id}/stop        → 优雅停止（driver SIGTERM）
POST /api/batch/v1/sql                   { sql, warehouse } → 经网关路由 Spark 执行重批 SQL
GET  /api/batch/v1/jobs/{id}/metrics     → { shuffleRead, shuffleWrite, spill, gcTime }
```
> 客户不直接操作 SparkApplication CR；REST 经 L0.11 封装层鉴权/配额/翻译，重批 SQL 经 L2.7 网关路由。

## 6. 关键流程

```text
客户提交任务 → 封装层鉴权+配额校验 → 生成 SparkApplication CR → apply 到租户 Namespace
   → Spark Operator reconcile → Driver Pod → 拉起 Executor Pod（动态分配）
   → Driver 注册 RestCatalog → 读 Iceberg manifest → 执行 DAG（AQE/DPP 优化）
   → 写 Iceberg 新快照 → commit → 状态回写 CR → 封装层映射为"成功" → 通知客户
```
1. **提交**：客户经数据开发/调度/SQL 网关任一入口提交，统一收敛到封装层。
2. **调度**：L4.2 DolphinScheduler 按 DAG/定时触发，调用上述 REST。
3. **执行**：SKE 拓扑调度把 executor 调度到数据所在节点，减少跨节点 IO。
4. **结果写出**：写 Iceberg 快照，元数据 commit 后立即可被 Trino/Doris 查询。

## 7. 资源与调优

- **Executor 配置**：默认 `cores=3, memory=8G`（对齐 spark-values.yaml `executor.cores: 3`），按作业类型模板（ETL/ML/SQL）预设；客户可在"任务"页调整，受工作空间 Quota 上限约束。套餐分档：基础版 cores=2 / 标准版 cores=3 / 旗舰版 cores=4（对应 spark-values.yaml tierProfiles）。
- **动态分配**：`dynamicAllocation.enabled=true`，`minExecutors=1, maxExecutors=受Quota`，`shuffleTracking.enabled=true`（K8s 模式必需）。
- **AQE + DPP**：Spark 3.5 默认开启自适应查询执行与动态分区裁剪，大 join 自动 broadcast/smj 切换。
- **SKE 拓扑调度**：Operator 注入 `podAntiAffinity` + 数据本地性 hint，SKE 调度器感知 Iceberg 文件所在节点优先调度 executor，跨节点读下降 30%+。
- **ML**：MLlib/Spark RAPIDS（可选 gpu 镜像）按需启用，资源独立 Quota 池。

## 8. 多环境适配

| 环境 | 镜像变体 | 存储驱动 | 作业代码改动 |
| --- | --- | --- | --- |
| 信创（ARM） | spark-arm（国产 JDK/原生 ARM） | XCObjectDriver | 零 |
| 本地数据中心 | spark-x86 | CephDriver | 零 |
| 公有云 VM | spark-x86 | S3Driver（客户密钥） | 零 |
| 私有云 | spark-x86 / spark-arm | PrivateDriver | 零 |

> 差检：四环境跑同一份 TPC-DS/TPC-ML 回归套件，结果偏差 < 5% 视为一致。差异只在镜像变体与 StorageDriver，作业代码、SQL、Catalog 配置完全相同。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Driver 单点 | 作业失败全丢 | K8s 重启 Driver Pod（restartPolicy），Checkpoint 支持 Streaming 恢复 |
| Executor 漂移 | 数据本地性丢失 | SKE 拓扑调度 + podAntiAffinity，executor 优先数据所在节点 |
| 大 shuffle 溢出 | OOM/慢 | 动态分配 + shuffle spill 监控，告警阈值自动扩 maxExecutors |
| 镜像变体不一致 | 跨环境结果偏差 | 统一构建基线 + 四环境 TPC-DS 回归门禁 |
| 信创 ARM 性能 | 较 x86 慢 | 国产 JDK + 向量化读 + 调优 executor 并发，benchmark 对齐 |
| 作业爆炸影响平台 | 资源抢占 | per-租户 Quota + PriorityClass + NetworkPolicy 隔离 |
| 小文件读放大 | 扫描慢 | 读走 Iceberg manifest 短路 + 定时 compaction 合并 |

## 10. 与 UI 的对应

控制台 v0.3「数据开发」页（SQL/PySpark/Scala 作业提交、运行日志、metrics 可视化）、「调度编排」页（DolphinScheduler DAG 节点即 Spark 作业）、工作台"运行中任务 / 资源用量 / Executor 数"均基于此模块。本文件是其批计算侧契约依据，客户视角只见"任务"与"运行结果"，不暴露 SparkApplication CR / Pod / K8s。
