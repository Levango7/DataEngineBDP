# L4.5.1 标签画像 · 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L4 数据开发与分析层
> 对标：阿里 DataPhin 标签画像 / 神策用户标签 / GrowingIO 圈选
> 关联：L2.5 OLAP/Doris（标签宽表、毫秒级圈选）；L2.2 Spark（标签计算 ETL）；L3.5 资产目录（标签即资产）；L0.11 封装层
> 适用版本：标准版✅ / 旗舰版✅（基础版❌，对照 §11.5 套餐模块矩阵）

## 1. 定位与价值

标签画像模块是**业务人员自助运营**的入口：将湖仓中分散的用户/商品行为数据，沉淀为可读、可圈选、可画像的标签宽表，支撑毫秒级人群圈选与画像导出。

客户价值：
- "业务自助圈人"——运营/营销人员 SQL 拖拽即可圈选目标人群，无需提需求给数据开发。
- "标签即资产"——标签纳入 L3.5 资产目录，可申请、可授权、可血缘追溯。
- "毫秒级响应"——Doris 标签宽表 + 向量化执行，千万级用户圈选 < 500ms。

平台价值：
- 复用 L2.5 Doris + L2.2 Spark，**无独立引擎**，K8s 部署零增量。
- 标签计算与圈选全经封装层收敛，租户隔离、配额受限、客户无感知底层。

## 3. 标签模型

标签按生产方式分三类：

| 类型 | 来源 | 产出方式 | 示例 |
| --- | --- | --- | --- |
| 事实标签 | 湖仓事实表 | 直接字段映射 | 注册天数、最近下单时间 |
| 规则标签 | 业务规则配置 | SQL 规则匹配 | 高频用户（30 日下单≥5）、流失预警 |
| 挖掘标签 | 算法模型 | Spark MLlib 离线训练 | 价格敏感度、品类偏好簇 |

标签宽表（Doris，按 `user_id` 主键聚合，列存）：

```sql
-- SQL：标签宽表建表
CREATE TABLE dws_user_tag_wide (
  user_id        BIGINT,
  tenant_id      INT,
  -- 事实标签
  reg_days       INT,
  last_order_ts  DATETIME,
  total_amount   DECIMAL(18,2),
  -- 规则标签（枚举编码）
  user_level     TINYINT,    -- 1新 2活 3沉 4流
  churn_risk     TINYINT,
  -- 挖掘标签
  price_sens     TINYINT,    -- 1低 2中 3高
  cate_cluster   INT,
  -- 更新元信息
  tag_version    STRING,
  update_ts      DATETIME
) ENGINE=OLAP
DUPLICATE KEY(user_id, tenant_id)
PARTITION BY RANGE(tenant_id)()
DISTRIBUTED BY HASH(user_id) BUCKETS 32
PROPERTIES("replication_num"="3");
```

## 4. 标签计算

Spark ETL 从湖仓 Iceberg 读事实数据，按标签定义计算后批量写入 Doris 宽表。

```text
┌──────────────── 图：标签计算流程图 ────────────────┐
│  Iceberg 事实表 ──→ Spark 读入 DataFrame            │
│        │                                            │
│        ├──→ 事实标签：字段直选/聚合                  │
│        ├──→ 规则标签：SQL 规则匹配（DSL→SQL）       │
│        └──→ 挖掘标签：加载模型预测                  │
│        │                                            │
│        ▼                                            │
│  标签列拼接（按 user_id 聚合） ──→ Stream Load 写 Doris │
└────────────────────────────────────────────────────┘
```

调度：标签定义变更触发增量计算；全量重算按日定时（凌晨低峰）。挖掘标签按周/月离线训练，模型产物存对象存储，Spark 加载推理。

## 5. 人群圈选

业务人员在圈选 UI 拖拽标签条件，封装层翻译为 Doris SQL，毫秒级返回 `user_id` 列表或统计计数。

```sql
-- SQL：圈选高价值且非流失用户
SELECT user_id
FROM dws_user_tag_wide
WHERE tenant_id = ${tenant}
  AND user_level = 2            -- 活跃
  AND total_amount >= 5000      -- 累计消费≥5000
  AND churn_risk = 1            -- 未流失
  AND price_sens IN (1, 2);     -- 非高价格敏感
```

性能保障：Doris 列存 + 位图索引 + 向量化，千万级宽表单条件 < 100ms，复合条件 < 500ms；圈选结果可一键导出 CSV 或落临时表供下游营销系统拉取。

## 6. 接口契约（经封装层 REST API）

```
POST /api/tag/v1/definitions          { name, type, rule } → 建标签定义
POST /api/tag/v1/compute              { defId, mode:full|incr } → 触发计算
GET  /api/tag/v1/portrait/{userId}    → { tags:[{k,v,ts}] }       // 单体画像
POST /api/tag/v1/segment              { conditions[] } → { count, sampleIds[] }  // 圈选
POST /api/tag/v1/segment/export       { conditions[], format:csv } → jobId       // 异步导出
```

> 全部接口经 L0.11 封装层鉴权与租户隔离，`tenant_id` 由 Token 注入，不可越权跨租户圈选。

## 7. 关键流程

```text
┌──────────── 图：标签运营全链路流程图 ────────────┐
│  ① 定义标签（事实/规则/挖掘） → 资产目录登记       │
│        ▼                                          │
│  ② Spark ETL 计算 → ③ 写入 Doris 标签宽表          │
│        ▼                                          │
│  ④ 业务圈选（拖拽条件） → Doris SQL → 返回人群      │
│        ▼                                          │
│  ⑤ 画像查看 / 导出 CSV / 推送营销系统              │
└────────────────────────────────────────────────────┘
```

标签定义经审批入资产目录（L3.5），计算作业由 L2.2 Spark 执行，宽表落 L2.5 Doris，圈选与导出经封装层 REST 暴露给业务 UI。

## 8. 多环境适配

- 引擎复用：四环境均由 L2.5 Doris + L2.2 Spark 提供，**本模块无独立部署**。
- 存储差异：Doris 数据落本地盘（BE）+ 对象存储冷备；信创环境用国产盘，云环境用云盘，Profile 切换即可。
- 算力差异：挖掘标签训练重，信创/本地集群小则降频（月级）或关闭，规则/事实标签不受影响。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 标签宽表列数膨胀 | Doris 表过宽、写入慢 | 按主题拆宽表（用户/商品/内容），冷标签归档 |
| 规则标签 SQL 注入 | 越权或拖垮集群 | DSL 白名单 + SQL 模板化 + 封装层超时熔断 |
| 挖掘模型漂移 | 标签失准 | 监控标签分布漂移，触发重训告警 |
| 圈选大结果集导出 | OOM/超时 | 异步导出 + 分页 Stream，限制单次上限 |
| 跨租户数据泄露 | 合规风险 | `tenant_id` 强制注入 + Doris RBAC + 审计日志 |
