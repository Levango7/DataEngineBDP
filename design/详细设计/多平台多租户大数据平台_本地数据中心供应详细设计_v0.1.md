# L0.2 本地数据中心供应 · 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L0 机器供应层
> 套餐：基础版（三档全含）
> 对标：OpenStack Ironic（裸金属）/ Rook-Ceph（存储接入）/ Cluster API（机器生命周期）
> 关联：L0.5 跨环境统一供给抽象（本模块为四环境之一）；L0.6 SKE 控制面；L0.10 环境适配框架（onprem Profile）；L0.11 封装层（接口经其暴露）；L2.1 统一存储（Ceph RGW 作为对象存储后端）

## 1. 定位与价值

本地数据中心供应是平台在**客户自建机房**场景下的机器与存储底座：将 x86 裸金属/虚机纳管为 K8s 节点，接入 Ceph/本地存储作为 L2.1 统一存储后端，并在其上适配自研 SKE 发行版。客户无感知 K8s，只见"湖仓集一体大数据平台"。

客户价值：
- "利旧自建"——复用客户既有 x86 服务器与交换机，不强制采购专属硬件。
- "存储同构"——Ceph RGW 对接 L2.1 CephDriver，与云上 S3 后端行为一致，作业与 SQL 不改。
- "交付可控"——全离线部署，不依赖公网，满足金融/政企数据驻留要求。

平台价值：
- 机器供应经 **MachineProvider 抽象**，本地/云 VM/私有云三环境复用同一控制面。
- 存储接入收敛到 L2.1 StorageDriver，本模块只负责"Ceph 集群就绪 + CSI 挂载"，不重复造存储语义。

## 2. 硬件清单

```text
┌──────── 计算节点（x86 裸金属 / 虚机） ────────┐
│  CPU≥16C  内存≥64G  系统盘≥200G SSD  数据盘≥4×2T NVMe/SATA  │
│  带 IPMI/BMC 带外口（裸金属）或 vNIC（虚机）                  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── 存储节点（Ceph OSD） ────────┐
│  CPU≥8C  内存≥32G  OSD 盘≥12×4T HDD + 1×200G SSD(WAL/DB)  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── 网络 + 负载均衡 ────────┐
│  标准交换机（10G/25G）+ 硬件 LB（F5/A10/Keepalived VIP 兜底）  │
└──────────────────────────────────┘
```

| 角色 | OS | 最低规格 | 用途 |
| --- | --- | --- | --- |
| Master | CentOS 7.9 / RHEL 8 / Ubuntu 22.04 | 8C/32G/200G | SKE 控制面 |
| Worker | 同上 | 16C/64G/200G+4×2T | 大数据计算 |
| Ceph OSD | 同上 | 8C/32G/12×4T | RGW/RBD/CephFS 后端 |
| LB | 硬件或 Keepalived | 双机热备 | 入口流量与 API Server VIP |

## 3. 机器纳管

```text
IPMI/BMC 开机 → PXE 引导基础镜像 → cloud-init 注入 SKE 组件
      → 打标签(role/disk/topology) → 加入节点池 → 就绪上报
```

- **裸金属**：经 IPMI 远程开机，PXE 从部署服务拉取基础镜像，cloud-init 注入 SKE kubelet/容器运行时。
- **虚机**：对接客户 vCenter/PVE，按模板克隆，同走 cloud-init 注入。
- **打标签**：按 `role=worker`、`disk-type=nvme`、`topology.kubernetes.io/zone=dc1` 打 Node Label，供调度与 Ceph CRUSH 拓扑使用。
- **节点池（NodePool）**：按角色分组，扩缩容以池为单位，机器故障自动隔离并触发补货。
- **就绪上报**：kubelet 注册成功后回写 MachineProvider，未在 SLA 内就绪的标记为 `degraded` 并触发替换。

## 4. Ceph 存储接入

Ceph 集群由本模块部署就绪，作为 L2.1 统一存储在本地数据中心的物理后端：

| Ceph 能力 | 对接 L2.1 用途 | 访问方式 |
| --- | --- | --- |
| RGW（对象存储） | CephDriver 后端，承载 Iceberg 表数据 | S3 兼容 API |
| RBD（块存储） | 有状态组件 PV（Doris BE/Kafka） | Ceph-CSI RBD |
| CephFS（文件存储） | 共享卷/临时数据 | Ceph-CSI CephFS |

- RGW 桶前缀按 `workspace/project` 隔离，配额由 L0.11 封装层下发。
- CRUSH 拓扑按机架/主机双层级映射，副本跨机架分布，避免整架故障丢数据。
- 集群健康（PG/OSD down/容量）上报 SKE 控制面，异常触发告警与自动 rebalance。
- 部署模式采用 cephadm 容器化编排，与 SKE 容器栈一致，避免双套运维体系。

## 5. SKE 在本地数据中心适配

- **内核调优**：标准内核参数脚本（vm.max_map_count、net.core.somaxconn、文件句柄、透明大页关闭），无定制内核模块，保持 OS 原厂支持。
- **Ceph CSI**：通过 rook-ceph.operator 部署 CSI 驱动，StorageClass 按需绑定 RBD/CephFS PV，RGW 经 Secret 注入 S3 凭据供 CephDriver 使用。
- **负载均衡**：裸金属无云 LB，采用 MetalLB（L2/BGP 模式）暴露 LoadBalancer Service；入口与 API Server 高可用优先走硬件 LB，MetalLB 作为兜底。
- **onprem Profile**：L0.10 环境适配框架加载 onprem Profile，关闭云专属特性（云 LB/云盘快照），启用本地镜像仓库与离线 helm。

## 6. 接口契约（经封装层）

机器纳管 REST API（内部，客户不直接调用，控制台经封装层转发）：

```
POST /api/l0/v1/onprem/machines/bootstrap   { bmc:{ip,user,pass}, role } → { machineId, status }   // ↔ L0.5 NodePool.createPool（IPMIDriver）
POST /api/l0/v1/onprem/nodepools/{pool}/scale   { targetReplicas }                                  // ↔ L0.5 NodePool.scalePool
GET  /api/l0/v1/onprem/machines/{id}            → { role, labels, capacity, health }                // ↔ L0.5 NodePool.listNodes
POST /api/l0/v1/onprem/ceph/cluster             { osdHosts, crushTopology } → { fsid, health }      // ↔ L0.5 StoragePool.createVolume（CephDriver）
GET  /api/l0/v1/onprem/ceph/cluster/{fsid}/health   → { pgState, osdDown, usagePct }
```

> 客户视角只显示"集群容量 / 节点健康 / 存储用量"，BMC 凭据、CRUSH 拓扑等基础设施细节不暴露。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 裸金属 BMC 异构 | 纳管失败或卡死 | MachineProvider 适配多厂商 BMC，失败降级为手动纳管并告警 |
| Ceph OSD 单盘故障 | PG 降级、IO 抖动 | 副本≥3 跨机架分布，自动 rebalance，OSD 热替换流程文档化 |
| 离线环境镜像缺失 | 部署中断 | 本地镜像仓库预置全部镜像与 helm 包，部署前做 preflight 校验 |
| 硬件 LB 不可得 | 入口无高可用 | MetalLB BGP 模式兜底，多 Worker 共享 VIP，文档给出两种方案选型 |
| 节点扩容慢（PXE/克隆） | 弹性受限 | 预热备用节点池，扩容优先从备用池取，后台异步补货 |

## 8. 与 UI 的对应

控制台 v0.3「平台运维」页（节点列表、Ceph 健康大盘、扩缩容操作）、工作台"集群容量 / 节点健康 / 存储用量"指标卡均基于本模块接口。客户视角屏蔽 BMC、CRUSH 等基础设施细节，仅呈现容量与健康趋势。
