# L0.12 弹性与调度 · 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L0 云原生底座层
> 套餐：基础版（三档全含）
> 对标：Kubernetes HPA / KEDA / Cluster Autoscaler / 自研 SKE Scheduler Extender
> 关联：L0.11 封装层（客户仅见"任务自动变快/并发提升"）；L0.6 SKE 控制面（K8s 调度 + 拓扑调度：NUMA + 数据本地性）；L2.* 引擎（按作业队列弹性）

## 1. 定位与价值

弹性与调度是云原生底座的**资源编排中枢**：以 HPA + KEDA 驱动 Pod 水平伸缩，以 Cluster Autoscaler 调度节点池扩缩，以 SKE Scheduler Extender 叠加 NUMA 亲和与数据本地性，以 ResourceQuota/LimitRange 约束租户配额。整套机制对客户**完全无感知**——封装层 L0.11 将其翻译为"任务自动变快 / 并发提升 / 排队变短"。

客户价值：
- "高峰自动加机器，闲时自动缩"——作业排队时 KEDA 拉起副本，低峰缩回，按量付费。
- "重作业跑得稳"——批/流/GPU/IO 分池隔离，互不抢占，污点容忍保证专机专用。
- "不超支"——租户/项目配额硬约束，超配即告警并拒新作业。

平台价值：
- 弹性策略经 **封装层翻译**，客户只见"扩缩策略 / 配额"两项配置，不接触 HPA/KEDA CR。
- 四环境（信创/本地/云VM/私有云）调度语义一致，差异只在节点池供给方式。

## 2. 总体架构

```text
┌──────── 客户视角（经 L0.11 封装层） ────────┐

└──────────────────────┬──────────────────────────┘
                        ▼ 翻译

│  HPA(CPU/内存)  KEDA(队列/消息深度)  Cluster Autoscaler(节点池)  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── 调度链 ────────┐

└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── 节点池（污点容忍 + 配额约束） ────────┐
│  控制池 │ 批池 │ 流池 │ IO池 │ GPU池   (按 arch/负载分组)  │
└──────────────────────┬──────────────────────────┘
                        ▼
              L0.6 K8s 控制面（SKE 发行版）
```

## 3. 弹性伸缩

- **HPA**：面向在线服务（Doris FE/BE、Trino Coordinator、网关），指标取 CPU/内存利用率，目标利用率 70%，扩缩稳定化窗口 300s 防抖。
- **KEDA**：面向计算作业（SparkApplication、FlinkDeployment、Trino Worker），按**作业队列深度 / Kafka 消息堆积 / Iceberg 待合并文件数**触发 ScaledObject，支持从 0 冷启到 N。
- **扩缩策略**：扩容先扩 Pod（秒级），Pod Pending 触发 Cluster Autoscaler 扩节点（分钟级）；缩容先缩 Pod（grace 120s 排空），节点空闲 10min 缩回。
- **策略协同**：HPA 与 KEDA 不叠加同一对象（在线用 HPA、作业用 KEDA）；Cluster Autoscaler 由 Pod Pending 驱动，不主动缩承载活跃作业的节点。

KEDA ScaledObject 示例（内部 CR，封装层生成）：
```yaml
apiVersion: keda.sh/v1alpha1
kind: ScaledObject
metadata: { name: spark-queue-{workspace} }
spec:
  scaleTargetRef: { kind: SparkApplication, name: spark-{workspace} }
  minReplicaCount: 0
  maxReplicaCount: 50
  triggers:
    - type: kafka
      metadata: { topic: jobs.{workspace}, lagThreshold: "100" }
```

## 4. 节点池（NodePool）管理

按架构与负载类型分组，污点隔离专机专用：

| 节点池 | 污点 | 容忍租户 | 承载 |
| --- | --- | --- | --- |
| 控制池 | `role=control:NoSchedule` | 平台 | K8s 控制面、封装层、网关 |
| 批池 | `role=batch:NoSchedule` | 全租户 | Spark Executor、Trino worker |
| 流池 | `role=stream:NoSchedule` | 全租户 | Flink TaskManager |
| IO池 | `role=io:NoSchedule` | 全租户 | compaction、数据同步、对象存储代理 |
| GPU池 | `role=gpu:NoSchedule` | 授权租户 | AI 推理/训练（按需启用） |

> 信创环境按 arch（x86/aarch64/鲲鹏/飞腾）再细分池，保证国产 CPU 二进制亲和。每池独立 Cluster Autoscaler 配置，互不串扰。

## 5. SKE 拓扑调度

SKE Scheduler Extender 在默认调度评分后**叠加两类亲和**：

- **NUMA 亲和**：流/批重算 Pod 绑定 NUMA 节点，避免跨 NUMA 内存访问延迟，对 Flink TM 尤为关键。
- **数据本地性**：读取 Iceberg 表时，Extender 查询分片所在对象存储区/节点拓扑，优先把 Executor 调度到数据就近节点，减少跨域拉取。

扩展器以 **Filter + Score** 两阶段接入 kube-scheduler，失败不阻塞调度（降级为默认调度），保证可用性。Extender 对外仅暴露内部 `/filter`、`/score` HTTP 端点，不经封装层，客户不可见。

调度评分流程：
1. kube-scheduler 完成默认 Filter/Score，得到候选节点列表。
2. 调用 SKE Extender `/score`：对每候选节点按 NUMA 距离 + 数据本地距离加权打分。
3. 选最高分节点绑定 Pod；若 Extender 超时/异常，回退默认调度结果。

## 6. 配额约束

- **ResourceQuota**：按 namespace（= workspace/project）约束 CPU/内存/Pod 数/PVC 总量，硬上限；超限 API 直接拒绝新作业。
- **LimitRange**：约束单 Pod 默认 request/limit 与上限，防止单作业抢占整池。
- **超配告警**：用量 ≥ 80% 触发告警，≥ 100% 拒新作业并通知租户；封装层翻译为"配额将满"提示。
- **跨租户隔离**：节点池通过污点 + ResourceQuota 双重隔离，租户 A 的作业不可落到租户 B 专属配额节点。


## 7. 接口契约（经封装层）

```
POST /api/elastic/v1/policies        { scope, metric, min, max, target } → 建扩缩策略
GET  /api/elastic/v1/policies/{id}   → { status, currentReplicas, nodes }
POST /api/elastic/v1/quotas          { scope, cpu, memory, pods }       → 建配额
GET  /api/elastic/v1/quotas/{scope}  → { used, hard, percent }
GET  /api/elastic/v1/pools           → [{ name, role, arch, ready, capacity }]
```

> scope 取 `workspace` / `project`；metric 取 `cpu` / `memory` / `queueDepth` / `messageLag`。HPA/KEDA/ResourceQuota CR 由封装层内部生成，客户不直接接触。

## 8. 多环境适配

| 环境 | 节点供给 | 扩缩能力 |
| --- | --- | --- |
| 信创 | 固定裸金属节点池（国产 CPU/OS） | 仅 Pod 级 HPA/KEDA，节点池人工扩 |
| 本地数据中心 | 虚机/裸金属静态池 | Pod 弹性 + 人工/脚本扩节点 |
| 公有云 VM | 云 VM 可调 API（按租户云账号） | 全自动 HPA+KEDA+Cluster Autoscaler |
| 私有云 | 厂商 VM API 或静态池 | 视厂商能力，能力探测后启用自动扩节点 |

> 关键约束：云环境扩节点用**客户自有云账号**，平台不代购云资源；信创环境默认关闭节点自动扩缩，避免动国产裸金属。四环境调度语义一致，差异收敛到节点供给适配器。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 扩容抖动（峰谷频繁） | 节点反复加减、成本波动 | HPA 稳定化窗口 + Cluster Autoscaler 缩容冷却 10min |
| KEDA 冷启慢 | 首作业等待镜像拉取 | 预热镜像 + 保底 1 副本 + 节点池预留 buffer |
| NUMA 亲和调度失败 | Extender 异常阻塞调度 | Extender 失败降级默认调度，仅打分不强制 |
| 跨租户抢占 | 大租户吃光节点池 | ResourceQuota + 污点隔离 + 节点池按租户保留比例 |
| 信创节点池不可扩 | 高峰排队 | 提前容量规划 + 排队告警 + 人工扩容 SOP |
