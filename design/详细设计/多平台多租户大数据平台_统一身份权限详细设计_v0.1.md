# X1 统一身份与权限 · 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · 横切能力层
> 对标：Keycloak（IAM）/ 国密 SM2/SM3/SM4（GB/T 32918 等）/ OAuth2.1 + OIDC
> 关联：L0.11 封装层（鉴权网关）；L3.7 数据安全（行级权限联动）；L5.1 控制台（登录/权限）；L5.2 运营后台（租户管理）
> 适用版本：基础版✅ / 标准版✅ / 旗舰版✅（全版本开放，对照 §11.5 套餐模块矩阵）

## 1. 定位与价值

统一身份与权限是平台的**唯一信任源**：以 Keycloak 承载认证授权，以国密算法承载加解密，以多租户 Realm 模型承载身份层级，所有控制台/引擎/作业/网关均回溯到此。

客户价值：
- "一次登录，全平台通行"——控制台、IDE 插件、CLI、作业提交均走 OIDC SSO。
- "信创合规"——SM2 证书/SM3 摘要/SM4 加密可替换 Keycloak 原生 RSA/SHA/AES，满足等保/密评。
- "租户自管"——租户管理员在本 Realm 内自管用户/角色/组织，平台管理员不越权。

平台价值：
- 鉴权逻辑收敛到 L0.11 网关 + Keycloak SPI，业务模块零硬编码鉴权。
- 国密改造经 **CryptoSpiFactory** 抽象，信创环境插国密、非信创环境插标准算法，二进制同一份。

## 2. 总体架构

```text
┌──────── 入口层（均经 L0.11 鉴权网关） ────────┐
│  L5.1 控制台   L5.2 运营后台   CLI/IDE   引擎/作业  │
└──────────────────────┬──────────────────────────┘
                        ▼  OIDC/OAuth2.1 + JWT(RFC9068)
┌──────── Keycloak on K8s（Helm，StatefulSet） ────────┐
│  Realm: sq（共享租户域，域内 client/role 隔离）+ master（平台域）  │
│  认证: OIDC·SAML·LDAP·Broker  授权: RBAC·ABAC·UMA     │
│  SPI: 国密加密 SPI · 事件监听 SPI · 同步 SPI           │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── 国密改造层（CryptoSpiFactory，可插拔） ────────┐
│  信创: SM2 证书 / SM3 摘要 / SM4-CBC 加密   非信创: RSA/SHA-256/AES-GCM  │
└──────────────────────┬──────────────────────────┘
                        ▼
┌──────── 身份存储 + 缓存 ────────┐
│  PostgreSQL（Realm/用户/角色）   Infinispan（会话/Realm/Token 缓存，Keycloak 原生分布式缓存）  │
└──────────────────────────────────┘
```

## 3. 认证模型

支持多 IdP 对接，按租户/环境配置启用项，统一收敛到 OIDC 协议对外发 Token：

- **OIDC/OAuth2.1**：平台默认，控制台/CLI/IDE 走 Authorization Code + PKCE，签发 RFC9068 JWT。
- **SAML 2.0**：对接客户已有 IdP（如信创统一身份认证、政务 SAML），经 Keycloak SAML Identity Provider 转换为 OIDC Token。
- **LDAP/AD**：对接企业域账号，经 User Federation Sync 双向同步，密码校验回源。
- **Broker 多 IdP 联邦**：一个 Realm 可挂多个外部 IdP，登录页按租户配置展示"企业 SSO / 政务证书 / 账号密码"多入口。

> 关键约束：对外只发 OIDC Token，SAML/LDAP 仅作入站联邦，避免下游业务多协议适配。

## 4. 授权模型

采用 **RBAC 为主 + ABAC 为辅** 的混合模型，权限粒度到"模块 × 资源 × 动作"：

- **RBAC 层级**：租户 → 组织 → 项目 → 角色 → 权限（`module:resource:action`，如 `lake:table:write`、`dev:job:submit`）。角色绑定到用户/用户组。
- **ABAC 层级**：以 Token claim（租户/项目/环境标签）+ 资源属性（归属项目、密级）做运行时判定，与 L3.7 数据安全行级权限联动（如"仅本部门 + 非密级数据"）。
- **UMA 资源授权**：对高敏感资源（如导出、跨租户访问）走 UMA 2.0，资源所有者在线授权，Ticket 一次性。

## 5. 国密改造

替换 Keycloak 加密/签名 SPI，信创环境插国密、非信创插标准算法，二进制同一份：

| 用途 | 信创实现 | 非信创实现 | 替换点 |
| --- | --- | --- | --- |
| TLS 证书/签名 | SM2 证书 + TLCP | RSA/ECC + TLS1.3 | Ingress + Keycloak HTTPS |
| 密码摘要存储 | SM3 + 盐 | SHA-256 + 盐 | PasswordHashing SPI |
| Token 签名 | SM2withSM3 | RS256/ES256 | Token Signature SPI |
| 敏感字段加密 | SM4-CBC | AES-GCM | Vault/凭据加密 SPI |
| 随机数 | 国密 DRBG | SecureRandom | nonce/盐生成 |

> 可插拔：经 `CryptoSpiFactory` 按 Profile 加载，信创 Profile 注入国密实现，非信创注入标准实现，Keycloak 主流程零改动。

## 6. 多租户身份模型

采用 sq 共享租户域 + 域内 client/role 隔离 + master 平台域的多租户 Realm 模型（对齐 keycloak-values.yaml 实际配置）：sq Realm 为所有租户共用域，每个租户在 sq 域内对应独立 client，租户隔离靠 client/role 边界；master Realm 为平台管理域，管理租户元数据与平台运维。身份层级如下：

```text
平台管理员(platform-admin)  ─ 管平台/建租户/运维
   └─ 租户管理员(tenant-admin)  ─ 本 Realm 内管用户/角色/组织/配额
          └─ 项目管理员(project-admin)  ─ 本项目内管成员/资源授权
                 └─ 成员(member)  ─ 使用平台资源
```

- **平台管理员**：驻 `master` 平台域，仅管租户生命周期、平台运维、全局配额，不接触业务数据。
- **租户管理员**：驻 `sq` 共享租户域内本租户 client，自管本租户用户/组织/角色，可委派项目管理员。
- **项目管理员**：在项目作用域内管成员与资源授权，权限不跨项目。
- **成员**：被授予项目角色，Token claim 携带 `tenant/org/project/roles`，网关据此放行。

> 隔离边界：master 平台域与 sq 共享租户域间强隔离；sq 域内各租户 client 间靠 client/role 边界隔离，跨 client 查询默认禁用，仅平台运维审计可读，业务不可见。

## 7. 接口契约

经 L0.11 网关暴露，认证/授权/用户/角色四组 REST API：

```text
POST /api/auth/v1/login            { grantType, idpHint } → { accessToken, refreshToken, idToken }
POST /api/auth/v1/refresh          { refreshToken } → { accessToken }
POST /api/auth/v1/logout           { refreshToken }
GET  /api/auth/v1/userinfo         → { tenant, org, project, roles, attrs }
POST /api/auth/v1/token/introspect { token } → { active, scope, exp }   // 网关侧校验
GET  /api/iam/v1/users             ?org=&project=&page= → [{ id, name, roles }]
POST /api/iam/v1/users             { name, email, org, roles }
POST /api/iam/v1/roles             { name, scope, perms: ["lake:table:write"] }
POST /api/iam/v1/roles/{r}/users   { userIds }   // 批量授权
GET  /api/iam/v1/permissions/check { subject, resource, action } → { allowed, reason }
```

> 引擎/作业侧鉴权不直连此 API，由网关在请求入口完成 Token 校验 + 权限判定，业务侧零鉴权代码。

## 8. 多环境适配

四环境算法与部署形态差异，Profile 切换即换实现，业务无感：

| 环境 | 算法套件 | IdP 来源 | 部署形态 |
| --- | --- | --- | --- |
| 信创 | SM2/SM3/SM4 + TLCP | 信创统一身份/政务 SAML | Keycloak on SKE，国密 SPI |
| 本地数据中心 | RSA/SHA-256/AES-GCM | LDAP/AD 或内置 | Keycloak on SKE，标准 SPI |
| 公有云 VM | RSA/SHA-256/AES-GCM | 客户云 IdP 或内置 | Keycloak on 客户 VM K8s |
| 私有云 | RSA/SHA-256/AES-GCM | 客户私有 IdP 或内置 | Keycloak on 私有云 K8s |

> 关键约束：云环境 Keycloak 部署在客户自管 K8s/VM，不绑云托管 IAM，保持可迁移、不锁云。

> 信创环境身份存储适配：信创环境 PostgreSQL 可切换为 openGauss（兼容 PostgreSQL 协议，§13 国产信创标杆元数据库），切换经 Keycloak datasource 配置项完成，业务无感。
>
> Keycloak 镜像：基于上游 24.0.5 + 国密 SPI 自研打包为 `sq-keycloak:24.0-0.1.0`（对齐 keycloak-values.yaml 中 image 配置），国密 SPI 经 CryptoSpiFactory 抽象，信创环境注入国密实现、非信创环境注入标准算法，二进制同一份。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 国密 SPI 与 Keycloak 版本耦合 | 升级失效 | SPI 接口最小化 + 升级回归用例 + 锁定 Keycloak LTS |
| 多 Realm 性能瓶颈 | 大租户登录慢 | Infinispan 分布式会话/Token 缓存（Keycloak 原生）+ Realm 分库 + 读写分离 |
| LDAP 同步延迟 | 账号变更不及时 | 增量同步 + 事件驱动 + 关键变更走实时 webhook |
| Token 泄露 | 越权访问 | 短 TTL access + 滚动 refresh + 网关侧 introspect + 撤销列表 |
| 跨租户越权 | 数据泄露 | Realm 强隔离 + 网关 claim 强校验 + ABAC 行级联动 |
| 信创 IdP 兼容性 | 对接失败 | Broker 适配层做协议降级 + preflight 能力探测 |

## 10. 与 UI 的对应

控制台 v0.3「身份权限」页（用户/角色/组织管理、登录策略、IdP 对接）、运营后台「租户管理」页（建租户/配额/审计）、控制台登录页（多 IdP 入口、SM2 证书登录）均基于此模块。本文件是其身份权限侧契约依据。
