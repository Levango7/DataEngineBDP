## 1. 定位与职责

主数据（Master Data）是「被多个业务域共享、变化缓慢、需全局一致」的核心实体。本模块职责：

1. **主数据建模**：定义主数据模型（实体 + 属性 + 编码规则）。
2. **录入与审批**：主数据录入、变更走审批流（接入 L3.7）。
3. **分发**：将权威主数据分发到各消费域（ Iceberg 主题表 / Doris 维表）。
4. **订阅**：消费域订阅主数据，变更自动同步。
5. **版本**：保留历史版本，支持追溯。

**与资产目录（L3.5）的关系**：主数据模型登记为「主数据类资产」，可被统一检索、申请权限；但主数据额外具备「分发 / 订阅 / 版本」能力，资产目录不负责这些。

## 2. 接口契约

### 2.1 模型定义 `POST /api/v1/mdm/models`
```json
{ "name":"dim_customer", "displayName":"客户主数据",
  "attrs":[ {"name":"cust_id","type":"string","pk":true},
            {"name":"cust_name","type":"string"},
            {"name":"region","type":"string","enum":["华东","华北","华南"]} ],
  "codeRule":"CUST-{yyyy}{seq:6}" }
→ 200 { "modelId":"mdm-dim_customer", "status":"active" }
```

### 2.2 实体 CRUD `POST /api/v1/mdm/models/dim_customer/entities`
```json
{ "cust_id":"CUST-2026000001", "cust_name":"示例客户A", "region":"华东" }
→ 200 { "entityId":"CUST-2026000001", "version":1, "status":"pending_approval" }
```

### 2.3 分发 `POST /api/v1/mdm/models/dim_customer/distribute`
```json
{ "targets":["iceberg_trade.dwd.dim_customer","doris.mart.dim_customer"] }
→ 200 { "taskId":"dist-xxx", "status":"synced" }
```

### 2.4 订阅 `POST /api/v1/mdm/subscribe`
```json
{ "model":"dim_customer", "consumer":"ws-demo-fin/trade", "onChange":"auto_sync" }
→ 200 { "subscriptionId":"sub-xxx" }
```

### 2.5 版本查询 `GET /api/v1/mdm/models/dim_customer/entities/CUST-2026000001/versions`

## 3. 关键流程

### 3.1 建模 → 录入 → 审批 → 分发
```
运营/数据管家 建主数据模型 dim_customer (mdm/models)
  → 录入实体 (status=pending_approval)
  → L3.7 审批流: 批准 → status=active, version=1
  → 分发到 Iceberg dwd.dim_customer + Doris mart.dim_customer
  → 消费域(交易域) 建表时引用 dim_customer, 保证与客户域一致
```

### 3.2 变更同步
```
主数据变更 (cust_name 更新) → 新版本 version=2, 审批通过
  → 所有订阅方(按 subscription) 收到变更事件 → 增量同步到目标表
  → 统一 SQL 网关查询时, 各域主数据一致 (L2.7 联邦)
```

## 4. 与相邻模块衔接

| 模块 | 关系 |
| --- | --- |
| L3.5 资产目录 | 主数据模型作为「主数据类资产」登记，可被检索 / 申请权限 |
| L2.7 统一 SQL | 主数据表（dim_*）可经网关联邦查询，参与跨域关联 |
| L3.7 安全脱敏 | 主数据敏感字段（如 cust_name）受脱敏策略约束，审批后可见 |
| L0.11 封装层 | 主数据按 `ws` / `project` 标签隔离；分发目标受配额约束 |
| L2.1 统一存储 | 主数据落地 Iceberg（湖仓集一体），Doris 维表由物化视图承接 |

---

## 5. 多环境一致性

- 主数据模型与分发逻辑四环境完全一致，仅存储驱动不同（StorageDriver）。
- 编码规则（`codeRule`）与环境无关，保证跨环境主数据可对齐。

## 6. 部署配置

部署参数落地于 `design/deploy/values/mdm-values.yaml`，由封装层 Helm Operator 渲染。关键配置块：

```yaml
# mdm-values.yaml
mdm:
  image: sq-mdm:0.1.0          # Java 实现
  replicas: 2
  resources:
    requests: { cpu: "0.5", memory: "1Gi" }
    limits:   { cpu: "1",   memory: "2Gi" }
  storage:
    relational: { type: "postgresql" }   # 主数据元数据
    distribute:
      iceberg: { enabled: true }
      doris:   { enabled: true }
  approval:
    engine: "java"             # 审批流引擎（Java）
    timeout: "24h"
  tierProfiles:
    base:      { replicas: 1, resources: "small" }
    standard:  { replicas: 2, resources: "medium" }
    flagship:  { replicas: 3, resources: "large" }
```

> 资源配额说明：`resources` 中 quota 为单组件上限，平台总额度见 §11.5.2，由封装层 ResourceQuota 在租户级聚合约束（非所有组件同时满载，故单组件配额之和可略超平台总额度）。

## 7. 风险与对策

| 风险 | 现象 | 对策 |
| --- | --- | --- |
| 主数据分歧 | 各域口径不一 | 强制单一可信源 + 订阅同步，禁止各域自建副本 |
| 审批绕过 | 脏数据入主数据 | 所有写入经 L3.7 审批流，引擎侧强制 |
| 分发延迟 | 订阅方陈旧 | 变更事件驱动增量同步 + 版本号校验 |
| 跨域依赖环 | 互相引用死锁 | 主数据不参与业务计算，仅作维度引用 |
