# L5.4 对内业务线门户 · 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L5 多租户产品层（SaaS）
> 对标：字节 DataLeap 内部门户 / 阿里 DataWorks 内部版 / 企业内部数据中台门户
> 关联：X1 统一身份权限（Keycloak）；§11.5 定价模型（内部结算系数0.3）；L5.2 运营后台；L0.9 可观测基座；L0.12 弹性调度；L3.4 数据权限

## 1. 定位与价值

对内业务线门户是平台面向**内部使用方**的统一入口：以"业务线-团队-项目"组织视图复用平台全部能力，免计费或走内部结算，不承诺 SLA，资源受部门预算软约束。仅适用于**标准版+旗舰版**。

客户价值：
- **业务线视角聚合**——一条业务线下的多团队、多项目资源/作业/成本一屏可见，免去逐项目跳转。
- **零计费摩擦**——成员用资源不刷卡、不走套餐，按内部结算（成本×0.3）月度推财务，研发专注业务。
- **内部协同加速**——同业务线跨项目数据共享、资源申请审批一键流转，避免外部租户的强隔离摩擦。

平台价值：
- 内部用量沉淀为平台真实负载样本，反哺 L0.12 弹性调度与容量规划。
- 业务线维度成本分摊为内部 IT 财务提供依据，支撑"用者自负"的内部成本文化。

## 2. 与外部租户控制台差异

| 维度 | 外部租户控制台（L5.1） | 对内业务线门户（本模块） |
| --- | --- | --- |
| 身份模型 | 租户管理员 → 项目 → 成员 | 业务线 → 团队 → 项目 → 成员（业务线为组织维度） |
| 计费 | 按套餐 + 超量计费，在线支付 | 免计费 或 内部结算（成本系数 0.3，月度出账推财务） |
| SLA | 承诺 SLA（99.9% 等） | best-effort，不承诺 SLA |
| 资源限制 | 套餐配额（硬限制，超限阻断） | 部门预算额度（软限制，超限告警不阻断） |
| 功能集 | 标准数据开发/治理/服务 | 额外：成本看板 / 资源申请审批 / 跨项目数据共享 |
| 视角 | 单租户自服务 | 业务线聚合 + 跨项目协同 |
| 上线门槛 | 自助开通 | 由平台运营（L5.2）分配业务线配额后开通 |

## 3. 组织-项目模型

```text
┌──────────── 组织树（X1 Keycloak 同步） ────────────┐
│  BusinessLine（业务线，顶层组织维度）              │
│      └── Team（团队）                              │
│            └── Project（项目，资源/数据隔离单元）   │
│                  └── Member（成员，角色绑定）       │
└────────────────────────────────────────────────────┘
权限规则：
  1. 沿树继承：业务线管理员 ≥ 团队负责人 ≥ 项目 owner
  2. 可越级授权：业务线管理员可直接授予某项目 owner
  3. 跨业务线默认不可见，显式授权才可见
```

- **业务线**：顶层组织维度（如"风控线""增长线"），由 L5.2 运营后台创建并分配预算额度。
- **团队**：业务线下分组，对应部门/小组，团队负责人审批本团队资源申请。
- **项目**：资源与数据隔离单元，对应一个工作空间；跨项目默认隔离。
- **成员**：经 X1 Keycloak 同步账号，角色沿树继承，可越级授权。

## 4. 门户功能

```text
┌────────────────── 对内业务线门户 ──────────────────┐
│ ① 业务线仪表盘   资源用量/作业成功率/成本趋势/TopN │
│ ② 项目沙箱       一键创建项目+数据源+Theia IDE      │
│ ③ 资源申请审批   成员申请→团队负责人审批→自动生效   │
│ ④ 成本看板       按项目/团队/业务线维度成本分摊     │
│ ⑤ 跨项目数据共享 同业务线内申请共享→L3.4 审批       │
└────────────────────────────────────────────────────┘
```

1. **业务线仪表盘**：聚合本业务线下所有项目的资源用量（CPU/内存/存储）、作业成功率、成本趋势（近 30 日）、TopN 项目排行；支持下钻到项目详情。
2. **项目沙箱**：一键拉起"项目 + 默认数据源 + 开发环境（Theia IDE）"，3 分钟可用；模板由平台运营预置。
3. **资源申请审批**：成员申请 CPU/内存/存储额度 → 团队负责人审批 → 审批通过自动调整项目 ResourceQuota；超部门预算则升级到业务线管理员。
4. **成本看板**：按项目/团队/业务线维度展示成本分摊，数据来自 L0.9 资源用量 × L0.12 弹性计量单价；支持导出月度报表。
5. **跨项目数据共享**：同业务线内项目间可申请共享表/数据集，经 L3.4 数据权限审批流，审批通过后自动授予跨项目读权限。

## 5. 内部结算

```text
资源用量(L0.9) ──→ 成本归集(按项目) ──→ 内部价格(×0.3) ──→ 月度出账 ──→ 推送财务系统
      │                  │                    │                │              │
      └─ L0.12 弹性计量 ──┘                    └─ §11.5 定价 ─┘              └─ ERP/财务API
```

- **成本采集**：从 L0.9 可观测基座按项目维度采集 CPU/内存/存储/IO 用量。
- **成本归集**：按项目归集到团队、业务线，形成三级成本树。
- **内部价格**：归集成本 × 内部系数 **0.3**（§11.5 定价模型），区分于外部套餐价。
- **月度出账**：每月 1 日凌晨生成业务线/团队/项目三级账单，落账单库。
- **推送财务**：经 ERP/财务 API 推送月度账单，附带用量明细可追溯；失败重试 3 次并告警。
- **对账与争议**：账单落库后 5 个工作日为争议期，业务线管理员可发起复核，由平台运营（L5.2）仲裁。

## 6. 接口契约

```text
GET  /api/portal/v1/businessLines                  → [{blId, name, budget, used}]
POST /api/portal/v1/projects                       { blId, teamId, name, template } → {projectId}
POST /api/portal/v1/resource/apply                 { projectId, cpu, mem, storage, reason } → {applyId}
POST /api/portal/v1/resource/approve               { applyId, decision, comment } → {ok}
GET  /api/portal/v1/cost/report                    { blId, dim, from, to } → [{dimKey, cost, breakdown}]
POST /api/portal/v1/share                          { srcProject, dstProject, table, scope } → {shareId}
```

接口职责说明：
- `listBusinessLines`：列出当前用户可见业务线及预算/已用额度，驱动仪表盘切换。
- `createProject`：在指定业务线/团队下建项目，按 template 预置数据源与开发环境。
- `applyResource` / `approveResource`：资源申请-审批对，审批通过自动调整 ResourceQuota。
- `getCostReport`：按 dim（project/team/bl）维度取成本报表，支持导出月度账单。
- `shareData`：发起跨项目数据共享申请，触发 L3.4 审批流，审批通过自动授权。

> 所有接口经 X1 鉴权 + 业务线/团队/项目三级鉴权；跨业务线访问默认拒绝，显式授权才放行。所有写操作落审计日志，保留 180 天。

## 7. 多环境对照

门户本身为**纯前端 + BFF API**，环境无关；差异仅在后端数据源随环境切换。

| 环境 | 前端 | BFF | 后端数据源 | 说明 |
| --- | --- | --- | --- | --- |
| 信创 | 同一套 | 同一套 | 信创 K8s + 国产对象存储 | 全栈信创部署 |
| 本地数据中心 | 同一套 | 同一套 | 本地 K8s + Ceph/MinIO | 裸金属/虚机自建 |
| 公有云 VM | 同一套 | 同一套 | 客户云对象存储（自带密钥） | 仅用裸对象存储，不绑云托管服务 |
| 私有云 | 同一套 | 同一套 | 厂商对象存储 / MinIO | 客户私有云 VM |

> 关键约束：门户前端/BFF 四环境完全一致，仅 Profile 切换后端数据源；不引入任何云原生托管服务，保持可迁移。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 业务线间数据越权 | 数据泄露、合规事故 | 三级鉴权 + 跨业务线默认拒绝 + L3.4 审计日志全量留痕 |
| 成本分摊精度不足 | 内部账单争议 | 按 L0.12 弹性计量粒度（项目×小时）归集，账单附用量明细可追溯 |
| 审批流堵塞 | 成员等资源，研发停滞 | 团队负责人 24h 未审批自动升级业务线管理员；超预算自动转审批 |
| 内部不承诺 SLA 的期望管理 | 用户误用外部 SLA 口径 | 门户显著标注"best-effort"，onboarding 文档明确不承诺 SLA |
| 跨项目共享失控 | 数据蔓延、权责不清 | 共享必须经 L3.4 审批 + 有效期 + 自动到期回收 + 审计可回溯 |

## 9. 与 UI 的对应

控制台 v0.3「业务线门户」入口（仅标准版+旗舰版可见）：业务线仪表盘页、项目沙箱创建向导、资源申请中心、成本看板、跨项目共享中心均基于本模块契约。本文件是其组织模型、结算规则与接口契约的依据。
