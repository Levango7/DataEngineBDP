# L2.3 流计算（Flink 1.18）· 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L2 大数据引擎层
> 适用套餐：标准版、旗舰版（基础版不含，对齐 §11.5.1 套餐矩阵）
> 对标：Apache Flink 1.18 / 阿里 Vvp / 华为 Stream SQL
> 关联：L2.1 统一存储（Flink CDC 实时写 Iceberg）；L2.8 消息（Kafka 流源/汇）；L0.11 封装层（Flink Operator 提交）；L2.6 湖仓集一体（实时入湖层）；L2.7 统一 SQL 网关（Stream SQL）

## 1. 定位与价值

流计算是湖仓集一体的**实时入湖引擎**：以 Flink 1.18 承载 CDC 实时采集、流式 ETL、实时聚合与物化，对接 Kafka 流源、MySQL/PG 变更流，实时写 Iceberg（湖）与 Doris（集），支撑毫秒~秒级新鲜度。

客户价值：
- "实时可用"——业务变更秒级入湖，BI/在线服务查到最新数据。
- "一套 SQL 通吃"——批用 Spark、流用 Flink，统一经 L2.7 网关下发，客户无引擎切换感。
- "信创友好"——Java 生态 + ARM 支持，国产 OS/JDK 可运行。

平台价值：
- 引擎经 **Flink Kubernetes Operator** 部署，作业即 `FlinkDeployment` CR，与 K8s 声明式一致。
- 状态后端统一到 L2.1 对象存储，四环境同构、可迁移、不锁云。
- 客户视角只见"流作业 / 同步任务"，不感知 K8s/Operator/CRD。

## 2. 总体架构

```text
┌──────── 客户接入（经 L0.11 封装层 / L2.7 SQL 网关） ────────┐
│  Stream SQL   Flink CDC 同步任务   PyFlink/Java 作业 Jar      │
└──────────────────────┬───────────────────────────┘
                        ▼
┌──────── Flink Kubernetes Operator（控制面） ────────┐
│  FlinkDeployment CR → JM/TM Pod 调度 → 作业生命周期           │
└──────────────────────┬───────────────────────────┘
                        ▼
┌──────── Flink 集群（数据面，on K8s/SKE） ────────┐
│  JobManager(调度/Checkpoint 协调)  TaskManager(Slot/算子执行)  │
│  Source(Kafka/MySQL CDC) → Transform → Sink(Iceberg/Doris)     │
└──────────────────────┬───────────────────────────┘
        ┌──────────────┼──────────────┬──────────────┐
        ▼              ▼              ▼              ▼
   Kafka(L2.8)    MySQL/PG CDC   Iceberg(L2.1)   Doris(L2.6)
   流源/汇         变更流          实时入湖         实时物化
```

## 3. 引擎抽象与 K8s 集成

Flink 经 **Flink Kubernetes Operator** 落 K8s：封装层把客户作业翻译为 `FlinkDeployment` CR，Operator 负责 JM/TM Pod 的创建、升级、Savepoint 与故障恢复。

```yaml
apiVersion: flink.apache.org/v1beta1
kind: FlinkDeployment
metadata: { name: cdc-mysql-to-iceberg, namespace: ws-{tenant} }
spec:
  image: flink:1.18-ske        # 信创/ARM 镜像按 Profile 切换
  flinkVersion: v1_18
  serviceAccount: flink-operator
  podTemplate:                 # SKE NumA 亲和 / 节点池反亲和
    spec: { containers: [...], affinity: {...} }
  job: { jarURI, entryClass, args, parallelism, state: running }
  flinkConfiguration:
    state.backend: rocksdb
    state.checkpoints.dir: s3a://{bucket}/flink/ckpt/{job}
    s3.endpoint: {StorageDriver 端点}
```

提交流程：客户提交 → 封装层校验配额/隔离 → 翻译 CR → `kubectl apply` → Operator 拉起 JM → JM 调度 TM → 作业 RUNNING。

## 4. CDC 实时入湖

Flink CDC 从 MySQL/PG（debezium）或 Kafka（canal/json）捕获变更流，经 Transform 后实时写 Iceberg（湖），并可选物化到 Doris（集）。

```text
MySQL/PG ──binlog──▶ Flink CDC Source ──▶ Transform(ETL/聚合)
                                              ├──▶ Iceberg Sink(L2.1 湖) ──▶ 快照可查
                                              └──▶ Doris Sink(L2.6 集)  ──▶ 在线查询
Kafka(L2.8) ─stream──▶ Flink Source ──────────┘
```

关键能力：无锁全量阶段 + 增量 binlog 续传；Schema Evolution 透传到 Iceberg；Exactly-Once 由两阶段提交 + Iceberg 快照原子提交保证。

## 5. 接口契约（经封装层）

```
POST /api/stream/v1/jobs                 { name, sql|jar, parallelism, resource } → 提交流作业
GET  /api/stream/v1/jobs/{id}            → { status, metrics, backpressure }
POST /api/stream/v1/jobs/{id}/savepoint  { cancelAfter } → 触发 Savepoint
POST /api/stream/v1/cdc/sync             { source: mysql, sink: iceberg, tables } → 建 CDC 同步
POST /api/stream/v1/jobs/{id}/scale      { parallelism } → 弹性扩缩容
```
> 客户不直接操作 CR/Operator；封装层做租户隔离、配额校验、镜像/Profile 注入。

## 6. 关键流程

```text
提交 → 封装层翻译 CR → Operator 起 JM → JM 起 TM →
Source(Kafka/CDC) → Transform(map/join/agg) → Sink(Iceberg/Doris) →
周期 Checkpoint → 状态写对象存储 → 快照提交 → 下游可见
```

1. **提交**：Stream SQL 或 Jar 经 L2.7/L0.11 进入封装层。
2. **调度**：Operator 按 PodTemplate 调度 JM/TM，SKE NumA 亲和绑核。
3. **执行**：Source 拉流 → 算子链算子执行 → Sink 写湖/集。
4. **Checkpoint**：周期触发，RocksDB 增量快照写对象存储，屏障对齐后提交。
5. **可见**：Iceberg 快照提交后下游 Trino/Doris 可读最新数据。

## 7. 状态管理与容错

- **状态后端**：RocksDB（增量 Checkpoint），状态存 L2.1 对象存储，四环境同路径。
- **Checkpoint**：周期（如 60s）+ 对齐，故障从最近 ckpt 恢复，语义 Exactly-Once。
- **Savepoint**：升级/迁移前手动触发，存对象存储，跨集群恢复。
- **两阶段提交**：Sink 端 upsert + Iceberg 快照原子提交，避免重复写。
- **反压**：JM 监控 inPoolUsage/outPoolUsage，超阈值告警 + 自动扩 TM Slot。

## 8. 资源与调优

- **TaskManager**：`taskmanager.numberOfTaskSlots` 按 SKE 节点 CPU 核数设；`memory.process.size` 留出 RocksDB native 内存。
- **并行度**：按 Kafka 分区数 / Source 并行度对齐，避免数据倾斜。
- **反压**：开启 `network.memory.fraction` 调优；倾斜 key 加 rebalance/rescale。
- **SKE NumA 感知**：PodTemplate 注入 `cpuManagerPolicy=static`，TM 绑核跨 NUMA 减远程内存访问。
- **Checkpoint 调优**：小状态用 aligned，大状态用 unaligned 屏障，避免反压时 ckpt 超时。

## 9. 多环境适配

| 环境 | 镜像 | K8s | 状态后端 | 说明 |
| --- | --- | --- | --- | --- |
| 信创 | flink:1.18-ske(ARM/国产 JDK) | SKE | 对象存储 | 国产 OS/JDK，ARM 节点池 |
| 本地 | flink:1.18 | 自建 K8s | Ceph/MinIO | 裸金属/虚机 |
| 公有云 VM | flink:1.18 | 客户 K8s | 客户对象存储 | **不绑云托管 Flink/Kafka**，只用裸 VM |
| 私有云 | flink:1.18 | 私有云 K8s | 厂商对象存储 | 客户私有云 |

> 关键约束：云环境只用"裸 K8s + 裸对象存储 + 裸 Kafka"，绝不启用云托管流服务——保持可迁移、不锁云。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 大状态 Checkpoint 慢 | 故障恢复慢、反压 | RocksDB 增量 ckpt + unaligned 屏障 + 状态分桶 |
| CDC 全量阶段锁源库 | 影响业务库 | 无锁快照算法（chunk + binlog 续传），低峰执行 |
| Kafka 端 Exactly-Once 失效 | 重复/丢数据 | 事务 Sink + 两阶段提交 + 幂等写 Iceberg |
| 反压级联 | 整作业吞吐塌陷 | 监控 in/outPoolUsage，自动扩 TM，拆链路 |
| 信创 JDK 兼容 | 算子异常 | 镜像 CI 跑信创 JDK 全量回归，缺失能力降级告警 |
