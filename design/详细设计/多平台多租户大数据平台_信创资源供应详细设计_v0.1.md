# L0.1 信创资源供应 · 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L0 机器供应层
> 套餐：基础版（三档全含）
> 对标：华为鲲鹏 KooLabs / 海光 CPU 纪管 / 飞腾 Phytium 服务器 + 麒麟V10 / openEuler 22.03
> 关联：L0.5 跨环境统一供给抽象（本模块为四环境之一）；L0.6 SKE 控制面（在信创裸机自建 K8s）；L0.10 环境适配框架（信创 Profile）；L0.11 封装层（接口经其暴露）

## 1. 定位与价值

信创资源供应是 L0 机器供应层的**国产化分支**：负责将鲲鹏/海光/飞腾服务器从"裸金属"纳管为"可调度 K8s 节点"，并打上 arch/os/role/zone 标签，供 L0.6 SKE 控制面在此之上自建 K8s 集群。客户无感知底层是信创还是 x86 云主机——统一经 L0.5 抽象。

客户价值：
- "国产合规"——CPU/OS/存储/网络/密码全栈信创，满足政企信创验收清单。
- "一池多架构"——ARM64 与 x86 同池调度，按 arch 标签路由镜像。
- "零差异体验"——上层作业/SQL/存储接口与云环境一致，仅 Profile 不同。

平台价值：纳管逻辑收敛到本模块，L0.6 SKE 只关心"已打标签的节点池"；信创特有驱动（国密卡、国产存储 CSI、ARM 镜像）在本模块适配并固化进 Profile。

## 3. 机器纳管

```text
图：信创机器纳管流程图

裸金属（IPMI/BMC 可达）
        │  ① bootstrap：经 IPMI PXE 引导 openEuler/麒麟
        ▼
纠净机器（OS 装好、SSH 通、基础包就绪）
        │  ② 探测：arch / os / cpu 型号 / 国密卡 / 存储可达性
        ▼
打标签（arch=arm64, os=openeuler, role=data, zone=cn-bj-1）
        │  ③ 装节点 agent + 国密驱动 + 存储 CSI 客户端
        ▼
加入节点池（按 arch+role 路由到对应 SKE 集群待建清单）
        │  ④ 上报 L0.5 抽象层，纳入统一供给视图
        ▼
就绪（供 L0.6 SKE 拉起 K8s 控制面/数据面）
```

纳管幂等：重复执行同一机器只更新标签与 agent 版本，不重装 OS。失败机器进入 `quarantine` 池，告警并保留现场日志。## 4. 节点标签体系

表：节点标签维度说明表

| 标签键 | 取值 | 来源 | 调度用途 |
| --- | --- | --- | --- |
| `arch` | arm64 / x86 | 探测 CPU | 镜像路由（ARM 镜像 vs x86 镜像） |
| `os` | openeuler / kylin / uos | 探测 /etc/os-release | 内核参数/驱动版本分支 |
| `role` | control / data / gpu | 纳管时指定 | SKE 控制面/数据面分布 |
| `zone` | cn-bj-1 / cn-sh-2 … | 纯管时指定 | 跨可用区高可用分布 |
| `crypto` | sm2sm4 / none | 探测国密卡 | 落盘加密调度偏好 |
| `storage` | oceanstor / ceph / nfs | 探测挂载 | CSI 驱动选择 |

标签不可由客户改写，仅由纳管流程与运维审批变更；arch/os 探测后固化，role/zone 纯管时录入可调。

## 5. SKE 在信创上的适配

- **ARM 镜像**：SKE 控制面镜像同时发布 amd64/arm64 双架构 manifest，节点按 arch 拉取对应镜像。
- **国密驱动**：国密卡驱动以 DaemonSet 装在带 `crypto=sm2sm4` 标签的节点；落盘加密经 LUKS+SM4，传输加密经 TLS+SM2 证书。
- **国产存储 CSI**：OceanStor/浪潮存储经厂商 CSI 插件挂载，能力探测后注册到 StorageDriver（见 L2.1）；缺失能力降级或告警。
- **openEuler 内核调优**：纳管时按基线设 `vm.max_map_count=262144`、`net.core.somaxconn=32768`、关 swap、THP=madvise，写入 `/etc/sysctl.d/99-ske.conf`。

## 6. 接口契约

经 L0.11 封装层暴露，客户不直接调；运维/平台内部使用：

```
POST   /api/l0/v1/xc/machines            { bmc, os, role, zone } → 纳管任务                    // ↔ L0.5 NodePool.createPool（XCBaremetalDriver）
GET    /api/l0/v1/xc/machines/{id}       → { status, labels, specs }                              // ↔ L0.5 NodePool.listNodes
PATCH  /api/l0/v1/xc/machines/{id}/labels  { role, zone }   // 仅可改 role/zone
POST   /api/l0/v1/xc/machines/{id}/preflight  → { arch, os, crypto, storage } 检查结果             // ↔ L0.5 preflight（能力矩阵回填 Profile.capabilities）
DELETE /api/l0/v1/xc/machines/{id}     → 退管（清理 agent，不重装 OS）                             // ↔ L0.5 NodePool.drainNode
```

> 所有接口经封装层鉴权与审计；arch/os 标签只读，role/zone 可运维调整。

## 7. 验收

preflight 在纳管完成与 SKE 建集群前各跑一次，四项全过方可入池：

表：preflight 检查项说明表

| 检查项 | 方法 | 通过条件 |
| --- | --- | --- |
| arch | `uname -m` | aarch64 或 x86_64，与申报一致 |
| OS | `/etc/os-release` | openEuler/麒麟/UOS 且版本在支持矩阵 |
| 国密卡 | `lspci` + 驱动加载 | 卡在位且驱动 DaemonSet Ready |
| 存储可达性 | CSI 探针读写 1MB | 厂商存储挂载并读写成功 |

任一不通过：节点置 `quarantine`，不入池，告警待运维处理。

## 8. 风险与对策

表：风险与对策对照表

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| ARM 镜像缺失 | 调度失败 | SKE 双架构 manifest 全量发布；纳管时镜像预拉 |
| 国密卡驱动不稳 | 落盘加密失败 | DaemonSet 健康检查 + 自动重装；preflight 卡门 |
| 国产存储 CSI 兼容差 | 挂载/扩容异常 | 能力探测降级；缺失能力走 NFS 兜底并告警 |
| 麒麟内核 4.19 偏旧 | 部分 K8s 特性不可用 | 限定麒麟节点 role=data；控制面强制 openEuler |
| 跨架构性能差异 | 作业倾斜 | 按 arch 分池 + 调度权重；监控 ARM/x86 时延对比 |

> 本模块是 L0.5 跨环境抽象的信创实现，所有标签与接口与云/本地分支保持同构，差异仅在内层驱动与探测逻辑。
