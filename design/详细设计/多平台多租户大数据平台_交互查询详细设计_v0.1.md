# L2.4 交互查询（Trino 438）· 详细设计（v0.1）

> 归属：多平台多租户大数据平台 · L2 大数据引擎层
> 适用套餐：标准版、旗舰版（基础版不含，对齐 §11.5.1 套餐矩阵）
> 对标：Trino 438（原 PrestoSQL）/ Starburst / Cloudera CDP 即席查询
> 关联：L2.1 统一存储（Iceberg Connector 直查）；L2.7 统一 SQL 网关（路由即席查询到 Trino）；L2.5 Doris（分工：Trino 即席/联邦，Doris OLAP/在线）；L2.6 湖仓集一体（仓层即席查询）

## 1. 定位与价值

交互查询（即"即席查询"与"联邦查询"的合称）是湖仓集一体的**即席/联邦查询引擎**：以 Trino 直接读取 Iceberg 表，无需搬运数据；跨 Iceberg、Doris、外部库做联邦关联；秒级到分钟级返回结果，供数据探查、Ad-hoc 分析、BI 报表。

与 Doris 分工：
- **Trino**：即席查询（Ad-hoc）、联邦查询（跨源 JOIN）、大表全表扫描与复杂分析 SQL；面向数据分析师。
- **Doris**：OLAP 加速（预聚合/物化）、在线高并发点查、毫秒级服务；面向在线应用与 BI Dashboard。

客户价值：
- "零搬运查询"——直接读 Iceberg，无需 ETL 到查询引擎，省存储省时。
- "联邦关联"——一条 SQL 跨 Iceberg + Doris + MySQL 关联，破数据孤岛。
- "标准 SQL"——ANSI SQL 兼容，降低分析师上手成本。

平台价值：
- Trino on K8s（Helm），Coordinator+Worker 分离，弹性扩缩；SKE 拓扑调度亲和对象存储。
- 经 L2.7 统一 SQL 网关统一入口，客户不直连 Trino，鉴权/审计/路由收敛。

## 3. Iceberg Connector

直查 L2.1 统一存储的 Iceberg 表，无需数据拷贝。Catalog 配置示例（`config.properties` / `catalog/iceberg.properties`）：

```properties
connector.name=iceberg
iceberg.catalog.type=rest
iceberg.catalog.uri=http://iceberg-catalog:8181
iceberg.file-format=PARQUET
```

- 元数据走 Iceberg REST Catalog（`iceberg-catalog:8181`，与 L2.1/L2.2/L2.5 及 trino-values.yaml `catalogUri` 一致），数据文件直读对象存储（经 StorageDriver 后端）。
- 支持时间旅行：`SELECT * FROM t FOR VERSION AS OF <snapshot-id>`。
- 支持隐藏分区、Schema 演进，Trino 自动识别 Iceberg manifest 优化裁剪。
- 读 Iceberg 不锁表，与 Spark 写、Flink 流写并发无冲突（快照隔离）。

## 4. 联邦查询

跨 Iceberg / Doris / 外部库关联，Trino 作为联邦查询编排器，下发谓词、流式聚合、内存计算。

SQL 示例：仓层 Iceberg 关联 Doris 物化与外部 MySQL 维表

```sql
SELECT  a.user_id, a.amt, b.region_name, c.level
FROM    iceberg.dws.user_amt      a        -- L2.1 Iceberg 仓层
JOIN    doris.online.user_region  b        -- L2.5 Doris 在线物化
  ON    a.user_id = b.user_id
JOIN    mysql.ext.user_level      c        -- 外部 MySQL 维表
  ON    a.user_id = c.user_id
WHERE   a.dt = CURRENT_DATE
LIMIT   1000;
```

- 谓词下推：Trino 将过滤条件下推到各 Connector，减少回传数据量。
- 跨源 JOIN 在 Coordinator 内存中完成，超大结果应分批或落临时表。
- 外部 JDBC Connector 仅作联邦补充，高频查询应物化到 Iceberg/Doris。

## 5. 接口契约

客户不直连 Trino，统一经 L2.7 SQL 网关路由；网关按"即席/联邦"标签路由到 Trino，按"OLAP/在线"路由到 Doris。

统一入口（L2.7 网关对外暴露，客户可见）：

```
POST /api/sql/v1/query          { sql, workspace, queue } → { queryId }
GET  /api/sql/v1/result/{id}    → { columns, rows, stats, nextPageToken }
GET  /api/sql/v1/status/{id}    → { state, progress, error }
POST /api/sql/v1/cancel/{id}    → { ok }
```

Trino 引擎内部接口（仅网关到 Trino 可达，客户不可见，NetworkPolicy 隔离）：

```
POST /v1/query          网关→Trino Coordinator 提交
GET  /v1/query/{id}     网关→Trino 查询状态/结果
DELETE /v1/query/{id}   网关→Trino 取消查询
```

- 鉴权/审计/配额由网关统一处理；Trino ResourceGroup 承接队列与优先级。
- 结果流式返回，大结果分页（nextPageToken），避免单次回传爆内存。
- JDBC/ODBC 驱动对接网关 `/api/sql/v1/query`，对客户暴露标准协议，隐藏 Trino 私有端点。

## 6. 关键流程

1. **提交**：客户经网关提交 SQL，网关鉴权后按标签路由到 Trino Coordinator。
2. **解析计划**：Coordinator 解析 SQL → 逻辑计划 → 物理计划，按 Catalog 拆分 Split。
3. **调度分发**：Coordinator 将 Split 分发到 Worker，SKE 拓扑调度使 Worker 亲和存储节点。
4. **并行执行**：Worker 并行拉取 Iceberg/Doris/外部数据，谓词下推，本地过滤聚合。
5. **结果聚合**：Worker 部分结果回传 Coordinator，流式聚合排序，分页返回网关→客户。
6. **超时熔断**：超时/内存超限触发查询取消，释放 Worker 资源，告警入审计。

## 7. 资源与调优

- **Worker 内存**：`query.max-memory-per-node` 限制单查询单节点内存，超限 fail-fast。
- **并发数**：`query.max-concurrent-queries` + ResourceGroup 分租户/队列限并发。
- **SKE 拓扑调度**：Worker Pod 反亲和 Coordinator，节点亲和对象存储所在节点，缩短读路径。
- **查询超时**：`query.execution-timeout` 默认 30min，超时自动取消；Ad-hoc 队列更短。
- **熔断**：连续失败/资源耗尽触发熔断，降级排队或拒绝新查询，保护集群稳定。
- **弹性扩缩**：HPA 按队列长度/内存利用率扩 Worker，闲时缩容，Coordinator 固定 1 副本。

## 8. 多环境适配

| 环境 | 部署形态 | 存储对接 | 备注 |
| --- | --- | --- | --- |
| 信创 | SKE on 国产 K8s，Trino ARM/X86 | 国产对象存储 + Iceberg | 优先国产 JRE，验证 ARM 性能 |
| 本地数据中心 | SKE on 裸金属/虚机 | Ceph RGW/MinIO + Iceberg | 自建 HMS，Worker 亲和存储节点 |
| 公有云 VM | SKE on 客户云 VM | 客户云对象存储（S3/OBS/OSS） | 客户提供密钥，不启云托管 Trino |
| 私有云 | SKE on 私有云 VM | 厂商对象存储/MinIO + Iceberg | 同构 Helm Chart，仅换 Profile |

> 关键约束：四环境同一套 Helm Chart + Catalog 配置模板，差异仅在 StorageDriver 后端与镜像仓库；不依赖任何云托管查询服务，保持可迁移。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 跨源大表 JOIN 爆内存 | 查询 OOM 失败 | 限制 JOIN 结果集；引导物化到 Iceberg/Doris；分批查询 |
| 即席大扫描压垮集群 | 影响其他查询 | ResourceGroup 限并发/内存；超时熔断；大查询走专用队列 |
| 对象存储读放大 | 查询慢、小文件多 | 依赖 L2.1 compaction；Trino 谓词下推 + Iceberg 分区裁剪 |
| 信创 ARM 性能 | 吞吐不及 X86 | 选型已验证 ARM 支持；调优 JVM/向量化；必要时 X86 节点混部 |
| 客户直连绕过网关 | 鉴权审计缺失 | NetworkPolicy 仅放行网关到 Trino；Trino 不暴露客户可达端点 |
