# 性能测试计划

> 归属：多平台多租户大数据平台 · 测试文档
> 版本：v1.0 ｜ 日期：2026-08-17 ｜ 状态：已完成
> 关联：`design/测试/测试规范.md`；`design/运维/运维手册.md`；`design/接口规范/统一API规范.md`；`design/v2.0/V2.0_架构设计文档.md`
> 适用范围：全平台 12 个 Spring Boot 应用 + 引擎层（Spark/Flink/Trino/Doris）+ 前端控制台
> 优先级：P0（必须补齐）

---

## 1. 测试目标

### 1.1 总体目标

通过系统化性能测试，验证多平台多租户大数据平台在目标负载下满足 SLA，识别性能瓶颈，建立性能基线，为容量规划和上线决策提供量化依据。

### 1.2 量化指标

| 指标 | 目标值 | 度量方式 | 备注 |
| --- | --- | --- | --- |
| API P99 延迟 | < 200ms | k6 trend `http_req_duration` | 控制面 API |
| API P95 延迟 | < 100ms | k6 trend | 控制面 API |
| API P99 延迟 | < 500ms | k6 trend | 数据面查询 API |
| TPS | > 1000 | k6 counter `http_reqs` / s | 控制面混合场景 |
| 并发用户 | ≥ 500 | k6 VUs | 单租户 |
| 多租户并发 | ≥ 50 租户 | k6 stages | 平台级 |
| 控制面可用性 | > 99.9% | 错误率统计 | 测试期间 |
| 数据面可用性 | > 99.5% | 错误率统计 | 测试期间 |
| 作业提交成功率 | > 99% | 业务自定义指标 | Spark/Flink/SQL |
| 引擎查询 P99 | < 3s | Trino/Doris 慢查询日志 | 1 亿行级 |
| 资源利用率 | CPU < 80%，内存 < 85% | Prometheus | 峰值负载 |

### 1.3 测试范围

- **控制面 API**：租户管理、用户认证、资产目录、作业管理、权限校验、计量计费等 12 个 Spring Boot 应用核心接口。
- **数据面查询**：统一 SQL 网关、Trino 交互查询、Doris OLAP 查询、Iceberg 表读写。
- **批流作业**：Spark 批作业提交与执行、Flink 流作业状态切换、调度编排吞吐。
- **前端控制台**：首屏加载、页面切换、列表分页、图表渲染。
- **多租户隔离**：50 租户并发下隔离开销与稳定性。

## 2. 测试工具

### 2.1 工具选型

| 工具 | 用途 | 选型理由 |
| --- | --- | --- |
| k6（JavaScript） | HTTP API 负载/压力/容量测试 | 脚本用 JS、高性能、自定义指标灵活、CI 友好 |
| JMeter | 复杂场景 + JDBC + MQTT 协议 | 协议覆盖广、GUI 录制、报表完整 |
| Prometheus + Grafana | 测试过程监控 + 基线采集 | 与生产监控同栈，结果可对比 |
| Jaeger / Tempo | 链路追踪定位瓶颈 | 与生产可观测同栈 |
| Locust（备选） | 分布式压测补充 | Python 生态，便于扩展 |

### 2.2 k6 脚本规范

- 脚本语言：JavaScript（ES6+），文件命名 `*.js`，场景命名 camelCase。
- 自定义指标命名：snake_case（如 `biz_success_rate`、`tenant_op_latency`）。
- 配置外置：URL、阈值、阶段参数从 `__ENV` 读取，禁止硬编码。
- 数据驱动：测试数据从 CSV/JSON 注入，支持多租户 Token 池。
- 阈值断言：每个脚本必须定义 `thresholds`，失败即退出码非 0。

### 2.3 测试数据准备

- 租户：预置 50 租户，每租户 10 用户，Token 通过 OIDC 接口批量签发。
- 数据：1 亿行订单事实表 + 100 万维度表 + 1000 个 Iceberg 表元数据。
- 作业：预置 100 个 Spark 批作业定义 + 20 个 Flink 流作业定义。
- 数据可重建：所有数据通过 `make data-perf-prepare` 一键生成与销毁。

| 编号 | 场景 | 类型 | 目标 | 时长 |

| P-06 | 流作业状态切换 | 负载 | 20 作业并发切换 < 5s | 15min |
| P-07 | 持续 8h 稳定性 | 耐久 | 1000 TPS 8h 无衰减 | 8h |

### 3.2 场景 P-01 控制面 API 基线负载（示例）

```javascript
// 代码示例：控制面API基线负载（k6 JavaScript）
import http from 'k6/http';
import { check, sleep } from 'k6';
import { Trend, Rate, Counter } from 'k6/metrics';

const bizSuccessRate = new Rate('biz_success_rate');
const tenantOpLatency = new Trend('tenant_op_latency');
const totalOps = new Counter('total_ops');

export const options = {
  stages: [
    { duration: '2m', target: 200 },   // ramp-up
    { duration: '20m', target: 1000 }, // 稳定负载
    { duration: '5m', target: 1000 },  // 持续
    { duration: '3m', target: 0 },     // ramp-down
  ],
  thresholds: {
    http_req_duration: ['p(99)<200', 'p(95)<100'],
    http_req_failed: ['rate<0.001'],
    biz_success_rate: ['rate>0.999'],
  },
};

const tokens = __ENV.TOKEN_POOL.split(',');

export default function () {
  const token = tokens[__VU % tokens.length];
  const params = { headers: { Authorization: `Bearer ${token}` } };
  const r = http.get(`${__ENV.BASE_URL}/api/v1/catalog/assets?page=1&size=20`, params);
  check(r, { 'status 200': (x) => x.status === 200 });
  bizSuccessRate.add(r.status === 200);
  tenantOpLatency.add(r.timings.duration);
  totalOps.add(1);
  sleep(0.05);
}
```

### 3.3 场景 P-08 极限压力（找拐点）

- 阶梯加压：从 500 TPS 起每 2 分钟提升 250 TPS，直到错误率 > 1% 或 P99 > 500ms。
- 记录拐点 TPS、对应 CPU/内存/连接池/锁等待。
- 输出容量上限报告，作为容量规划输入（参见 `design/运维/容量规划指南.md`）。

## 4. 测试环境

### 4.1 环境规格

| 维度 | 规格 | 备注 |
| --- | --- | --- |
| K8s 集群 | 3 master + 10 worker | master 4C8G，worker 16C64G |
| 数据库 | openGauss 3 节点 | 8C32G，SSD 500G |
| 引擎 | Spark 3.5 / Flink 1.18 / Trino 428 / Doris 2.1 | 独立资源池 |
| 监控 | Prometheus + Grafana + Loki + Tempo | 与生产同栈 |
| 网络 | 内网万兆，跨机房千兆 | 与生产同拓扑 |
| 数据量 | 1 亿事实表 + 100 万维度 | 见 §2.3 |

### 4.2 环境隔离

- 性能测试专用集群，禁止与 dev/staging 共用。
- 测试数据物理隔离：独立 namespace + 独立存储卷 + 独立数据库实例。
- 测试期间关闭非必要后台作业（如非压测作业、自动扩缩容）。
- 每次测试前执行 `make env-reset` 还原基线状态。

## 5. 执行计划

### 5.1 阶段划分

| 阶段 | 内容 | 产出 | 工期 |
| --- | --- | --- | --- |
| 准备 | 环境搭建 + 数据准备 + 脚本开发 | 12 个 k6 脚本 + 环境就绪 | 5d |
| 基线 | P-01 ~ P-06 基线场景 | 基线报告 v1.0 | 3d |
| 耐久 | P-07 8h 稳定性 | 稳定性报告 | 2d |
| 压力 | P-08 ~ P-10 极限与恢复 | 容量上限 + 熔断验证 | 3d |
| 前端 | P-11 ~ P-12 前端 + 冷启动 | 前端性能报告 | 2d |
| 复盘 | 瓶颈分析 + 优化建议 | 性能测试总结报告 | 2d |

### 5.2 触发时机

- **每次发布前**：必跑 P-01、P-03、P-04，作为发布门禁。
- **每日定时**：P-01 基线回归，对比基线偏差 > 10% 告警。
- **架构变更后**：全量 12 场景回归。
- **容量评估前**：P-08 极限压力刷新容量上限。

### 5.3 CI 集成

- PR 流水线：触发 P-01 短时版本（5min），失败阻断合并。
- 夜间流水线：触发 P-01 ~ P-06 完整版，结果推送 Grafana 大盘。
- 发布流水线：触发 P-01 ~ P-12 全量，输出发布性能报告。

## 6. 结果分析与报告

### 6.1 报告内容

每份场景报告必须包含：

1. 场景描述 + 执行参数 + 执行时间。
2. 核心指标实测值与目标值对照表。
3. TPS/延迟随时间曲线图。
4. 资源利用率（CPU/内存/网络/IO）曲线。
5. 错误分类统计与根因初判。
6. 通过/未通过结论 + 未通过项的优化建议。

### 6.2 通过标准

- 所有核心指标达到 §1.2 目标值。
- 8h 稳定性场景 TPS 衰减 < 5%，无内存泄漏迹象。
- 极限压力场景明确给出容量上限与拐点。
- 熔断降级在阈值触发后 5s 内生效，恢复后 30s 内回到正常水位。

### 6.3 失败处理

- 单项指标未达标：定位瓶颈 → 提交优化 issue → 复测至达标。
- 环境问题：记录环境差异 → 修正环境 → 重跑。
- 数据问题：校验数据量与分布 → 重新准备数据 → 重跑。

## 7. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| 测试环境与生产差异大 | 中 | 结果失真 | 严格对齐生产规格，差异项显式标注 |
| 测试数据分布失真 | 中 | 指标偏差 | 按生产抽样构造数据，定期刷新 |
| 压测影响生产监控 | 低 | 误告警 | 独立集群 + 独立监控命名空间 |
| 引擎资源争抢 | 中 | 指标抖动 | 引擎独立资源池，按场景隔离 |
| 8h 耐久成本高 | 高 | 排期紧张 | 8h 改为每周一次，日常用 1h 简版 |
