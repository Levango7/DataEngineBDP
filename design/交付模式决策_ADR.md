# ADR：交付模式决策（私有化 vs SaaS）

> 版本：v1.0 ｜ 日期：2026-09-12 ｜ 状态：决策定稿
> 关联文档：`design/多平台多租户大数据平台_产品原型设计_v0.4.md` §2.1 交付模式澄清、§11.5 套餐与定价模型、`design/定位收敛决策_v1.0.md`
> 决策背景：评估报告指出"SaaS 与私有化定位模糊，多租户面向谁不清晰"。本文档记录私有化 vs SaaS 决策依据、共存机制与切换方案。

---

## 1. 决策标题

**ADR-002：以私有化交付为主模式，托管 SaaS 为可选增量模式，两者共享同一代码库通过 DELIVERY_MODE Profile 切换**

---

## 2. 决策上下文

### 2.1 问题陈述

平台同时声称"私有化可交付"与"对内对外兼顾 SaaS"，导致两个歧义：
1. SaaS 与私有化是否同一产品？是否需要维护两套代码？
2. 多租户面向谁？私有化下"多租户"指什么？

### 2.2 约束

- 5 人团队 + 12 个月交付约束（见定位收敛决策_v1.0.md），不可能同时工程化两种交付模式。
- 客户群体分化：大型企业/金融/政务要求数据在自有机房（私有化），中小客户要求快速试用低门槛（SaaS）。
- 信创合规要求高场景必须私有化（数据不出客户机房）。

---

## 3. 决策方案

### 3.1 私有化交付（主模式，v2.1 当前）

| 项 | 值 |
| --- | --- |
| 部署形态 | K8s 在客户自有机器（信创/本地/云 VM）上自建，平台整体部署在客户机房 |
| 多租户面向 | **客户内部多业务线**（type=internal），按"组织-项目"粒度共享资源池 |
| 计费模型 | 平台许可费（一次性买断）+ 年度服务费 + 节点附加 + 信创适配附加（见 §11.5.4） |
| 数据主权 | 数据存储在客户自有集群，客户完全掌控 |
| 运营后台 | 客户租户管理员可只读访问（监控全局水位/告警），写操作仅平台超管 |
| 启用版本 | v2.1（当前） |
| 切换方式 | `DELIVERY_MODE=private` Spring Profile |

### 3.2 托管 SaaS（可选模式，v2.3+ 规划）

| 项 | 值 |
| --- | --- |
| 部署形态 | 由平台运营方在自有集群上提供托管多租户，客户不接触 K8s 与机房 |
| 多租户面向 | **外部中小客户**（type=external），按套餐独占或共享资源池 |
| 计费模型 | 按月订阅费 + 超量计费（见 §11.5.4.1 SaaS 订阅起价） |
| 数据主权 | 数据存储在平台方集群，客户按合规要求选择是否接受 |
| 运营后台 | 外部租户不可见运营后台，仅见租户内控制台 |
| 启用版本 | v2.3+（规划中） |
| 切换方式 | `DELIVERY_MODE=saas` Spring Profile |

---

## 4. 共存机制

### 4.1 共享同一代码库

两种交付模式**共享同一代码库**，不维护两套代码分支。差异通过以下机制收敛：

| 层 | 共享 | 差异 |
| --- | --- | --- |
| 控制台（L5.1） | ✅ 同一 Vue3 前端 | 无 |
| 封装层（L0.11） | ✅ 同一 K8s 翻译逻辑 | 无 |
| 引擎层（L2） | ✅ 同一 Spark/Flink/Doris/Iceberg | 无 |
| 治理层（L3） | ✅ 同一元数据/质量/血缘/资产 | 无 |
| 横切（X1–X4） | ✅ 同一 Keycloak/APISIX/安全/运维 | 无 |
| 计费引擎（L5.2） | 同一计量采集 | 私有化按许可+年度服务费；SaaS 按月订阅+超量计费 |
| 运营后台可见性 | 同一运营后台 | 私有化对内部租户只读；SaaS 对外部租户不可见 |
| 资源池调度 | 同一 K8s 调度 | 私有化独占客户硬件；SaaS 共享平台方资源池 |

### 4.2 Profile 切换

```yaml
# application-private.yaml（私有化，v2.1 默认）
delivery:
  mode: private
  billing:
    strategy: license-plus-annual  # 许可费 + 年度服务费
  operations-console:
    tenant-admin-access: read-only  # 内部租户管理员只读
  resource-pool:
    ownership: customer-dedicated  # 独占客户硬件

# application-saas.yaml（SaaS，v2.3+）
delivery:
  mode: saas
  billing:
    strategy: subscription-plus-overage  # 月订阅 + 超量计费
  operations-console:
    tenant-admin-access: none  # 外部租户不可见
  resource-pool:
    ownership: platform-shared  # 共享平台方资源池
```

切换方式：启动时通过 `--spring.profiles.active=private` 或 `=saas` 激活对应配置，业务代码无感知。

## 5. 决策依据

| 维度 | 私有化（主） | SaaS（可选） | 依据 |
| --- | --- | --- | --- |
| 客户群体 | 大型企业/金融/政务/信创 | 中小客户/快速试用 | 私有化客户预算高、合规要求高；SaaS 客户门槛低、弹性优先 |
| 数据合规 | 数据在客户机房，合规无争议 | 数据在平台方，需客户接受 | 金融/政务必须私有化；中小客户可接受 SaaS |
| TCO（3 年） | 基础版约 43 万（首年 29 万 + 后续 7 万/年） | 基础版约 7.2 万 | SaaS TCO 低但数据在平台方；私有化 TCO 高但数据自主 |
| 工程成本 | v2.1 可交付（主链路 11 模块） | v2.3+ 可交付（需托管资源池调度） | SaaS 需额外实现共享资源池隔离与计费引擎，5 人团队 v2.1 不可能完成 |
| 市场切入 | 私有化先打信创/大型企业标杆 | SaaS 后放大规模 | 先私有化建标杆，再 SaaS 放量 |

> **结论**：私有化是主模式，因①合规要求高场景必须私有化；②5 人团队 v2.1 只能做私有化；③私有化先建标杆客户。SaaS 是可选增量，因①中小客户需求存在；②共享代码库成本低；③v2.3 规模放大时启动。

---

## 6. 非目标声明

- **v2.1 不做 SaaS 托管运营**：`DELIVERY_MODE=saas` Profile 存在但不激活，计费引擎与托管资源池调度移至 v2.3+。
- **不维护两套代码分支**：两种模式共享同一代码库，差异通过 Profile 收敛。
- **不做混合云交付**：不支持"部分模块私有化 + 部分模块 SaaS"的混合形态，每个实例只启用一种交付模式。
