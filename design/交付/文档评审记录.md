## 2. 评审标准

### 2.1 评审维度

| 维度 | 说明 | 权重 |
| --- | --- | --- |
| 完整性 | 文档覆盖需求的所有方面，无遗漏关键章节 | 30% |
| 准确性 | 文档内容与技术实现一致，数据/版本/路径准确 | 30% |
| 一致性 | 跨文档术语、格式、版本号、引用路径一致 | 20% |
| 可读性 | 结构清晰、层次分明、语言简洁、示例充分 | 20% |

### 2.2 检查项

| 类别 | 检查项 |
| --- | --- |
| 路径有效性 | 文档引用的文件路径是否存在 |
| 交叉引用 | 文档间的交叉引用是否正确（双向可达） |
| 术语一致 | 术语使用是否一致（如"租户"不混用"workspace"） |
| 版本统一 | 版本号是否统一（同一文档不同位置版本号一致） |
| 格式规范 | Markdown 标题层级、代码块命名、表格格式是否规范 |
| 章节完整 | 是否包含必备章节（概述、关联、版本变更） |
| 元信息完整 | 文档头部的归属/版本/日期/状态/关联/适用范围是否完整 |

### 6.3 改进建议

1. **建立术语表**：建议在 `design/开发规范/术语表.md` 中建立统一术语表，作为文档编写基线，避免术语漂移。
2. **自动化校验**：引入 markdown-link-check + vale 等工具，在 CI 中自动校验文档链接与风格。
3. **逐字评审**：后续安排模块 owner 对 40+ 份详细设计文档逐字评审，重点检查技术细节与代码一致性。
4. **评审常态化**：每季度执行一次全量文档评审，建立评审基线，跟踪文档质量趋势。
5. **文档度量**：建立文档度量看板，含完成率、评审通过率、问题修复率、文档活跃度等指标。
