# 定位收敛决策（v1.0）

> 版本：v1.0 ｜ 日期：2026-09-12 ｜ 状态：决策定稿
> 关联文档：`design/多平台多租户大数据平台_产品原型设计_v0.4.md` §1.5 分阶段定位、`ROADMAP.md` 定位收敛声明
> 决策背景：评估报告指出"七大维度全量并行 + 5 人团队 + 12 个月"不可行，需收敛为分版本聚焦有限维度。本文档记录七大维度优先级排序依据、资源分配比例与非目标声明。

---

## 1. 七大维度定义

本平台的产品定位由以下七个维度构成，每个维度独立可验收：

| 编号 | 维度 | 定义 | 对应模块/能力 |
| --- | --- | --- | --- |
| D1 | 本地数据中心交付 | 在客户本地机房 x86 裸金属/虚机上自建 K8s 并交付完整平台 | L0.2、L0.5–L0.12、L2–L5 |
| D2 | 湖仓集主链路 | 湖→仓→集三级 + 统一 SQL 网关 + 主链路端到端跑通 | L2.1、L2.6、L2.7、L3.5、L5.1 |
| D3 | 多租户隔离与计量 | 租户/工作空间/项目隔离 + 计量计费 + 运营后台 | L0.11、L5.2、X1、X4、§11 |
| D4 | K8s 透明封装 | 客户无感知 K8s，仅见业务语义 | L0.11 封装层 |
| D5 | 信创优先适配 | 国产芯片/OS/国密/ARM 全量验证 | L0.1、X1 国密、§5.3 信创 Profile |
| D6 | AI 一站式 | 向量库 + 知识工程 + LLMOps + 领域大模型接口 | L4.5.3–L4.5.6 |
| D7 | 公有云/私有云交付 | 四环境零改动交付 + SaaS 托管运营 + 数据资产流通 | L0.3、L0.4、L5.6、§11.5.4.1 SaaS |

## 2. 优先级排序与依据

| 优先级 | 维度 | 排序依据 | 不可延后理由 |
| --- | --- | --- | --- |
| P0 | D1 本地数据中心交付 | 最小可售卖形态，无本地交付则无商业化基础 | 私有化是主交付模式（见交付模式决策_ADR），必须先行 |
| P0 | D2 湖仓集主链路 | 平台核心价值链，决定"是不是大数据平台" | 无主链路则其余维度无承载 |
| P0 | D3 多租户隔离与计量 | 私有化面向"客户内部多业务线"的必要条件 | 无多租户则无法支撑多业务线复用与计费 |
| P0 | D4 K8s 透明封装 | 商用可交付的关键，客户不买 K8s | 无封装则客户技术门槛过高，无法售卖 |
| P1 | D5 信创优先适配 | 差标护城河，但需本地主链路先稳 | 信创适配依赖主链路跑通后再做 ARM/国密验证 |
| P1 | D6 AI 一站式 | 差标护城河，但属增量能力非基础 | AI 层复用 L2/L3 数据，需主链路先就绪 |
| P2 | D7 公有云/私有云交付 | 规模放大，但依赖前六维稳定 | 四环境适配需主链路 + 信创验证后才能保证零改动 |

> **排序逻辑**：P0 是"能卖私有化"的最小集（四维度），P1 是"差异化护城河"（信创 + AI），P2 是"规模放大"（公有云 + 商业化）。优先级递减不代表不重要，而是代表"可以晚做而不破坏已交付价值"。

## 4. 非目标声明（明确不做，避免范围蔓延）

### 4.1 v2.1 非目标

- **不做信创全量适配**：信创环境仅做 PoC 级验证（鲲鹏 ARM 可拉起），不做国密全链路改造与等保三级测评。
- **不做 AI 一站式**：L4.5.3–L4.5.6 智能数据层保留设计文档，工程实现移至 v2.2（见 §16.4.2）。
- **不做公有云/私有云交付**：L0.3/L0.4 保留 Profile 驱动框架，但不做真实云 API 联调。
- **不做 SaaS 托管运营**：§11.5.4.1 SaaS 订阅定价仅为设计，不实现托管多租户运营。
- **不做数据资产流通**：L5.6 移至 v2.3。

### 4.2 v2.2 非目标

- **不做公有云/私有云交付**：四环境适配框架就绪，但不做真实云 VM 联调。
- **不做 SaaS 托管运营**：仅支持私有化交付（DELIVERY_MODE=private）。
- **不做数据资产流通**：L5.6 移至 v2.3。

### 4.3 v2.3 非目标

- 无（七维度全量交付，进入商业化运营阶段）。

## 5. 收敛约束与变更控制

1. **单调递增**：每个版本只新增定位维度，不回退已交付维度。若新维度导致已交付维度主链路退化，则新维度阻断上线。
2. **资源不超载**：任一版本的资源分配总和 = 100%，不通过加班或扩团队突破 5 人 × 12 个月约束。
3. **非目标不可偷做**：非目标声明中的能力，即使工程上"顺手做了"也不纳入版本验收，避免范围蔓延。
4. **变更需评审**：本决策的版本-维度映射变更需经架构评审（至少 3 人签字），并同步更新 `design/多平台多租户大数据平台_产品原型设计_v0.4.md` §1.5 与 `ROADMAP.md` 定位收敛声明。
