## 第1章 平台登录与导航

### 1.1 平台访问

- 域名：由所在租户管理员提供，形如 `https://console.<env>.dataengine.example.com`。
- 浏览器：Chrome 90+ / Edge 90+ / Firefox 88+，信创环境用奇安信/红莲花浏览器。
- 账号：由租户管理员创建并发放，首次登录强制改密 + 绑定 MFA。

### 1.2 登录步骤

1. 访问控制台域名。
2. 输入账号与密码。
3. 输入 MFA 验证码（TOTP 或钉钉扫码）。
4. 首次登录完成初始化设置（改密/MFA/保密协议/个人信息）。
5. 进入控制台首页。

### 1.3 控制台导航

登录后左侧菜单（按角色权限可见性不同）：

| 菜单 | 子菜单 | 数据工程师 | 数据分析师 |
| --- | --- | --- | --- |
| 概览 | 工作台 / 通知 / 待办 | ✅ | ✅ |
| 数据 | 数据集成 / 数据源 / 数据湖 | ✅ | ✅（只读） |
| 开发 | 作业开发 / SQL 网关 / 调度 | ✅ | ✅（SQL） |
| 治理 | 资产目录 / 元数据 / 血缘 / 质量 | ✅ | ✅ |
| BI | 数据集 / 图表 / 仪表盘 | ✅ | ✅ |
| 运维 | 仅本租户监控 | ✅（只读） | ❌ |

### 1.4 工作台

工作台首页展示：

- **待办**：待审批/待处理任务（如数据集申请、质量告警）。
- **最近使用**：最近访问的作业/SQL/仪表盘。
- **快捷入口**：新建作业/新建 SQL/新建仪表盘。
- **租户公告**：管理员发布的公告。
- **资源用量**：本租户/本项目的配额使用率。

### 1.5 全局搜索

- 快捷键 `Ctrl+K` 唤起全局搜索。
- 支持搜索：作业 / SQL / 数据集 / 图表 / 仪表盘 / 数据资产。
- 支持模糊匹配与拼音首字母。

## 第2章 数据集成

### 2.1 数据集成概念

数据集成（Data Integration）将外部数据源数据同步到平台数据湖或数仓，是数据开发的第一步。

- **数据源**：外部系统连接配置（MySQL/Oracle/Kafka/FTP/S3 等）。
- **同步任务**：定义从源到目标的同步规则与调度。
- **同步模式**：全量 / 增量 / CDC 实时 / 定时。

### 2.2 创建数据源

#### 2.2.1 入口

`数据 → 数据集成 → 数据源 → 新建数据源`

#### 2.2.2 支持的数据源类型

| 类型 | 用途 | 同步模式 |
| --- | --- | --- |
| MySQL / PostgreSQL / Oracle / SQLServer | 关系型数据库 | 全量 / 增量 / CDC |
| Kafka | 流数据 | 实时 |
| FTP / SFTP | 文件 | 全量 / 增量 |
| S3 / OSS / OBS | 对象存储 | 全量 / 增量 |
| HDFS | Hadoop 文件 | 全量 / 增量 |
| HTTP API | 接口数据 | 定时拉取 |

#### 2.2.3 创建 MySQL 数据源（示例）

1. 点击"新建数据源"，选择类型"MySQL"。
2. 填写表单：

   | 字段 | 必填 | 示例 |
   | --- | --- | --- |
   | 数据源名称 | 是 | `业务库-订单` |
   | 数据源类型 | 是 | `MySQL` |
   | 主机 | 是 | `10.0.1.10` |
   | 端口 | 是 | `3306` |
   | 数据库名 | 是 | `order_db` |
   | 账号 | 是 | `debdp_reader` |
   | 密码 | 是 | `***` |
   | SSL | 否 | 启用 |
   | 网络通道 | 否 | `VPC` / `公网` / `VPN` |

3. 点击"测试连接"，须返回"连接成功"。
4. 点击"保存"，数据源创建完成。

#### 2.2.4 凭证安全

- 密码使用国密 SM4 加密存储，明文不可见。
- 凭证轮转：建议 90 天更换一次数据库账号密码，更新数据源配置。
- 网络通道：优先 VPC/VPN，避免公网直连。

### 2.3 配置同步任务

#### 2.3.1 入口

`数据 → 数据集成 → 同步任务 → 新建任务`

#### 2.3.2 配置向导（4 步）

**第 1 步：选择源与目标**

- 源：选择已创建的数据源 + 源表（可多选）。
- 目标：选择数据湖（Iceberg）/ 数仓（Doris）/ Kafka / HDFS。
- 自动读取源表 Schema，目标表可自动建表或选已有表。

**第 2 步：字段映射**

- 默认同名映射，可自定义目标字段名。
- 类型自动转换（如 MySQL `DATETIME` → Iceberg `TIMESTAMP`）。
- 可添加常量字段、忽略字段、应用脱敏函数。

**第 3 步：同步策略**

| 策略 | 说明 | 适用 |
| --- | --- | --- |
| 全量覆盖 | 每次全量拉取覆盖目标 | 小表 / 维表 |
| 增量 upsert | 按主键 upsert 增量数据 | 大表 / 事实表 |
| CDC 实时 | 监听 binlog 实时同步 | 实时场景 |
| 定时全量 | Cron 定时全量 | 周期性全量 |

**第 4 步：调度配置**

- 触发方式：手动 / Cron 定时 / 事件触发（如上游任务完成）。
- Cron 示例：`0 0 * * *`（每日 0 点）、`0 */1 * * *`（每小时）。
- 高级：并发度 / 批大小 / 错误阈值 / 重试次数 / 超时。

#### 2.3.3 提交与运行

1. 配置完成后点击"保存"或"保存并提交"。
2. 任务进入"已保存"或"运行中"状态。
3. 可在任务列表查看状态、监控、日志。

### 2.4 查看同步状态

#### 2.4.1 任务列表

`数据 → 数据集成 → 同步任务`

| 字段 | 说明 |
| --- | --- |
| 任务名称 | 用户命名 |
| 源 → 目标 | 数据源与目标简述 |
| 同步模式 | 全量/增量/CDC |
| 状态 | 运行中/成功/失败/已暂停 |
| 最近同步 | 最后一次同步时间 |
| 下次同步 | 下次调度时间 |
| 吞吐 | 最近同步速率（行/秒） |

#### 2.4.2 任务详情

点击任务进入详情页：

- **概览**：状态/进度/吞吐/延迟/错误数。
- **运行历史**：历次同步记录，可查看单次日志。
- **监控图表**：吞吐/延迟/错误数时间序列。
- **配置**：查看/编辑任务配置。
- **日志**：实时日志 + 历史日志，可按级别筛选。

#### 2.4.3 操作

- **暂停 / 恢复**：暂停后调度不触发，恢复后继续。
- **立即执行**：忽略调度立即触发一次。
- **停止**：停止运行中的同步（CDC 停止后可从断点续传）。
- **删除**：软删除，30 天回收站。

### 2.5 数据集成 FAQ

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| 测试连接失败 | 网络不通 / 账号权限不足 | 检查网络通道 / 授予 SELECT 权限 |
| CDC 同步延迟高 | 源库 binlog 量大 / 并发不足 | 提升并发度 / 拆分表 |
| 同步任务失败 | 源表 Schema 变更 / 字段类型不兼容 | 更新映射 / 修正类型 |
| 全量同步慢 | 表过大 / 批大小过小 | 增大批大小 / 分片并行 |
| 目标表数据重复 | 未设主键 / upsert 配置错 | 配置主键与 upsert 字段 |

## 第3章 作业开发

### 3.1 作业概念

作业（Job）是在大数据引擎上运行的具体任务，平台支持四类引擎：

| 引擎 | 作业类型 | 典型场景 |
| --- | --- | --- |
| Spark | Spark SQL / Jar / PySpark / Notebook | 批处理 / 大规模 ETL / ML |
| Flink | Flink SQL / Jar / PyFlink | 流处理 / 实时入仓 / CEP |
| Trino | SQL | 联邦查询 / 即席分析 |
| Doris | SQL | 实时数仓 / 高并发查询 |

### 3.2 创建 Spark 作业

#### 3.2.1 入口

`开发 → 作业开发 → 新建作业 → Spark`

#### 3.2.2 表单字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 作业名称 | 是 | 用户命名 |
| 作业类型 | 是 | SQL / Jar / PySpark / Notebook |
| 引擎版本 | 是 | Spark 3.5（默认） |
| 工作空间 | 是 | 决定数据源与资源队列 |
| 资源队列 | 是 | 引擎内资源队列 |
| 优先级 | 否 | 高/中/低，默认中 |
| 描述 | 否 | 备注 |

#### 3.2.3 Spark SQL 作业示例

场景：将 ODS 订单表清洗为 DWD 订单表。

```sql
-- Spark SQL功能名：ODS订单清洗为DWD订单
SET spark.sql.iceberg.handle-timestamp-without-timezone = true;

INSERT INTO dwd.dwd_order
SELECT
    order_id,
    user_id,
    product_id,
    CAST(order_amount AS DECIMAL(18,2)) AS order_amount,
    FROM_UNIXTIME(order_time, 'yyyy-MM-dd HH:mm:ss') AS order_time,
    '${dt}' AS dt
FROM ods.ods_order
WHERE dt = '${dt}'
  AND order_id IS NOT NULL
  AND order_amount > 0;
```

参数化：`${dt}` 为调度参数，运行时由调度器传入（如 `2026-08-18`）。

#### 3.2.4 资源配置

| 配置 | 推荐值 | 说明 |
| --- | --- | --- |
| driver CPU | 1–4 核 | driver 进程 CPU |
| driver 内存 | 1–4 Gi | driver 进程内存 |
| executor 数 | 2–20 | executor 实例数 |
| executor CPU | 1–4 核 | 单 executor CPU |
| executor 内存 | 2–8 Gi | 单 executor 内存 |
| 并行度 | executor 数 × executor CPU | shuffle 并行度 |

> 资源不足会导致作业 OOM 或排队，过大浪费资源。建议小作业 2 executor × 2 核 × 4Gi，大作业按数据量估算。

### 3.3 提交作业

#### 3.3.1 提交步骤

1. 在作业编辑器编写 SQL/代码。
2. 点击"语法检查"确认无误。
3. 点击"提交"，选择资源配置。
4. 确认提交，作业进入"已提交"状态。
5. 引擎调度后状态变为"运行中"。
6. 完成后状态为"成功"或"失败"。

#### 3.3.2 作业状态流转

```text
草稿 → 已提交 → 排队 → 运行中 → 成功
                                → 失败
                                → 已停止
```

### 3.4 查看作业日志

#### 3.4.1 日志类型

- **driver 日志**：driver 进程 stdout/stderr，含 SQL 执行计划。
- **executor 日志**：各 executor 进程日志，含 task 级别信息。
- **引擎日志**：Spark Master/Worker 日志（运维可查）。

#### 3.4.2 查看方式

- `作业详情 → 日志`：实时滚动日志，可按 driver/executor 切换。
- 日志支持按级别（INFO/WARN/ERROR）筛选。
- 支持关键字搜索与时间范围筛选。
- 可下载完整日志（压缩包）。

#### 3.4.3 常见日志关键字

| 关键字 | 含义 | 处理 |
| --- | --- | --- |
| `OutOfMemoryError` | OOM | 增大内存 / 优化数据倾斜 |
| `Container killed by YARN` | 超内存被杀 | 增大 executor 内存 |
| `FileNotFound` | 数据文件不存在 | 检查数据路径与分区 |
| `Permission denied` | 权限不足 | 检查数据源权限 |
| `Task failed` | task 失败 | 查看具体 task 日志 |

### 3.5 停止与重跑

#### 3.5.1 停止作业

- `作业详情 → 操作 → 停止`：触发优雅退出，已完成 task 保留。
- 停止后状态为"已停止"，可重跑。

#### 3.5.2 重跑作业

- `作业详情 → 操作 → 重跑`：从头重新运行。
- 高级：可指定从某阶段重跑（如跳过已成功的上游 task）。

### 3.6 Flink 作业开发

#### 3.6.1 创建 Flink 作业

入口：`开发 → 作业开发 → 新建作业 → Flink`

#### 3.6.2 Flink SQL 示例

场景：Kafka 实时订单流写入 Iceberg。

```sql
-- Flink SQL功能名：Kafka实时订单写入Iceberg
-- 创建源表（Kafka）
CREATE TABLE kafka_order (
    order_id STRING,
    user_id STRING,
    order_amount DECIMAL(18,2),
    order_time TIMESTAMP(3),
    WATERMARK FOR order_time AS order_time - INTERVAL '5' SECOND
) WITH (
    'connector' = 'kafka',
    'topic' = 'orders',
    'properties.bootstrap.servers' = 'kafka:9092',
    'format' = 'json'
);

-- 创建目标表（Iceberg）
CREATE TABLE iceberg_order (
    order_id STRING,
    user_id STRING,
    order_amount DECIMAL(18,2),
    order_time TIMESTAMP(3),
    dt STRING
) WITH (
    'connector' = 'iceberg',
    'catalog-name' = 'hive_catalog',
    'warehouse' = 'hdfs:///warehouse/iceberg'
);

-- 实时同步
INSERT INTO iceberg_order
SELECT
    order_id,
    user_id,
    order_amount,
    order_time,
    DATE_FORMAT(order_time, 'yyyy-MM-dd') AS dt
FROM kafka_order;
```

#### 3.6.3 Checkpoint 与 Savepoint

- **Checkpoint**：周期性状态快照（如每 60 秒），故障自动恢复。
- **Savepoint**：手动触发，用于升级/迁移/暂停后恢复。
- 配置：`Checkpoint 间隔 60s`，`最小间隔 30s`，`超时 10min`。
- 停止作业时可触发 Savepoint，下次从 Savepoint 启动实现无损停止。

### 3.7 作业开发 FAQ

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| 作业 OOM | 内存不足 / 数据倾斜 | 增大内存 / 处理倾斜 |
| 作业长时间排队 | 资源队列满 / 优先级低 | 提升优先级 / 调整队列 |
| Spark SQL 慢 | 数据倾斜 / 小文件 / 未分区 | 开启 AQE / 合并小文件 |
| Flink Checkpoint 失败 | 状态过大 / 存储异常 | 增大 Checkpoint 超时 / 检查存储 |
| 作业失败但日志不明显 | 日志被截断 | 下载完整日志 / 查看引擎日志 |

## 第4章 SQL 查询

### 4.1 SQL 网关概念

SQL 网关提供即席查询能力，无需编写作业即可查询数据：

- **Trino**：联邦查询 / 即席分析 / 交互式查询，低延迟。
- **Doris**：实时数仓 / 高并发查询 / 物化视图。
- **Spark SQL**：大规模查询 / 与 Spark 作业一致引擎。

### 4.2 使用 SQL 网关

#### 4.2.1 入口

`开发 → SQL 网关 → 新建查询`

#### 4.2.2 选择引擎与工作空间

- 引擎：Trino / Doris / Spark SQL（按权限可见）。
- 工作空间：决定可见的 catalog 与 schema。
- 资源队列：决定查询资源与并发限制。

#### 4.2.3 SQL 编辑器

- 语法高亮 + 自动补全（表名/字段名）。
- 语法检查（提交前校验）。
- 多 Tab 支持，可同时编辑多个查询。
- 快捷键：`Ctrl+Enter` 运行，`Ctrl+S` 保存，`Ctrl+/` 注释。

### 4.3 Trino 联邦查询示例

#### 4.3.1 跨源 JOIN

```sql
-- SQL功能名：跨MySQL与Iceberg联邦查询
SELECT
    a.order_id,
    a.user_id,
    a.order_amount,
    b.user_name,
    b.region
FROM mysql.order_db.orders a
JOIN iceberg.user_catalog.dim_user b
    ON a.user_id = b.user_id
WHERE a.dt = '2026-08-18'
ORDER BY a.order_amount DESC
LIMIT 100;
```

#### 4.3.2 查看执行计划

```sql
EXPLAIN
SELECT count(*) FROM iceberg.user_catalog.dwd_order WHERE dt = '2026-08-18';
```

关注点：

- 是否有 `TableScan` 全表扫描（应走分区裁剪）。
- 跨源 JOIN 是否有 `Exchange` 大量数据传输（应优化为下推）。

### 4.4 Doris 实时查询示例

```sql
-- SQL功能名：Doris实时聚合查询
SELECT
    region,
    product_category,
    SUM(order_amount) AS total_amount,
    COUNT(DISTINCT user_id) AS uv
FROM doris.realtime_dw.dwd_order
WHERE order_time >= NOW() - INTERVAL '1' DAY
GROUP BY region, product_category
ORDER BY total_amount DESC
LIMIT 50;
```

### 4.5 查看查询结果

#### 4.5.1 结果展示

- **表格视图**：默认，支持排序/筛选/分页。
- **图表视图**：快速切换为柱/线/饼/散点图。
- **原始视图**：JSON 原始数据。

#### 4.5.2 结果操作

- **导出**：CSV / Excel / JSON / Parquet，单次最多 100 万行。
- **保存为数据集**：直接进入 BI 流程，可参数化。
- **收藏**：保存 SQL 到"我的收藏"，可命名。
- **历史**：保留 30 天查询历史，可重跑。

### 4.6 SQL 查询 FAQ

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| 查询超时 | 数据量大 / 未走分区 | 加分区过滤 / 优化 SQL / 提高超时 |
| 联邦查询慢 | 大表跨源拉取 | 加下推过滤 / 改用 ETL 预 JOIN |
| 查询报"表不存在" | 工作空间无权限 | 切换工作空间 / 申请权限 |
| 结果导出慢 | 行数过多 | 缩小结果 / 异步导出 |
| SQL 语法报错 | 引擎方言差异 | 参考引擎 SQL 文档 |

## 第5章 BI 可视化

### 5.1 BI 概念

BI 模块提供数据可视化能力，包含三个核心对象：

- **数据集**：逻辑数据源（SQL + 参数），可复用。
- **图表**：基于数据集的可视化单元（柱/线/饼/...）。
- **仪表盘**：多图表组合 + 联动 + 钻取。

### 5.2 创建数据集

#### 5.2.1 入口

`BI → 数据集 → 新建数据集`

#### 5.2.2 步骤

1. 选择数据源：Trino / Doris / Spark SQL。
2. 编写 SQL：定义数据集逻辑。
3. 字段类型识别：自动识别维度/度量/时间字段。
4. 参数化：可定义参数（如 `${region}`），图表可传参。
5. 测试运行：验证 SQL 与字段。
6. 保存：命名 + 选目录 + 权限。

#### 5.2.3 数据集示例

```sql
-- SQL功能名：销售趋势数据集
SELECT
    DATE(order_time) AS dt,
    region,
    product_category,
    SUM(order_amount) AS total_amount,
    COUNT(DISTINCT user_id) AS uv,
    COUNT(*) AS order_cnt
FROM dwd.dwd_order
WHERE order_time BETWEEN ${start_date} AND ${end_date}
GROUP BY DATE(order_time), region, product_category
ORDER BY dt;
```

参数：`start_date` / `end_date`，类型为日期，默认值为近 30 天。

## 第6章 数据治理

### 6.1 数据治理概念

数据治理（Data Governance）让数据"可发现 / 可理解 / 可信任 / 可消费"，包含：

- **资产目录**：全租户数据资产可检索。
- **元数据管理**：技术/业务/管理元数据采集与维护。
- **血缘解析**：数据从源到目标的流转关系。
- **质量监控**：数据质量规则与评分。
- **安全脱敏**：敏感数据脱敏策略。

### 6.2 数据资产目录

#### 6.2.1 入口

`治理 → 资产目录`

#### 6.2.2 检索

- 关键词搜索：表名/字段名/业务术语/标签。
- 筛选：业务域 / Owner / 标签 / 评分 / 更新时间。
- 排序：评分 / 热度 / 更新时间。

#### 6.2.3 资产详情

点击资产进入详情页：

- **基本信息**：表名/所属库/Owner/标签/业务描述。
- **Schema**：字段名/类型/注释/是否主键/是否敏感。
- **血缘**：上游来源 + 下游消费（表级 + 字段级）。
- **质量**：5 维度评分 + 历史趋势 + 规则列表。
- **采样**：前 100 行数据预览（须有权限）。
- **订阅**：订阅变更通知 / 申请使用。

#### 6.2.4 资产登记

新表/新字段须登记到资产目录：

1. `治理 → 资产目录 → 登记资产`。
2. 选择表，填写业务描述、Owner、标签、业务域。
3. 配置敏感字段标记与脱敏策略。
4. 提交后资产可被检索。

### 6.3 元数据管理

#### 6.3.1 元数据类型

| 类型 | 来源 | 示例 |
| --- | --- | --- |
| 技术元数据 | 自动采集 | 表名/字段类型/分区/存储格式 |
| 业务元数据 | 人工维护 | 业务描述/业务术语/指标定义 |
| 管理元数据 | 人工维护 | Owner/标签/分类/生命周期 |

#### 6.3.2 元数据维护

- `治理 → 元数据 → 表详情 → 编辑`。
- 可编辑：业务描述 / Owner / 标签 / 字段注释 / 敏感标记。
- 变更入审计日志，可追溯。

### 6.4 血缘解析

#### 6.4.1 血缘类型

- **表级血缘**：表 A → 表 B（如 `INSERT INTO B SELECT FROM A`）。
- **字段级血缘**：字段 A.x → 字段 B.y。
- **作业血缘**：作业 → 输入表 + 输出表。
- **指标血缘**：指标 → 来源表/字段。

#### 6.4.2 查看血缘

- `治理 → 血缘 → 输入表名`。
- 上游：展开查看数据来源（递归到源）。
- 下游：展开查看数据消费（递归到 BI 报表）。
- 影响分析：修改某字段，查看下游影响范围。

### 6.5 数据质量

#### 6.5.1 质量维度

| 维度 | 含义 | 典型规则 |
| --- | --- | --- |
| 完整性 | 字段非空率 | `count(*) - count(field) / count(*)` |
| 唯一性 | 字段唯一率 | `count(distinct field) / count(*)` |
| 一致性 | 跨表一致 | `A.field = B.field` |
| 准确性 | 业务准确 | 正则 / 枚举 / 范围 |
| 及时性 | 数据新鲜度 | `max(update_time) > now() - 1h` |

#### 6.5.2 配置质量规则

1. `治理 → 数据质量 → 新建规则`。
2. 选择表与字段。
3. 选择维度与规则（内置 + 自定义 SQL）。
4. 配置阈值（如完整性 ≥ 99%）。
5. 配置调度（定时 + 实时）。
6. 配置告警（低于阈值告警）。

#### 6.5.3 查看质量报告

- `治理 → 数据质量 → 质量报告`。
- 5 维度雷达图 + 历史趋势。
- 单表质量详情：规则列表 + 历次执行结果。
- 质量下降告警：触发后通知 Owner。

### 6.6 数据治理 FAQ

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| 资产目录搜不到 | 未登记 / 无权限 | 登记资产 / 申请权限 |
| 血缘缺失 | 作业未解析 / SQL 复杂 | 重新触发血缘解析 |
| 质量评分低 | 数据质量问题 | 按规则排查并整改 |
| 元数据采集延迟 | 采集任务未运行 | 检查采集任务状态 |
| 脱敏未生效 | 策略未启用 / 字段标记错 | 检查脱敏策略与字段标记 |

## 第7章 用户常见问题 FAQ

### 7.1 通用问题

**Q1：忘记密码怎么办？**
A：点击登录页"忘记密码"，通过邮箱重置；或联系租户管理员重置。

**Q2：账号被锁怎么办？**
A：多次密码错误会锁 30 分钟，等待解锁或联系管理员解锁。

**Q3：看不到某些菜单怎么办？**
A：菜单可见性由角色权限决定，联系管理员调整角色或申请权限。

**Q4：作业/SQL 报"权限不足"怎么办？**
A：数据级权限限制，在`治理 → 资产目录`找到数据 → 申请使用权限。

### 7.2 数据开发问题

**Q5：作业资源怎么估算？**
A：经验公式：executor 数 ≈ 数据量(GB) / 10，单 executor 4 核 8Gi。如 100GB 数据用 10 executor × 4 核 × 8Gi。

**Q6：Spark SQL 数据倾斜怎么处理？**
A：1) 开启 AQE：`SET spark.sql.adaptive.enabled=true`；2) 对倾斜 key 加盐打散；3) 两阶段聚合。

**Q7：Flink 作业状态过大怎么办？**
A：1) 增大 Checkpoint 间隔；2) 清理过期状态（TTL）；3) 使用增量 Checkpoint（RocksDB）。

### 7.3 BI 问题

**Q8：仪表盘能给外部客户看吗？**
A：可以，通过"链接分享"设密码与有效期，或"嵌入 iframe"集成到客户系统。注意数据脱敏与权限。

**Q9：数据集 SQL 改了，已建图表会更新吗？**
A：会自动更新，但图表字段引用须重新映射（如字段名变更）。

### 7.4 治理问题

**Q10：怎么知道我的数据被谁用了？**
A：`治理 → 血缘 → 输入表名 → 下游`，可看到下游消费方（作业/报表/用户）。
